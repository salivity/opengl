OpenGL Transform Feedback for Capturing Vertex Outputs

Transform feedback in OpenGL allows developers to capture primitive and vertex data directly from the vertex, tessellation, or geometry processing stages into buffer objects before they reach the rasterizer. This article explains how OpenGL implements transform feedback, details how to disable screen rasterization entirely using native OpenGL states, and walks through the configuration of shaders, buffers, and execution commands required to harvest vertex data efficiently.

Core Concept of Transform Feedback

Normally, the OpenGL pipeline passes processed vertices from the vertex (or geometry) shader to the rasterizer, which generates fragments for the screen. Transform feedback diverts these processed primitives into one or more buffer objects (GL_TRANSFORM_FEEDBACK_BUFFER). This mechanism enables General-Purpose GPU (GPGPU) workflows, particle simulations, and dynamic geometry manipulation directly on the GPU without CPU readbacks.

Disabling Screen Rendering with Rasterizer Discard

To capture vertex outputs without rendering to the screen, OpenGL provides the GL_RASTERIZER_DISCARD state. When enabled, it cuts off the pipeline immediately after the last active pre-rasterization shader stage (vertex, tessellation, or geometry).

glEnable(GL_RASTERIZER_DISCARD);
// Perform drawing commands to capture data
glDisable(GL_RASTERIZER_DISCARD);

When GL_RASTERIZER_DISCARD is active:

  • The rasterizer does not generate fragments.
  • Fragment shaders are completely bypassed.
  • Framebuffers and the screen remain untouched.
  • Performance increases because pixel processing and depth/stencil testing are skipped.

Configuring Shaders for Capture

Before linking the shader program, OpenGL must be instructed on which output variables (varyings) to capture. This is configured using glTransformFeedbackVaryings:

const char* varyings[] = { "outPosition", "outVelocity" };
glTransformFeedbackVaryings(shaderProgram, 2, varyings, GL_INTERLEAVED_ATTRIBS);
glLinkProgram(shaderProgram);

Two capture modes exist:

  1. GL_INTERLEAVED_ATTRIBS: Writes all specified attributes consecutively into a single buffer object ([pos, vel, pos, vel, ...]).
  2. GL_SEPARATE_ATTRIBS: Directs each attribute into its own distinct buffer object bound to separate binding points.

Setting Up Buffers and Transform Feedback Objects

Transform Feedback Objects (TFOs) encapsulate the state of transform feedback buffer bindings, simplifying state management:

GLuint tfo;
glGenTransformFeedbacks(1, &tfo);
glBindTransformFeedback(GL_TRANSFORM_FEEDBACK, tfo);

GLuint tbo;
glGenBuffers(1, &tbo);
glBindBuffer(GL_TRANSFORM_FEEDBACK_BUFFER, tbo);
glBufferData(GL_TRANSFORM_FEEDBACK_BUFFER, bufferSize, NULL, GL_STATIC_READ);

// Bind buffer to index 0 for capturing
glBindBufferBase(GL_TRANSFORM_FEEDBACK_BUFFER, 0, tbo);

Execution Flow

To capture the data during a draw call:

  1. Activate the Program and Bind Feedback Objects:

    glUseProgram(shaderProgram);
glBindTransformFeedback(GL_TRANSFORM_FEEDBACK, tfo);

  2. Enable Rasterizer Discard:

    glEnable(GL_RASTERIZER_DISCARD);

  3. Begin Transform Feedback: Specify the primitive type being captured (GL_POINTS, GL_LINES, or GL_TRIANGLES). The output of the preceding shader stage must match this primitive topology.

    glBeginTransformFeedback(GL_POINTS);

  4. Issue Draw Command:

    glDrawArrays(GL_POINTS, 0, vertexCount);

  5. End Feedback and Restore Pipeline:

    glEndTransformFeedback();
glDisable(GL_RASTERIZER_DISCARD);
glBindTransformFeedback(GL_TRANSFORM_FEEDBACK, 0);

Utilizing the Captured Data

Once the feedback process ends, the buffer contains the computed outputs. This data can be:

  • Read back to the CPU via glGetBufferSubData or glMapBufferRange.
  • Kept on the GPU to serve as vertex inputs for subsequent draw passes using glDrawTransformFeedback or standard glDrawArrays calls.
