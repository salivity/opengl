OpenGL Vertex Shader Clip Distances Explained

Custom user-defined clip distances in OpenGL provide a hardware-accelerated mechanism for discarding geometry against arbitrary spatial boundaries before fragment shading occurs. By computing signed distances in a vertex shader and writing them to the built-in gl_ClipDistance[] array, developers can define custom clipping planes to slice meshes, render cross-sections, or restrict rendering volumes. This article explains how the OpenGL pipeline processes these values, how to implement them in shader code, and how to configure the OpenGL state machine.

The Role of gl_ClipDistance[]

In OpenGL, clipping traditionally occurs against the normalized device coordinate (NDC) viewing frustum. User-defined clip distances extend this behavior by allowing arbitrary clipping planes. The vertex shader communicates with the hardware clipping stage using the built-in output array:

out float gl_ClipDistance[];

Each index in the array corresponds to an active clipping condition. The value assigned to an element represents the signed distance from the vertex to a clipping boundary:

  • A positive value indicates the vertex is inside the valid region and should be preserved.
  • A negative value indicates the vertex is outside the valid region and subject to clipping.
  • A zero value lies directly on the clipping boundary.

Computing Clip Distances in GLSL

A standard clipping plane is mathematically defined by the plane equation \(Ax + By + Cz + D = 0\), represented as a vec4(A, B, C, D). In the vertex shader, the signed distance from a point to this plane is computed using a four-component dot product.

Both the vertex position and the clipping plane must exist in the same coordinate space—typically world space or view space:

#version 330 core

layout (location = 0) in vec3 aPos;

uniform mat4 uModel;
uniform mat4 uView;
uniform mat4 uProjection;
uniform vec4 uClipPlane; // (A, B, C, D) in world space

void main()
{
    vec4 worldPos = uModel * vec4(aPos, 1.0);
    
    // Evaluate signed distance to the plane
    gl_ClipDistance[0] = dot(worldPos, uClipPlane);

    gl_Position = uProjection * uView * worldPos;
}

Hardware Processing and Primitive Reconstruction

Once the vertex shader finishes, the primitive assembly and clipping stages evaluate the values:

  1. Complete Rejection: If all vertices of a primitive (such as a triangle) have negative values for the same clip distance index, the entire primitive is discarded before rasterization.
  2. Complete Acceptance: If all vertices have positive values, the primitive passes unmodified.
  3. Primitive Slicing: If a primitive spans across the boundary (some vertices are positive and others are negative), the hardware clips the polygon along the zero-crossing plane. New vertices are generated at the intersection points, interpolating vertex attributes and creating new triangles to complete the boundary.

Because clipping occurs prior to rasterization, fragments behind the clipping plane are never generated. This avoids the overhead of executing fragment shaders for discarded areas and preserves early depth-testing optimizations.

Host Application Configuration

Assigning values to gl_ClipDistance[] in the shader has no effect unless the corresponding hardware clip planes are explicitly enabled in the OpenGL host application. Each index must be enabled individually:

glEnable(GL_CLIP_DISTANCE0);
// Additional distances can be enabled up to hardware limits:
// glEnable(GL_CLIP_DISTANCE1);

To determine how many simultaneous clip distances the host hardware supports, query the driver using:

GLint maxClipDistances;
glGetIntegerv(GL_MAX_CLIP_DISTANCES, &maxClipDistances);

OpenGL core specifications guarantee support for at least eight simultaneous clip distances (GL_CLIP_DISTANCE0 through GL_CLIP_DISTANCE7). If a plane is disabled via glDisable(GL_CLIP_DISTANCEi), the GPU ignores the corresponding index in gl_ClipDistance[] during clipping.
