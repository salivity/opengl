Clustered Forward Shading in Modern OpenGL

Clustered forward shading is an advanced rendering technique designed to handle thousands of dynamic light sources efficiently within a standard forward rendering pipeline. Traditional forward shading struggles with high light counts due to redundant evaluations per fragment, while tiled shading techniques suffer from depth-range discontinuities. By subdividing the camera's view frustum into a three-dimensional grid of spatial sub-volumes—often referred to as "froxels"—clustered forward shading isolates lights along the X, Y, and Z axes. This allows fragment shaders to query only the specific subset of lights affecting a fragment's precise 3D location, retaining the flexibility of forward rendering, such as hardware multi-sample anti-aliasing (MSAA) and straightforward transparency handling, without sacrificing performance.

The Frustum Subdivision Scheme

The foundation of clustered shading is the partitioning of the view frustum into a three-dimensional grid. The view volume is sliced in three dimensions:

  • X and Y Slices: The screen is divided into a 2D grid of uniform tiles, typically 16x16 or 32x32 pixels in size, matching the structure used in tiled forward shading.
  • Z Slices: The depth axis is divided using an exponential (logarithmic) scale rather than a linear one. Because perspective projection compresses geometry with distance, linear slicing would cause distant clusters to encompass massive world-space volumes while near clusters remain tiny. Exponential slicing ensures that clusters scale proportionally with the perspective expansion, maintaining a balanced spatial volume per cluster across the entire view range.

In OpenGL, the cluster index for a given fragment is computed directly in the fragment shader. The screen-space pixel coordinates \((x, y)\) determine the horizontal and vertical cluster coordinates, while the linear view-space depth determines the slice along the Z axis via a logarithmic mapping formula.

Light Culling with Compute Shaders

Assigning lights to these 3D clusters occurs in a compute shader pass prior to the main geometry rendering. Modern OpenGL uses compute shaders to execute this process efficiently on the GPU:

  1. AABB Generation: A compute pass calculates the Axis-Aligned Bounding Box (AABB) in view space for every cluster in the 3D grid. These bounds are written to a Shader Storage Buffer Object (SSBO).
  2. Intersection Testing: A subsequent compute pass tests each light volume (typically spheres for point lights and cones for spot lights) against the cluster AABBs. A thread can be assigned per cluster to test all active lights, or per light to test candidate clusters.
  3. Data Packing: When a light intersects a cluster, its index is recorded. To avoid allocating fixed-size arrays for every cluster—which would consume excessive VRAM—an indirect list format is commonly used.

The light grid is typically represented in GPU memory using two SSBOs:

  • The Light Index List: A flat array of integers storing the accumulated light indices for all clusters sequentially.
  • The Cluster Grid Buffer: An array indexed by the 3D cluster ID containing two integers: the offset pointing to the start of that cluster's indices in the Light Index List, and the total count of lights affecting that cluster.

Global atomic counters are used within the compute shader to dynamically pack light indices into the continuous index buffer.

Fragment Evaluation in the Forward Pass

During the final geometry pass, the standard forward vertex and fragment shaders execute. For each fragment, the lighting calculation proceeds as follows:

  1. The fragment's screen position gl_FragCoord.xy is divided by the tile size to derive the X and Y cluster indices.
  2. The view-space depth is derived from gl_FragCoord.z using the inverse projection matrix or reconstructed linearly to calculate the Z cluster slice.
  3. The 3D coordinate is flattened into a 1D index: \[\text{ClusterIndex} = X + (Y \times \text{GridDimX}) + (Z \times \text{GridDimX} \times \text{GridDimY})\]
  4. The fragment shader reads the offset and count from the Cluster Grid Buffer using this index.
  5. A simple loop iterates through the Light Index List from offset to offset + count, fetching the light properties (position, color, attenuation) from a global light buffer and calculating the lighting contribution.

Advantages Over Preceding Architectures

By adding depth-based clustering, this architecture resolves the primary limitation of standard tiled forward shading, where a near object and a distant background object within the same screen tile would cause the shader to evaluate all lights along that entire view ray. Because modern OpenGL supports SSBOs, atomic counters, and compute shaders, clustered forward shading operates entirely on the GPU with minimal memory overhead, allowing modern rendering engines to scale to tens of thousands of active lights in a single scene.
