Image-Based Lighting for Diffuse Surfaces in OpenGL PBR

Image-Based Lighting (IBL) is a rendering technique that treats an entire surrounding environment as an omnidirectional light source, capturing realistic ambient lighting rather than relying on discrete point or directional lights. In a Physically Based Rendering (PBR) pipeline using OpenGL, diffuse illumination from an environment is calculated by solving the diffuse irradiance integral across a hemisphere oriented around a surface's normal vector. This article explores what IBL is and breaks down the mathematical and practical steps required to convolve an environment map into an irradiance map for real-time diffuse shading in OpenGL.

What is Image-Based Lighting?

Traditional real-time lighting approximates light emission using mathematical sources like directional, point, and spot lights. While computationally inexpensive, these analytical lights fail to reproduce the complex, indirect ambient light bouncing off surrounding scenery.

Image-Based Lighting solves this by using high dynamic range (HDR) images—typically stored as equirectangular panoramas or cubemaps—to represent the light arriving from all directions toward a scene. Instead of manually placing dozens of ambient fill lights, the environment itself becomes the light emitter. In a PBR context, this lighting is split into two primary components: diffuse irradiance and specular reflection.

The Diffuse Reflectance Equation

Under the standard PBR Cook-Torrance model, total outgoing radiance is the sum of diffuse and specular terms. The diffuse component assumes ideal Lambertian reflection, meaning incoming light scatters equally in all directions across the hemisphere centered on the surface normal \(n\).

The outgoing diffuse radiance \(L_o\) is expressed by the hemisphere integral:

\[L_o(p, \omega_o) = \frac{k_d c}{\pi} \int_{\Omega} L_i(p, \omega_i) (n \cdot \omega_i) d\omega_i\]

Where:

  • \(k_d\) is the ratio of incoming light that is refracted (diffuse).
  • \(c\) is the surface albedo color.
  • \(\Omega\) is the hemisphere oriented along normal \(n\).
  • \(L_i(p, \omega_i)\) is the incoming radiance from direction \(\omega_i\).
  • \(n \cdot \omega_i\) is the cosine attenuation factor.

Computing this integral dynamically for every fragment during real-time rendering is too expensive because it requires sampling hundreds of light directions per pixel.

Pre-Computing Diffuse Irradiance via Convolution

Because the diffuse integral depends solely on the surface normal direction \(n\)—and not on the viewing direction \(\omega_o\)—the integral can be pre-computed for every possible normal orientation. This process is called convolution.

Convolving an environment map involves integrating all incoming radiance over the hemisphere around a given normal vector \(n\) and writing the result to a new cubemap, called an irradiance map. Because diffuse scattering blends light from all directions, the resulting irradiance map looks like an extremely blurred version of the original environment cubemap.

Implementing Diffuse IBL in OpenGL

Implementing diffuse IBL in OpenGL consists of an offline or load-time pre-processing pass followed by a runtime sampling step.

1. Environment Map Setup

Load an equirectangular HDR image into OpenGL and project it onto a standard cubemap texture using a framebuffer object (FBO) and a simple vertex/fragment shader pass rendering to six cubemap faces.

2. Hemisphere Convolution Shader

Render to a new, low-resolution cubemap (e.g., \(32 \times 32\) pixels per face is usually sufficient due to the high degree of blur). The fragment shader loops over spherical coordinates \(\phi\) (azimuth, 0 to \(2\pi\)) and \(\theta\) (polar, 0 to \(\pi/2\)) to sample the original environment map:

vec3 irradiance = vec3(0.0);
vec3 up    = vec3(0.0, 1.0, 0.0);
vec3 right = normalize(cross(up, N));
up         = normalize(cross(N, right));

float sampleDelta = 0.025;
float nrSamples = 0.0; 

for(float phi = 0.0; phi < 2.0 * PI; phi += sampleDelta) {
    for(float theta = 0.0; theta < 0.5 * PI; theta += sampleDelta) {
        // Spherical to Cartesian (tangent space)
        vec3 tangentSample = vec3(sin(theta) * cos(phi), sin(theta) * sin(phi), cos(theta));
        // Tangent space to world space
        vec3 sampleVec = tangentSample.x * right + tangentSample.y * up + tangentSample.z * N; 

        irradiance += texture(environmentMap, sampleVec).rgb * cos(theta) * sin(theta);
        nrSamples++;
    }
}
irradiance = PI * irradiance * (1.0 / float(nrSamples));

The term \(\cos(\theta)\) accounts for the incident angle of the light, while \(\sin(\theta)\) accounts for the shrinking surface area of spherical sample rings near the poles.

3. Real-Time Shading Integration

During the main PBR rendering pass, pass the pre-filtered irradiance cubemap to the fragment shader. Retrieve the ambient diffuse lighting using the fragment's world-space normal vector:

vec3 ambientDiffuse = texture(irradianceMap, Normal).rgb;
vec3 kD = 1.0 - F; // F is the Fresnel factor calculated via the Fresnel-Schlick approximation
kD *= 1.0 - metallic;

vec3 diffuse = kD * ambientDiffuse * albedo;
vec3 ambient = diffuse * ao; // Modulate by ambient occlusion

By querying this single pre-calculated cubemap texture, the shader achieves accurate, physically plausible global ambient lighting with minimal runtime cost.
