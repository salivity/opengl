How TAA Resolves Sub-Pixel Jitter in OpenGL

Temporal Anti-Aliasing (TAA) mitigates jagged geometric edges and specular crawling by distributing spatial samples across time rather than calculating multiple samples per pixel in a single frame. In an OpenGL rendering engine, this technique works by applying a sub-pixel jitter sequence to the camera's projection matrix on each frame, rendering the scene to an off-screen framebuffer, and temporally accumulating the results using a history buffer. By utilizing motion vectors to reproject historical pixel data and employing neighborhood clamping to prevent ghosting, TAA reconstructs a high-resolution, anti-aliased image at a fraction of the computational cost of traditional Multi-Sample Anti-Aliasing (MSAA) or Super-Sample Anti-Aliasing (SSAA).

Sub-Pixel Jittering and the Projection Matrix

Standard rasterization samples a pixel at its geometric center \((0.5, 0.5)\). Geometric edges that partially cover a pixel either trigger a sample or miss it, producing hard aliasing artifacts. TAA solves this by shifting the sampling point slightly on every frame within the boundaries of the pixel.

To distribute these samples evenly over time, OpenGL engines use low-discrepancy quasi-random patterns, such as the Halton(2, 3) sequence, typically cycling through 8 to 16 phases. The engine applies the offset directly to the camera’s perspective projection matrix before rendering the scene geometry:

  1. Obtain the current frame's 2D sub-pixel offset \((j_x, j_y)\) in the range of \([-0.5, 0.5]\).
  2. Convert the pixel offset to Normalized Device Coordinates (NDC) by scaling it according to the viewport dimensions: \[\Delta x = \frac{2 \cdot j_x}{\text{width}}, \quad \Delta y = \frac{2 \cdot j_y}{\text{height}}\]
  3. Inject these offsets into the third column (or row, depending on matrix layout) of the OpenGL projection matrix at indices \(M_{2,0}\) and \(M_{2,1}\).

Because the viewport transformation maps NDC to window coordinates, modifying the projection matrix shifts the entire rasterized scene by a fraction of a pixel without altering world-space coordinates.

Rendering and Off-Screen Buffers

The jittered scene is rendered into an OpenGL Framebuffer Object (FBO) containing multiple color attachments. To resolve the jitter later in the pipeline, the engine must output two critical pieces of data:

  • Current Color Buffer: The standard scene color rendered with the jittered projection matrix.
  • Velocity Buffer (Motion Vectors): A 2-channel floating-point texture (GL_RG16F) storing the screen-space displacement of each pixel from the previous frame to the current frame.

The velocity vector is computed in the vertex or fragment shader by comparing the current unjittered clip-space position with the previous frame's unjittered clip-space position:

\[\vec{v} = \left(\frac{\text{pos}_{\text{current}.\text{xy}}}{\text{pos}_{\text{current}.\text{w}}} - \frac{\text{pos}_{\text{previous}.\text{xy}}}{\text{pos}_{\text{previous}.\text{w}}}\right) \cdot 0.5\]

Using unjittered projection matrices for velocity calculations is essential to prevent camera jitter from polluting the motion vectors, ensuring that the vectors reflect only true camera and object movement.

Temporal Reprojection and History Sampling

Once the current frame is rendered, a full-screen compute or fragment shader pass executes the temporal accumulation. The shader takes the current jittered color texture, the velocity buffer, and a history color texture from the previous frame as inputs.

For each screen pixel:

  1. The shader reads the velocity vector \(\vec{v}\) at the current UV coordinate.
  2. It samples the history buffer at the reprojected location: \(\text{UV}_{\text{history}} = \text{UV} - \vec{v}\).
  3. If the reprojected coordinate falls outside the \([0, 1]\) screen bounds, the historical data is discarded, and the engine falls back to the current frame's color.

Neighborhood Clamping and Anti-Ghosting

Directly blending past frames introduces severe motion blur and trail artifacts (ghosting) when objects move or occlude one another. To eliminate ghosting, the engine validates the historical sample against the current frame's local environment.

The resolve shader samples a \(3 \times 3\) grid of pixels surrounding the current pixel in the current color buffer. It calculates the minimum and maximum color boundaries of this neighborhood, forming an Axis-Aligned Bounding Box (AABB) in color space. Transforming colors from standard RGB to a perceptual color space with separated luminance and chrominance—such as YCoCg—produces significantly sharper bounding boxes.

The reprojected history color is then clamped or clipped to this local AABB:

\[\text{Color}_{\text{history}} = \text{clamp}(\text{Color}_{\text{history}}, \text{Color}_{\min}, \text{Color}_{\max})\]

Clipping algorithms that trace a ray from the history color toward the current pixel's color to find the intersection point with the AABB yield cleaner results than simple per-channel clamping, preserving contrast along moving edges.

Accumulation and Feedback

The final step blends the current jittered color with the validated history color using an Exponential Moving Average (EMA):

\[\text{Color}_{\text{final}} = \alpha \cdot \text{Color}_{\text{current}} + (1.0 - \alpha) \cdot \text{Color}_{\text{history}}\]

The blend factor \(\alpha\) is typically set between \(0.05\) and \(0.10\). A weight of \(0.10\) retains 90% of the historical information, effectively integrating multiple sub-pixel samples over consecutive frames to reconstruct smooth, anti-aliased edges.

The resulting Color_final is output to the backbuffer for display and copied or flipped into the history texture for use in the subsequent frame, closing the temporal feedback loop.
