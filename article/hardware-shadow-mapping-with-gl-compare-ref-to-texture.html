Hardware Shadow Mapping with GL_COMPARE_REF_TO_TEXTURE

This article explains how modern graphics processing units evaluate shadow map samples when using OpenGL's GL_COMPARE_REF_TO_TEXTURE mode. By offloading depth testing directly to the Texture Processing Unit (TPU), the GPU performs depth comparisons and bilinear percentage-closer filtering directly on chip, significantly reducing shader ALU overhead and improving performance.

Configuration and Sampler Types

To activate hardware-accelerated depth comparison, a depth texture must have its GL_TEXTURE_COMPARE_MODE parameter configured to GL_COMPARE_REF_TO_TEXTURE. Developers also configure the comparison operator via GL_TEXTURE_COMPARE_FUNC, most commonly setting it to GL_LEQUAL (less than or equal).

In the OpenGL Shading Language (GLSL), the texture is bound to shadow sampler types, such as sampler2DShadow or samplerCubeShadow. Instead of standard two-dimensional UV coordinates, lookup functions like texture() take a coordinate vector where an additional component represents the reference depth (\(D_{ref}\)) calculated from the light's perspective. For example, a lookup using sampler2DShadow takes a vec3(u, v, D_ref).

The Hardware Evaluation Pipeline

Once a sampling instruction is issued, the hardware executes the lookup through the following steps:

  1. Texel Fetching: The texture unit retrieves the stored depth values (\(D_{tex}\)) from the depth map corresponding to the given texture coordinates.
  2. Hardware Comparison: Dedicated fixed-function comparison units within the TPU evaluate the condition defined by GL_TEXTURE_COMPARE_FUNC:

\[\text{Result} = D_{ref} \le D_{tex} \ ? \ 1.0 : 0.0\]

If the reference depth is less than or equal to the value in the depth map, the surface is closer to the light than the occluder, indicating that the fragment is illuminated and returning a value of 1.0. Otherwise, the fragment is in shadow, returning 0.0.

Filtering and Hardware Percentage Closer Filtering (PCF)

The primary advantage of GL_COMPARE_REF_TO_TEXTURE emerges when combined with texture filtering:

  • Nearest Filtering (GL_NEAREST): The TPU fetches a single depth texel, performs a single comparison against \(D_{ref}\), and returns either 0.0 or 1.0.
  • Linear Filtering (GL_LINEAR): Instead of averaging four depth values together and then performing a single comparison—which produces severe geometric and shadow artifacts—the hardware executes four separate comparisons. The TPU fetches the \(2 \times 2\) footprint of adjacent depth texels, tests each texel independently against the single reference depth \(D_{ref}\), and then bilinearly interpolates the four comparison outcomes.

This process, known as hardware Percentage Closer Filtering (PCF), yields a floating-point value between 0.0 and 1.0. The result provides antialiased, soft shadow edges directly from the sampling unit without requiring manual multismaple loops in the fragment shader.
