Dynamic Reflection Probes in OpenGL

Reflection probes are spatial anchor points used in real-time computer graphics to capture local specular lighting and environmental reflections, dramatically improving realism compared to a single global skybox. This article details the mechanics of reflection probes within Physically Based Rendering (PBR) workflows and outlines how to dynamically update their radiance inputs in modern OpenGL using Framebuffer Objects (FBOs), cubemap rendering passes, and mipmapped roughness filtering.

What Are Reflection Probes?

A reflection probe is an invisible point in a 3D scene that captures a 360-degree view of its surroundings into a cubemap texture. In standard Image-Based Lighting (IBL), using a single distant environment map causes reflections on local indoor geometry to appear spatially disconnected. Reflection probes solve this by capturing localized light information:

  • Local Capture: Probes sit at defined coordinates and capture local geometry and lighting.
  • Bounding Volumes: Probes use spheres or axis-aligned bounding boxes (AABBs) to define their influence zone and blend boundaries.
  • Parallax Correction: Using box projection or sphere projection algorithms, the probe adjusts the reflection vector based on the scene bounds to ensure reflections accurately reflect local surfaces rather than appearing infinitely far away.

Dynamically Updating Radiance Inputs in OpenGL

While static scenes precompute probe cubemaps, dynamic scenes—featuring moving geometry, varying light conditions, or day-night cycles—require real-time radiance updates. In OpenGL, updating dynamic radiance inputs involves three core steps: cubemap allocation, multi-angle scene capture, and pre-filtering for roughness.

1. Cubemap and Framebuffer Setup

To render into a cubemap dynamically, allocate a GL_TEXTURE_CUBE_MAP with mipmaps enabled to support various surface roughness levels, then link it to an FBO.

GLuint cubemapTexture;
glGenTextures(1, &cubemapTexture);
glBindTexture(GL_TEXTURE_CUBE_MAP, cubemapTexture);

for (unsigned int i = 0; i < 6; ++i) {
    glTexImage2D(GL_TEXTURE_CUBE_MAP_POSITIVE_X + i, 0, GL_RGB16F, 
                 resolution, resolution, 0, GL_RGB, GL_FLOAT, nullptr);
}
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_MIN_FILTER, GL_LINEAR_MIPMAP_LINEAR);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_R, GL_CLAMP_TO_EDGE);
glGenerateMipmap(GL_TEXTURE_CUBE_MAP);

GLuint captureFBO, captureRBO;
glGenFramebuffers(1, &captureFBO);
glGenRenderbuffers(1, &captureRBO);
glBindFramebuffer(GL_FRAMEBUFFER, captureFBO);
glBindRenderbuffer(GL_RENDERBUFFER, captureRBO);
glRenderbufferStorage(GL_RENDERBUFFER, GL_DEPTH_COMPONENT24, resolution, resolution);
glFramebufferRenderbuffer(GL_FRAMEBUFFER, GL_DEPTH_ATTACHMENT, GL_RENDERBUFFER, captureRBO);

2. Rendering the Six Cubemap Faces

Set up a 90-degree field-of-view (FOV) projection matrix with an aspect ratio of 1:1. From the probe's world position, construct six view matrices oriented along the primary axes: \(+X, -X, +Y, -Y, +Z,\) and \(-Z\).

Loop through each face, attaching the target cubemap face to the FBO color attachment, and render the scene:

glm::mat4 captureProjection = glm::perspective(glm::radians(90.0f), 1.0f, 0.1f, 100.0f);
glm::mat4 captureViews[] = {
   glm::lookAt(probePos, probePos + glm::vec3( 1,  0,  0), glm::vec3(0, -1,  0)),
   glm::lookAt(probePos, probePos + glm::vec3(-1,  0,  0), glm::vec3(0, -1,  0)),
   glm::lookAt(probePos, probePos + glm::vec3( 0,  1,  0), glm::vec3(0,  0,  1)),
   glm::lookAt(probePos, probePos + glm::vec3( 0, -1,  0), glm::vec3(0,  0, -1)),
   glm::lookAt(probePos, probePos + glm::vec3( 0,  0,  1), glm::vec3(0, -1,  0)),
   glm::lookAt(probePos, probePos + glm::vec3( 0,  0, -1), glm::vec3(0, -1,  0))
};

glViewport(0, 0, resolution, resolution);
glBindFramebuffer(GL_FRAMEBUFFER, captureFBO);

for (unsigned int i = 0; i < 6; ++i) {
    glFramebufferTexture2D(GL_FRAMEBUFFER, GL_COLOR_ATTACHMENT0, 
                           GL_TEXTURE_CUBE_MAP_POSITIVE_X + i, cubemapTexture, 0);
    glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
    RenderScene(captureViews[i], captureProjection);
}

Note: Alternatively, you can use layered rendering via a Geometry Shader or the GL_AMD_vertex_shader_layer / GL_NV_viewport_array2 extensions to draw all six faces in a single draw call.

3. Updating the Radiance Input (Filtering)

Raw cubemaps only provide perfect mirror reflections. In standard PBR, the Split-Sum approximation requires the radiance map to be pre-filtered across multiple roughness levels stored within the cubemap's mipmap chain.

For dynamic updates, recalculating this every frame can be demanding. Two main approaches update this radiance data:

  1. Hardware Mipmap Generation (Approximation): Calling glGenerateMipmap(GL_TEXTURE_CUBE_MAP) generates standard downsampled mipmaps. While physically inaccurate compared to a GGX-weighted convolution, fetching lower mipmaps for rougher materials provides an inexpensive pseudo-blur suitable for high-performance budgets.
  2. Compute Shader Convolution: Dispatch an OpenGL compute shader across the cubemap's mip levels. The compute shader executes a Monte Carlo integration with Importance Sampling using the GGX Normal Distribution Function (NDF), writing the blurred radiance results directly into specific mipmap levels using imageStore.

Optimization Strategies for Real-Time Updates

Re-rendering the scene six times introduces significant draw call overhead. To maintain interactive frame rates in OpenGL:

  • Time-Slicing: Instead of capturing all six faces every frame, update a single face per frame. The entire probe updates completely every six frames.
  • Low Resolutions: Allocate low-resolution textures for dynamic probes (e.g., \(128 \times 128\) or \(256 \times 256\)), as specular reflections rarely require high-frequency geometric detail.
  • Culling and LODs: When rendering probe passes, disable post-processing, cull small decorative objects, and force meshes to render with lower Levels of Detail (LODs).
