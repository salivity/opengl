How dFdx Works in OpenGL Fragment Shaders

This article explains how the built-in dFdx function calculates screen-space derivatives in OpenGL fragment shaders. It covers the underlying hardware architecture of \(2 \times 2\) pixel quads, the discrete mathematical formulas used to approximate partial derivatives, and how the GPU evaluates these calculations across adjacent fragments.

The Fragment Quad Architecture

GPUs do not process screen fragments in complete isolation. Instead, modern graphics hardware executes fragment shaders concurrently in groups of four organized into \(2 \times 2\) pixel grids known as "quads."

Within a quad, the four fragment coordinates are arranged along the window space:

  • Top-left: \((x_0, y_0)\)
  • Top-right: \((x_0 + 1, y_0)\)
  • Bottom-left: \((x_0, y_0 + 1)\)
  • Bottom-right: \((x_0 + 1, y_0 + 1)\)

Even if a primitive covers only one pixel in a quad, the GPU executes the shader for all four pixels to maintain lockstep SIMD (Single Instruction, Multiple Data) execution and to ensure derivative data is available. Uncovered fragments are executed as helper invocations and discarded before the write stage.

Mathematical Formulation of dFdx

Mathematically, the derivative of a function \(f(x)\) with respect to \(x\) is defined as the limit of the difference quotient:

\[\frac{\partial f}{\partial x} = \lim_{\Delta x \to 0} \frac{f(x + \Delta x) - f(x)}{\Delta x}\]

Inside a rasterized pipeline, continuous values are sampled at discrete pixel intervals. Therefore, the GPU replaces the infinitesimal limit with a discrete finite difference. Because adjacent pixels in screen space are spaced exactly one pixel apart, \(\Delta x = 1\).

Substituting \(\Delta x = 1\) simplifies the difference quotient directly to:

\[\frac{\partial f}{\partial x} \approx \frac{f(x + 1) - f(x)}{1} = f(x + 1) - f(x)\]

Evaluation Across the Quad

When dFdx(p) is called on an arbitrary variable or expression \(p\), the GPU evaluates \(p\) across horizontal neighbors within the quad using internal cross-lane register sharing.

Let the evaluated values of \(p\) within a \(2 \times 2\) quad be:

  • \(p_{00} = p(x_0, y_0)\)
  • \(p_{10} = p(x_0 + 1, y_0)\)
  • \(p_{01} = p(x_0, y_0 + 1)\)
  • \(p_{11} = p(x_0 + 1, y_0 + 1)\)

Depending on hardware and OpenGL specifications (specifically starting with OpenGL 4.5 or GL_ARB_derivative_control), dFdx operates in one of two modes:

1. Coarse Derivatives (dFdxCoarse)

Most standard implementations evaluate a single horizontal delta per quad row or per quad. The difference between the right and left pixels of the top row is calculated:

\[\Delta p_{\text{row0}} = p_{10} - p_{00}\]

This single value is typically shared across both horizontal fragments in that row, or across all four fragments in the quad:

\[\text{dFdx}(p) = p_{10} - p_{00}\]

2. Fine Derivatives (dFdxFine)

Fine derivatives calculate independent differences for each horizontal pair in the quad:

  • For fragments in the top row: \(\text{dFdx}(p) = p_{10} - p_{00}\)
  • For fragments in the bottom row: \(\text{dFdx}(p) = p_{11} - p_{01}\)

In standard GLSL, dFdx can map to either coarse or fine approximations depending on the vendor driver, though coarse calculations are common to optimize instruction cache and register usage.

Practical Implications

Because dFdx depends on inter-fragment communication within a quad:

  • Uniform Control Flow: If dFdx is used inside divergent branching (such as non-uniform if conditions), fragments within the quad may execute different execution paths, making neighbor values undefined and yielding graphical artifacts.
  • Piecewise Flatness: Because \(\Delta x = 1\) over the span of the quad, dFdx returns a constant rate of change across the quad's horizontal span, producing piecewise-constant derivative values on screen.
