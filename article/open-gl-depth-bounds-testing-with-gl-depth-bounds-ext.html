OpenGL Depth Bounds Testing with glDepthBoundsEXT

The depth bounds test, exposed via the GL_EXT_depth_bounds_test extension and the glDepthBoundsEXT function, is an optimization feature in OpenGL that discards fragments based on the existing depth buffer content. By restricting rendering operations to an explicit depth range \([z_{min}, z_{max}]\) in window coordinates, the GPU can bypass expensive rasterization, fragment shading, and blending stages for any pixel whose current depth value lies outside this window. This article explains the mechanics of the depth bounds test, how it interacts with the graphics pipeline, and how it is applied to eliminate redundant raster workload.

Mechanics of the Depth Bounds Test

Unlike standard depth testing (glDepthFunc), which evaluates an incoming fragment's depth against the value currently stored in the depth buffer, the depth bounds test evaluates the existing depth buffer value at the fragment's screen coordinates against a predefined numerical interval.

The test is configured using:

glEnable(GL_DEPTH_BOUNDS_TEST_EXT);
glDepthBoundsEXT(clamp(zmin, 0.0, 1.0), clamp(zmax, 0.0, 1.0));

During fragment processing, the GPU queries the value \(z_{stored}\) already present in the depth buffer at \((x, y)\). If the condition:

\[z_{min} \le z_{stored} \le z_{max}\]

evaluates to false, the fragment fails the depth bounds test and is discarded immediately. The incoming fragment's own generated depth value does not affect this test.

How it Prevents Raster and Shading Work

The primary architectural advantage of glDepthBoundsEXT is its capability to cull pixel processing before or during early pipeline stages:

  1. Bypassing Fragment Shaders (Early-Z Integration): When hardware-level early depth testing is active, the GPU evaluates depth operations prior to invoking the fragment shader. Because the depth bounds test relies solely on \(z_{stored}\), modern rasterizers can evaluate the bounds condition concurrently with or prior to standard Early-Z tests. Fragments falling outside the active window are killed before fragment shader execution, saving shading cycles and texture bandwidth.
  2. Hierarchical-Z (Hi-Z) Culling: Modern GPUs organize depth into low-resolution tiles (Hierarchical Z). If a tile's minimum and maximum stored depths fall entirely outside \([z_{min}, z_{max}]\), the GPU rasterizer can reject the entire tile at the coarse raster stage. This prevents fine-grained rasterization and eliminates subsequent per-fragment operations altogether.
  3. Bandwidth Reduction: Fragments discarded by the depth bounds test perform no color buffer writes, no stencil operations, and no depth updates, conserving memory bus bandwidth.

Primary Use Case: Deferred Shading Light Volumes

The most prominent application of glDepthBoundsEXT is optimizing light volume rendering in deferred lighting pipelines.

When rendering a localized light source (such as a point light or spotlight):

  • The light affects geometry only within a finite 3D bounding volume.
  • By projecting the world-space bounding volume of the light onto the camera's view axis, the application calculates near and far depth extents \([z_{min}, z_{max}]\) in screen space.
  • Setting glDepthBoundsEXT to these extents guarantees that light volume geometry is only shaded where the underlying scene geometry physically intersects the depth range of the light.

Without depth bounds testing, pixels covering background or foreground surfaces that lie outside the light's radius would still execute the lighting fragment shader unless rejected by two-pass stencil volume techniques. glDepthBoundsEXT replaces complex stencil setups with a single, highly efficient depth-rejection state change.
