How glBlitFramebuffer Copies OpenGL Framebuffer Data

This article explains how the glBlitFramebuffer function transfers color, depth, and stencil data between distinct OpenGL framebuffer objects (FBOs). It covers the binding mechanics required to establish source and destination buffers, coordinate mapping for scaling and flipping, bitmask selection for targeting specific data buffers, filtering constraints, and the special rules governing multisample anti-aliasing (MSAA) resolves.

Framebuffer Binding Mechanics

Before invoking glBlitFramebuffer, OpenGL requires the application to bind the source and target framebuffers to two dedicated binding points: GL_READ_FRAMEBUFFER and GL_DRAW_FRAMEBUFFER.

glBindFramebuffer(GL_READ_FRAMEBUFFER, srcFBO);
glBindFramebuffer(GL_DRAW_FRAMEBUFFER, dstFBO);

When blitting executes, OpenGL reads pixel data exclusively from the attachments bound to GL_READ_FRAMEBUFFER and writes the results directly into the attachments of GL_DRAW_FRAMEBUFFER. This separation allows simultaneous access to two different framebuffers without causing state conflicts or feedback loops.

Coordinate Mapping, Scaling, and Inversion

The function defines rectangular regions in both the read and draw buffers:

void glBlitFramebuffer(
    GLint srcX0, GLint srcY0, GLint srcX1, GLint srcY1,
    GLint dstX0, GLint dstY0, GLint dstX1, GLint dstY1,
    GLbitfield mask,
    GLenum filter
);
  • Direct Copying: If the source and destination dimensions match (dstX1 - dstX0 == srcX1 - srcX0 and dstY1 - dstY0 == srcY1 - srcY0), data transfers at a 1:1 pixel ratio.
  • Stretching and Scaling: If the source and destination rectangles have different widths or heights, the GPU scales the image data to fit the destination bounds.
  • Flipping: If the start coordinates are greater than the end coordinates (for example, srcY0 > srcY1 or dstY0 > dstY1), OpenGL flips the image along the respective axis, which is commonly used to adjust for inverted Y-coordinates across different rendering APIs or texture conventions.

Selecting Buffers with the Mask

The mask parameter determines which attachments are copied. It accepts a bitwise OR combination of three flags:

  • GL_COLOR_BUFFER_BIT: Copies the color buffer specified by glReadBuffer to the draw buffers enabled by glDrawBuffers.
  • GL_DEPTH_BUFFER_BIT: Copies the depth attachment values.
  • GL_STENCIL_BUFFER_BIT: Copies the stencil attachment values.

You can copy multiple buffer types simultaneously (for example, GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT), provided that the operational constraints for each buffer type are satisfied.

Filtering Rules and Format Constraints

The filter parameter specifies the interpolation algorithm used when scaling: either GL_NEAREST or GL_LINEAR.

  • Color Buffers: Support both GL_NEAREST and GL_LINEAR. Linear filtering produces smooth interpolation when resizing.
  • Depth and Stencil Buffers: Must use GL_NEAREST. Passing GL_LINEAR when blitting depth or stencil data generates a GL_INVALID_OPERATION error because interpolating discrete depth or stencil indices yields invalid data.
  • Format Compatibility: The internal formats of the source and destination attachments must be compatible. For example, copying a floating-point depth buffer to a normalized integer depth buffer is allowed, but format mismatches that prevent conversion will generate an error.

Multisample (MSAA) Resolution

glBlitFramebuffer is the standard mechanism in OpenGL to resolve multisample renderbuffers into standard, single-sample textures for display or post-processing.

When the read framebuffer is multisampled and the draw framebuffer is single-sampled:

  1. The source and destination rectangles must have identical dimensions. Stretching is not permitted during an MSAA resolve.
  2. The filter parameter must be set to GL_NEAREST.
  3. The GPU calculates the average sample value for color pixels across all MSAA samples and writes the resolved result to the destination buffer.

If both buffers are multisampled, they must contain the exact same number of samples; otherwise, the blit operation fails.

Scissor Box Interaction

Blit operations respect the draw framebuffer's scissor test. If GL_SCISSOR_TEST is enabled, only pixels that fall within the defined scissor rectangle of the destination framebuffer are modified. Pixels outside the scissor region remain untouched, providing fine-grained control over targeted sub-regions.
