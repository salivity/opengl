Features Removed in OpenGL 3.0 Core Profile

The release of OpenGL 3.0 introduced a formal deprecation mechanism that led to the removal of vast portions of legacy functionality in subsequent Core Profiles (formalized in versions 3.1 and 3.2). This article details the specific capabilities, functions, and architectures that were permanently removed from the OpenGL Core Profile to modernize the graphics pipeline, eliminate obsolete hardware paradigms, and transition the API entirely toward programmable shaders and high-performance buffer objects.

Immediate Mode

Immediate mode rendering using glBegin() and glEnd() blocks was completely eliminated. Functions that submitted per-vertex attributes sequentially—such as glVertex*(), glNormal*(), glTexCoord*(), and glColor*()—were removed. Modern Core OpenGL requires vertex data to be stored in GPU-accessible memory via Vertex Buffer Objects (VBOs) and referenced through Vertex Array Objects (VAOs).

Fixed-Function Pipeline

The entire fixed-function vertex and fragment processing pipeline was removed. Hardware states that automatically computed lighting, fog, texture blending, material properties, and alpha testing without custom program code are unavailable in Core Profile. All per-vertex and per-fragment operations must be implemented explicitly using the OpenGL Shading Language (GLSL) via vertex and fragment shaders.

Built-in Matrix Stacks and Transformations

OpenGL previously managed coordinate systems and projection mathematics via an internal matrix stack. Functions including glMatrixMode(), glPushMatrix(), glPopMatrix(), glLoadIdentity(), glMultMatrix(), glRotate*(), glTranslate*(), and glScale*() were removed. Applications must now calculate their own transformation matrices on the CPU and pass them to shaders as uniform variables.

Client-Side Vertex Arrays

Prior to OpenGL 3.0, applications could supply geometry directly from CPU system memory using functions such as glVertexPointer(), glColorPointer(), glNormalPointer(), and glTexCoordPointer(). These client-side vertex arrays were eliminated; data must reside in server-side buffer objects managed by glBindBuffer() and configured with glVertexAttribPointer().

Display Lists

Display lists, created using glNewList(), glEndList(), and executed with glCallList(), were removed. Previously used to cache sequences of commands on the GPU, display lists became redundant with the advent of uniform buffers, shader programs, and vertex buffers.

Obsolete Primitive Types

Specific rendering primitives were excised due to modern GPU architectures operating strictly on points, lines, and triangles. The removed primitive types include:

  • GL_QUADS
  • GL_QUAD_STRIP
  • GL_POLYGON

Geometry must now be composed using GL_TRIANGLES, GL_TRIANGLE_STRIP, or GL_TRIANGLE_FAN.

Selection and Feedback Modes

Rasterization-independent operation modes, specifically Selection Mode (GL_SELECT) and Feedback Mode (GL_FEEDBACK), were purged alongside functions like glRenderMode(), glInitNames(), and glPassThrough(). Object picking and geometry queries must instead be implemented using color-buffer picking, depth tests, occlusion queries, or compute/transform feedback mechanisms.

Evaluators and Pixel Operations

Hardware evaluators for Bézier surfaces and spline generation (glMap1*, glMap2*, glEvalCoord*) were removed in favor of software tessellation and later hardware tessellation shaders. Additionally, legacy pixel drawing routines such as glDrawPixels(), glBitmap(), and glPixelTransfer() were removed; texture mapping onto geometric quads or blitting via Framebuffer Objects (FBOs) replaced them.

Accumulation Buffer

The accumulation buffer and its associated commands (glAccum()) were permanently eliminated. Post-processing effects such as motion blur, depth of field, and antialiasing that historically relied on the accumulation buffer are now achieved using off-screen render targets and multi-pass shaders.
