Generate Primitive Strips with OpenGL Geometry Shader

The OpenGL geometry shader stage sits between the vertex shader and the rasterizer, possessing the unique ability to change primitive topology dynamically. When configured to take isolated points as input, a geometry shader can expand each point into a complex primitive strip—such as a line_strip or a triangle_strip—by generating and emitting multiple vertices in a specific sequential order. This article explains the layout configurations, vertex emission mechanisms, and execution flow required to transform point data into primitive strips within GLSL.

Input and Output Layout Declarations

To convert points into strips, the geometry shader must first declare the incoming primitive type and the target output primitive type along with the maximum number of vertices it will produce.

#version 330 core

// Declare isolated points as input
layout (points) in;

// Declare the output strip type and upper vertex bound
layout (triangle_strip, max_vertices = 4) out;

The layout (points) in; directive configures each geometry shader invocation to process exactly one vertex from the preceding stage, accessible via the built-in array gl_in[0]. The output layout determines the assembly rule used by the primitive assembler downstream. Specifying triangle_strip or line_strip dictates how the emitted vertices are joined. The max_vertices qualifier reserves buffer space on the GPU; keeping this number as low as possible ensures optimal hardware occupancy.

The Primitive Strip Assembly Rules

Primitive strips allow successive primitives to share vertices, reducing memory bandwidth and calculation overhead:

  • Line Strip (line_strip): The first two emitted vertices form the first line segment. Every subsequent vertex forms an additional line segment using the preceding vertex (\(V_0-V_1\), \(V_1-V_2\), \(V_2-V_3\), etc.).
  • Triangle Strip (triangle_strip): The first three emitted vertices form the first triangle. Each subsequent vertex forms another triangle with the previous two vertices (\(V_0-V_1-V_2\), \(V_1-V_2-V_3\), \(V_2-V_3-V_4\), etc.). The GPU automatically alternates the winding order internally to ensure consistent face culling across all sub-triangles.

Vertex Emission Workflow

The geometry shader utilizes two built-in GLSL functions to assemble strips from an incoming point:

  1. EmitVertex(): Writes current output variables (such as gl_Position, UV coordinates, and normals) into the output stream. Every time this function is called, the pipeline records a new vertex for the current primitive strip.
  2. EndPrimitive(): Signals the hardware that the current strip is complete. Any subsequent call to EmitVertex() will begin a distinct, unconnected strip.

When expanding an isolated point, the shader computes offsets relative to gl_in[0].gl_Position, writes the coordinates, and calls EmitVertex() iteratively in strip order.

Implementation Example: Expanding a Point into a Quad

A common application of this technique is camera-facing billboard generation or 2D particle rendering, where an incoming point is transformed into a four-vertex quad via a triangle_strip.

#version 330 core

layout (points) in;
layout (triangle_strip, max_vertices = 4) out;

in vec2 vSize[]; // Size passed from vertex shader
out vec2 TexCoords;

uniform mat4 uProjection;

void main() {
    vec4 center = gl_in[0].gl_Position;
    float halfWidth = vSize[0].x * 0.5;
    float halfHeight = vSize[0].y * 0.5;

    // Vertex 0: Bottom-Left
    gl_Position = uProjection * (center + vec4(-halfWidth, -halfHeight, 0.0, 0.0));
    TexCoords = vec2(0.0, 0.0);
    EmitVertex();

    // Vertex 1: Bottom-Right
    gl_Position = uProjection * (center + vec4(halfWidth, -halfHeight, 0.0, 0.0));
    TexCoords = vec2(1.0, 0.0);
    EmitVertex();

    // Vertex 2: Top-Left
    gl_Position = uProjection * (center + vec4(-halfWidth, halfHeight, 0.0, 0.0));
    TexCoords = vec2(0.0, 1.0);
    EmitVertex();

    // Vertex 3: Top-Right
    gl_Position = uProjection * (center + vec4(halfWidth, halfHeight, 0.0, 0.0));
    TexCoords = vec2(1.0, 1.0);
    EmitVertex();

    // Finalize the triangle strip
    EndPrimitive();
}

In this implementation, the incoming point serves as the origin. The shader calculates four distinct corner positions. By emitting them in the order Bottom-Left, Bottom-Right, Top-Left, and Top-Right, the hardware constructs two adjacent triangles that share an edge (\(V_0-V_1-V_2\) and \(V_1-V_2-V_3\)). Calling EndPrimitive() terminates the strip, sending the complete quad down the graphics pipeline to the rasterizer.
