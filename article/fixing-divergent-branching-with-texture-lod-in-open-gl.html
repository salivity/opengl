Fixing Divergent Branching with textureLod in OpenGL

In OpenGL, sampling textures inside non-uniform conditional branches with standard functions like texture() can cause rendering artifacts and undefined behavior. This occurs because the GPU calculates Level of Detail (LoD) using implicit screen-space derivatives across neighboring fragments in a \(2\times2\) quad. Using textureLod stabilizes divergent branching by providing an explicit mipmap level, removing the need for hardware-computed spatial derivatives and ensuring deterministic sampling behavior across all execution lanes.

The Problem with Implicit Derivatives

Standard GLSL texture sampling functions (texture, textureProj, etc.) rely on the GPU's rasterization architecture, which processes fragments in \(2\times2\) pixel clusters known as quads. To select the appropriate mipmap level, the hardware computes implicit finite differences between neighboring fragments in the quad using hardware equivalents of dFdx and dFdy. This calculation establishes the texture coordinate gradient relative to screen space.

When a shader introduces dynamic branching—such as an if statement based on a non-uniform condition—neighboring fragments within the same quad may take different execution paths. If some fragments execute the branch while others do not, the execution lanes for the inactive fragments are masked out. Because the gradient calculation requires active neighboring data across the entire quad, derivative values within the divergent branch become undefined. This typically manifests as rapid mipmap switching, severe visual flickering, black fringes, or hardware-specific rendering corruption.

How textureLod Solves Divergence

The textureLod function accepts an explicit LoD parameter rather than relying on automatic derivation:

vec4 textureLod(gsampler2D sampler, vec2 P, float lod);

By explicitly declaring the target mipmap level (e.g., 0.0 for full resolution, or a custom precomputed value), textureLod bypasses the hardware's automatic gradient computation entirely.

Because spatial derivatives are not evaluated:

  1. Independent Lane Execution: Individual fragments in a quad can sample textures regardless of the execution state of neighboring fragments.
  2. Deterministic Output: Every pixel executing the branch receives a predictable mipmap level rather than garbage data derived from masked or inactive adjacent threads.
  3. Specification Compliance: The OpenGL Shading Language (GLSL) specification explicitly disallows implicit derivative operations in non-uniform flow control; using textureLod adheres strictly to valid control flow rules.

Practical Implementation

When sampling inside conditional statements, replace implicit lookups with explicit alternatives:

// Unsafe in divergent branches:
if (materialID == 2) {
    color = texture(diffuseMap, uv); // Undefined behavior if quad diverges
}

// Safe in divergent branches:
if (materialID == 2) {
    color = textureLod(diffuseMap, uv, 0.0); // Explicit base level
}

If mipmapping is still required inside a divergent branch, gradients can be calculated before the branch executes using dFdx and dFdy in uniform flow control, and then passed into textureGrad. However, for scenarios where uniform detail or a specific mip level is acceptable, textureLod provides the most direct and computationally lightweight method to eliminate divergence-related sampling artifacts in OpenGL shaders.
