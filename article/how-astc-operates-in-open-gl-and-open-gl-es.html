How ASTC Operates in OpenGL and OpenGL ES

Adaptive Scalable Texture Compression (ASTC) is an advanced lossy texture compression technology standardized by the Khronos Group to provide fine-grained control over texture quality and memory footprint. Within modern OpenGL and OpenGL ES ecosystems, ASTC operates as a unified, hardware-accelerated format that replaces older, fragmented compression standards. This article details the structural mechanics of ASTC, how modern graphic APIs expose its capabilities, and the pipeline workflow required to load and sample ASTC textures efficiently.

The ASTC Compression Architecture

ASTC compresses image data into fixed-size 128-bit (16-byte) data blocks. While the storage footprint per block is fixed, the spatial footprint—the number of texels each block represents—is variable.

Developers can choose block footprints ranging from dense \(4\times4\) grids (8.0 bits per pixel) to sparse \(12\times12\) grids (0.89 bits per pixel) for 2D textures, alongside specialized 3D footprints ranging from \(3\times3\times3\) to \(6\times6\times6\). Regardless of the dimension, the underlying decoding algorithm parses color endpoints, partition tables, and weight grids within the 128-bit payload. This flexibility allows engines to target specific quality-to-memory ratios on an individual asset basis using a single, unified format.

API Integration and Extensions

In modern graphics systems, ASTC is integrated into OpenGL and OpenGL ES through core specifications and standard Khronos extensions:

  • OpenGL ES: ASTC support is mandated in OpenGL ES 3.2 for the Low Dynamic Range (LDR) profile. On OpenGL ES 3.0 and 3.1 devices, it is commonly supported via GL_KHR_texture_compression_astc_ldr or GL_OES_texture_compression_astc.
  • OpenGL (Desktop): Supported via GL_KHR_texture_compression_astc_ldr and GL_KHR_texture_compression_astc_hdr. Desktop drivers implement this extension natively on hardware with shared mobile architectures or via driver-level emulation and hardware support on newer graphics processors.

The format supports both LDR (standard RGB/RGBA) and High Dynamic Range (HDR) modes, as well as distinct color spaces such as linear RGB and sRGB.

Runtime Operation in the Graphics Pipeline

The operational lifecycle of an ASTC texture within an OpenGL or OpenGL ES application follows distinct stages:

1. Capability Verification

Before allocating textures, applications query device capabilities to verify that ASTC formats are present. This is done by checking the extension string or querying supported formats:

GLint numFormats = 0;
glGetIntegerv(GL_NUM_COMPRESSED_TEXTURE_FORMATS, &numFormats);
GLint formats[numFormats];
glGetIntegerv(GL_COMPRESSED_TEXTURE_FORMATS, formats);

2. Texture Allocation and Ingestion

ASTC textures are pre-compressed offline using tools such as ARM's astcenc. The resulting raw payload contains the 128-bit blocks without container headers.

The client application passes this data directly to the GPU using glCompressedTexImage2D or the modern Direct State Access (DSA) alternative, glCompressedTextureSubImage2D. The internal format parameter dictates the block footprint and color space:

  • GL_COMPRESSED_RGBA_ASTC_4x4_KHR
  • GL_COMPRESSED_SRGB8_ALPHA8_ASTC_8x8_KHR
  • GL_COMPRESSED_RGBA_ASTC_12x12_KHR

The driver verifies that the byte size provided matches the formula:

\[\text{Data Size} = \left\lceil \frac{\text{Width}}{\text{BlockWidth}} \right\rceil \times \left\lceil \frac{\text{Height}}{\text{BlockHeight}} \right\rceil \times 16 \text{ bytes}\]

3. Real-Time Hardware Decompression

During shader execution, texture decompression does not occur on the CPU or during the initial API load call. Instead, compressed blocks reside in GPU VRAM.

When a fragment shader calls a standard sampling function (such as texture(sampler2D, uv) in GLSL), the GPU's fixed-function Texture Processing Unit (TPU) fetches the required 128-bit block into the texture cache. Dedicated hardware decoders unpack the texel color in real time. Because the decoding logic is transparent to GLSL, no custom shader code is required to handle ASTC data.

System Performance Implications

By keeping textures compressed in GPU memory, ASTC directly reduces memory bandwidth usage—the primary contributor to thermal throttling and battery drain on mobile and embedded GPUs. Smaller block sizes provide near-lossless visual fidelity for normal maps and UI elements, while larger block sizes allow drastic bandwidth reduction for diffuse surfaces, enabling higher frame rates and larger asset budgets within modern OpenGL environments.
