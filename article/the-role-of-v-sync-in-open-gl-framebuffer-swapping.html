The Role of VSync in OpenGL Framebuffer Swapping

Vertical synchronization (VSync) plays a critical role in OpenGL by coordinating the timing between the GPU's framebuffer swaps and the display monitor's physical refresh cycle. In double-buffered rendering, VSync determines whether the front and back buffers swap immediately upon completion of a frame or wait for the monitor to finish drawing the current image. By synchronizing this swap with the display's vertical blanking interval, VSync directly controls frame pacing, prevents screen tearing, and influences input latency.

Double Buffering and the Swap Mechanism

To prevent flickering during rendering, OpenGL applications typically use double buffering. In this architecture:

  • The front buffer holds the finished frame currently being scanned out and displayed by the monitor.
  • The back buffer is where the GPU renders the next frame.

Once the GPU finishes rendering the back buffer, an execution call—such as glfwSwapBuffers, wglSwapBuffers, or glXSwapBuffers—is issued to swap the buffers, turning the back buffer into the new front buffer.

What VSync Controls

Displays redraw pixels row by row from top to bottom at a set frequency (e.g., 60Hz, 144Hz). Between completing one full frame and starting the next, the monitor undergoes a brief pause known as the Vertical Blanking Interval (VBLANK). VSync settings determine when the buffer swap is allowed to execute relative to VBLANK:

1. VSync Disabled (Swap Interval 0)

When VSync is turned off, the buffer swap occurs immediately when the frame finishes rendering, regardless of where the display's scanout beam is located.

  • Consequence: If the buffers swap mid-scanout, the display draws the top portion of the screen from the old frame and the bottom portion from the new frame. This results in an artifact known as screen tearing.
  • Latency: Input latency is minimized because the monitor always receives the newest available image data with zero wait time.

2. VSync Enabled (Swap Interval 1)

When VSync is enabled, the GPU halts the buffer swap until the monitor finishes the current frame and enters the VBLANK period.

  • Consequence: Screen tearing is completely eliminated because a swap never occurs while the screen is actively reading pixels.
  • Latency & Frame Drops: If the GPU takes longer to render a frame than the duration of the display's refresh interval (for example, taking 17ms on a 60Hz/16.6ms screen), the swap misses the VBLANK. The monitor must redraw the previous frame again, effectively cutting the perceived framerate in half (e.g., dropping from 60 FPS directly to 30 FPS) and introducing input lag.

3. Higher Swap Intervals (Interval \(n\))

OpenGL allows setting an integer swap interval via platform extensions (like wglSwapIntervalEXT on Windows or glXSwapIntervalSGI on Linux). Setting an interval of \(n\) forces the application to wait for \(n\) monitor refresh cycles before swapping, effectively locking the maximum frame rate to \(\frac{\text{Refresh Rate}}{n}\).

4. Adaptive VSync (Negative Swap Intervals)

Many modern OpenGL implementations support extensions such as EXT_swap_control_tear. Passing a negative interval (such as -1) enables adaptive VSync:

  • If the application runs at or above the monitor's refresh rate, VSync remains active to eliminate tearing.
  • If the frame rate drops below the refresh rate, VSync automatically disables itself for that frame, allowing an immediate swap to minimize stutter and input lag at the expense of temporary tearing.

Summary

The vertical synchronization setting in OpenGL is the gatekeeper of buffer presentation. It acts as a deliberate trade-off mechanism: enabling it prioritizes visual integrity and smooth pacing by aligning buffer swaps with VBLANK, while disabling it prioritizes immediate responsiveness and low latency at the expense of screen tearing.
