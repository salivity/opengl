Depth Comparison for Clustered Lighting in OpenGL

This article examines the critical function of depth values and depth comparison in clustered shading architectures implemented in modern OpenGL. It covers how non-linear hardware depth is mapped to linear space, how depth comparisons assign fragments to spatial cluster bins along the view frustum, and how depth boundaries prevent unnecessary light calculations by isolating visible geometric ranges.

The Role of Depth in Clustered Lighting

Clustered lighting subdivides the camera frustum into a 3D grid of cells—referred to as clusters or froxels—along the screen-space X, Y, and view-space Z axes. Unlike standard tiled forward shading, which bins lights strictly in 2D screen tiles, clustered lighting uses depth to isolate lights within specific volumetric segments along the camera's line of sight.

To shade a fragment, the rendering pipeline must determine which cluster contains the fragment. This requires reconstructing the fragment's position in view or world space, a process fundamentally reliant on the depth buffer.

Reconstructing View-Space Depth

OpenGL stores non-linear depth values in the range \([0, 1]\) within the hardware depth buffer or a depth attachment. In the fragment shader or compute pass:

  1. Depth Retrieval: The normalized device coordinate (NDC) depth is sampled from a depth texture or read directly via gl_FragCoord.z.
  2. Linearization: Non-linear hardware depth is converted to linear view-space depth using the camera's near (\(z_{near}\)) and far (\(z_{far}\)) projection planes:

\[Z_{view} = \frac{z_{near} \cdot z_{far}}{z_{far} - z_{raw} \cdot (z_{far} - z_{near})}\]

  1. Position Calculation: Combining this linear depth with the screen coordinate and the inverse projection matrix reconstructs the 3D position needed for distance calculations against point, spot, and area lights.

Depth Comparison and Cluster Indexing

Once linear depth is acquired, depth comparison determines the cluster slice index along the Z-axis.Frustum depth is typically partitioned logarithmically rather than linearly to account for perspective projection and maintain uniform cluster sizes in view space:

\[Slice_Z = \left\lfloor \frac{\log(-Z_{view} / z_{near})}{\log(z_{far} / z_{near})} \cdot Slices_{total} \right\rfloor\]

Depth comparison serves distinct functions at two stages of the pipeline:

  • Fragment-to-Cluster Mapping: During the final shading pass, the fragment's linear depth is compared against the precomputed near and far bounds of cluster slices to fetch the correct light list offset from a Shader Storage Buffer Object (SSBO).
  • Cluster Frustum Building (Light Culling): When generating bounding boxes or spheres for the clusters in a compute shader, depth slice boundaries are compared against light bounding volumes to build per-cluster light index lists.

Depth Bounds and Precision Management

Depth comparisons directly impact the efficiency and visual correctness of clustered rendering in OpenGL:

  • Bounding Range Optimization: Without depth comparisons, clusters would span the entire view frustum from near to far planes, increasing light assignment overhead. By testing depth values, only the clusters containing actual geometry are flagged for active lighting evaluation.
  • Precision Artifacts: Standard 24-bit integer depth buffers exhibit severe non-linear precision loss near the far plane. Imprecise depth comparisons can cause a fragment to be assigned to an adjacent cluster, resulting in popping artifacts or missed light contributions. Using a 32-bit floating-point depth buffer (GL_DEPTH_COMPONENT32F) and reversed floating-point depth techniques minimizes comparison error across cluster boundaries.
  • Early Depth Testing: Performing depth comparisons prior to fragment execution via layout(early_fragment_tests) in; ensures that hidden or occluded geometry is discarded before position reconstruction and cluster lookup occur, eliminating redundant memory fetches from the light buffers.
