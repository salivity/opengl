Generating Geometry with OpenGL Compute Shaders

Compute shaders in modern OpenGL provide a flexible, general-purpose method for procedural geometry generation, terrain tessellation, and particle meshing. By executing arbitrary compute workloads across parallel workgroups, compute shaders can generate triangle primitives by writing vertex coordinates, normals, and indices directly into memory buffers. Because compute shaders bypass the traditional fixed-function pipeline, they do not write directly to legacy Transform Feedback targets; instead, they output to Shader Storage Buffer Objects (SSBOs) that simultaneously double as Vertex Buffer Objects (VBOs), allowing the rasterizer to immediately consume the synthesized mesh data.

The Unified Buffer Architecture

The key to generating vertex and index data in a compute shader and consuming it in a rendering pass is OpenGL's flexible buffer binding model. An OpenGL buffer is merely an allocated block of GPU memory; its role is determined by the binding target used at any given time.

  1. Buffer Allocation: Allocate a buffer using glNamedBufferStorage or glBufferData. Flag the buffer for dynamic storage, allowing it to be bound both as an SSBO (GL_SHADER_STORAGE_BUFFER) for the compute pass and as a VBO (GL_ARRAY_BUFFER) or element buffer (GL_ELEMENT_ARRAY_BUFFER) for the draw pass.
  2. Compute Binding: Bind the buffer to an indexed target via glBindBufferBase(GL_SHADER_STORAGE_BUFFER, binding_index, buffer_id).
  3. Vertex Array Configuration: In the Vertex Array Object (VAO), bind the exact same buffer using glVertexArrayVertexBuffer or glBindBuffer(GL_ARRAY_BUFFER, buffer_id) and define its vertex attribute layouts using glVertexAttribPointer.

Writing Vertices in the Compute Shader

Within the compute shader (GLSL), the target buffer is declared as a buffer block, typically using the std430 layout for tightly packed, efficient memory alignment.

#version 430 core

layout(local_size_x = 64, local_size_y = 1, local_size_z = 1) in;

struct Vertex {
    vec4 position;
    vec4 normal;
};

layout(std430, binding = 0) writeonly buffer OutputMesh {
    Vertex vertices[];
};

void main() {
    uint triangleIndex = gl_GlobalInvocationID.x;
    uint vertexOffset = triangleIndex * 3;

    // Procedural generation logic for three vertices of a triangle
    vertices[vertexOffset + 0].position = vec4(...);
    vertices[vertexOffset + 1].position = vec4(...);
    vertices[vertexOffset + 2].position = vec4(...);
}

The shader calculates triangle vertices linearly or parametrically using thread invocation IDs (gl_GlobalInvocationID). Each thread can compute an entire triangle (writing three distinct Vertex structures) or handle a single vertex within a grid.

Memory Synchronization

Compute shaders execute asynchronously relative to the rest of the OpenGL pipeline. To prevent data hazards—such as the vertex puller reading unwritten or partially written vertex data—a memory barrier must be placed between the compute dispatch and the draw call:

// Dispatch the compute shader
glUseProgram(computeProgram);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 0, meshBuffer);
glDispatchCompute(numWorkgroupsX, 1, 1);

// Ensure compute writes are visible to vertex attribute fetching
glMemoryBarrier(GL_VERTEX_ATTRIB_ARRAY_BARRIER_BIT | GL_ELEMENT_ARRAY_BARRIER_BIT);

// Render the generated geometry
glUseProgram(renderProgram);
glBindVertexArray(meshVAO);
glDrawArrays(GL_TRIANGLES, 0, totalGeneratedVertices);

If the generated geometry uses an index buffer instead of unindexed arrays, include GL_ELEMENT_ARRAY_BARRIER_BIT in the memory barrier mask.

Dynamic Counts and Indirect Drawing

When the exact number of generated triangles is unknown ahead of time—such as in Marching Cubes or dynamic frustum culling algorithms—atomic counters inside the compute shader track the emitted vertex count.

Rather than reading this count back to the CPU via glGetBufferSubData (which causes a pipeline stall), the compute shader writes the count directly into a DrawArraysIndirectCommand struct inside a GL_DRAW_INDIRECT_BUFFER. The draw pass then uses glDrawArraysIndirect or glDrawElementsIndirect, allowing entire compute-to-draw generation loops to reside entirely on the GPU without CPU intervention.
