Screen-Space Reflections Ray Marching in OpenGL

Screen-space reflections (SSR) create dynamic, real-time reflections by reusing scene data already rendered to the frame buffer. Inside an OpenGL fragment shader, this technique relies on ray marching through screen space, projecting reflection rays from surface fragments and checking them against the scene's depth buffer. This article details the mathematical and algorithmic pipeline required to implement ray-marched SSR, from ray setup and depth intersection tests to binary search refinement and artifact mitigation.

1. Required Buffers and Inputs

To perform SSR in a deferred or post-processing pipeline, the fragment shader requires access to several G-buffer textures:

  • Depth Texture: Used to reconstruct 3D positions and evaluate ray-surface intersections.
  • Normal Texture: View-space surface normals for calculating the reflection direction.
  • Color/Albedo Texture: The fully rendered HDR scene color to sample reflection values from.
  • Projection and Inverse Projection Matrices: Uniform matrices to transform coordinates between view space and normalized device coordinate (NDC) space.

2. Calculating the Reflection Vector

The process begins by reconstructing the current fragment's view-space position. Using the fragment's screen UV coordinates and sampling the depth buffer, you convert the screen-space coordinate into NDC space (coordinates ranging from -1.0 to 1.0) and multiply it by the inverse projection matrix:

vec3 getViewPosition(vec2 texCoord) {
    float depth = texture(depthTexture, texCoord).r * 2.0 - 1.0;
    vec4 clipSpacePosition = vec4(texCoord * 2.0 - 1.0, depth, 1.0);
    vec4 viewSpacePosition = invProjectionMatrix * clipSpacePosition;
    return viewSpacePosition.xyz / viewSpacePosition.w;
}

The view vector points from the camera (which is at vec3(0.0) in view space) to the fragment position. Using the normalized view direction and the view-space normal, compute the reflection vector using the GLSL reflect function:

vec3 viewDir = normalize(viewPos);
vec3 reflectDir = normalize(reflect(viewDir, normal));

3. Ray Marching in View and Screen Space

With the starting position and reflection vector determined, the ray advances iteratively along the reflection vector. While advanced methods march directly in screen-space 2D coordinates (using a DDA algorithm), uniform 3D view-space marching is standard and straightforward to implement:

  1. Define Steps: Establish a maximum number of steps (e.g., 30 to 100) and a step size.
  2. March the Ray: In each iteration, increment the ray's position: currentRayPos += reflectDir * stepSize.
  3. Project to Screen Space: Transform currentRayPos using the standard projectionMatrix to obtain clip coordinates, perform the perspective divide by w, and map the result to [0.0, 1.0] texture UV space.
  4. Sample Scene Depth: Read the stored depth value at the projected UV coordinate and convert it to linear view-space depth.

4. Detecting Intersections

An intersection occurs when the ray travels behind geometry currently visible in the depth buffer. This requires checking two conditions:

  • The ray's current view-space depth is greater than (or further away than) the depth sampled from the texture at the ray's projected UV.
  • The difference between the ray depth and sampled depth is within a specified thickness threshold to prevent the ray from falsely hitting the back of thin geometry.
float sampledDepth = getViewPosition(projectedUV).z;
if (rayPos.z < sampledDepth && abs(rayPos.z - sampledDepth) < thickness) {
    // Hit detected
}

5. Binary Search Refinement

Uniform ray marching often produces stepping artifacts or missed intersections. When a hit is detected, a binary search refines the exact point of contact. The shader halves the step size and steps backward or forward depending on whether the refined ray is currently in front of or behind the surface depth. Repeating this for 4 to 8 iterations significantly sharpens reflections without heavily impacting performance.

6. Shading, Edge Fading, and Limitations

Once the final UV intersection coordinate is determined, sample the scene color texture at that coordinate to get the reflected color.

Because SSR only reflects data present in the current camera frame, rays intersecting off-screen geometry or backfaces lack valid data. Smooth falloff masks must be applied to prevent harsh cutoffs:

  • Screen Edge Fading: Attenuate reflection intensity as the hit UV coordinates approach 0.0 or 1.0.
  • Fresnel Factor: Scale the reflection using the Schlick Fresnel approximation to ensure surfaces are more reflective at grazing angles.
  • Camera Facing Attenuation: Fade out reflection vectors that point directly toward the camera, as they will hit back-facing geometry not recorded in the depth buffer.
