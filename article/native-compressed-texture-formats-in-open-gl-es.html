Native Compressed Texture Formats in OpenGL ES

Efficient mobile graphics rendering relies heavily on hardware-level texture compression to reduce memory footprint, optimize bandwidth, and minimize battery consumption. Unlike standard image compression formats like PNG or JPEG, GPU texture formats allow random, fast access to texel data directly on the hardware. This article examines the native compressed texture formats used across mobile devices running OpenGL ES, distinguishing between universal standards and vendor-specific legacy formats.

ETC1 (Ericsson Texture Compression)

Introduced as an optional extension in OpenGL ES 2.0, ETC1 became the baseline texture format for early Android devices.

  • Characteristics: Compresses 24-bit RGB data into 4-bit-per-pixel (bpp) blocks using 4x4 texel blocks.
  • Limitations: ETC1 lacks native support for an alpha channel. To use transparency, developers must either supply a secondary alpha-only texture or use shader-based workarounds.
  • Hardware Support: Universally supported across virtually all Android hardware running OpenGL ES 2.0 and later.

ETC2 and EAC

ETC2 is a backward-compatible superset of ETC1, standardized as a mandatory core feature in OpenGL ES 3.0.

  • RGB8 / RGBA8: Provides high-quality RGB compression alongside native alpha support (both 1-bit punch-through alpha and full 8-bit interpolated alpha).
  • EAC (Ericsson Alpha Compression): Used for single-channel (R11) and dual-channel (RG11) data, making it ideal for normal maps, height maps, and separate masks.
  • Hardware Support: Mandatory for any mobile GPU certified for OpenGL ES 3.0 or higher (including ARM Mali, Qualcomm Adreno, and Imagination PowerVR).

ASTC (Adaptive Scalable Texture Compression)

Developed by ARM and AMD and adopted by Khronos, ASTC is the current industry standard for mobile texture compression. It is an extension in OpenGL ES 3.0/3.1 and a core feature of OpenGL ES 3.2.

  • Flexibility: ASTC operates using variable block footprints ranging from 4x4 pixels (8.0 bpp) down to 12x12 pixels (0.89 bpp). This allows developers to fine-tune the exact balance between file size and visual fidelity on a per-texture basis.
  • Channels: Natively supports 1 to 4 channels (RGBA) in both low dynamic range (LDR) and high dynamic range (HDR).
  • Hardware Support: Supported on modern mobile GPUs, including ARM Mali (T628 and newer), Qualcomm Adreno (4xx series and newer), and Apple GPUs (A8 and newer).

Vendor-Specific Formats (Legacy)

Before the adoption of OpenGL ES 3.0 and ASTC, mobile GPU manufacturers relied heavily on proprietary formats exposed through vendor-specific extensions:

  • PVRTC / PVRTC2 (PowerVR): Proprietary to Imagination Technologies. PVRTC was standard on early iOS devices and select Android devices. It supports 2 bpp and 4 bpp modes with alpha, but requires square textures with power-of-two (POT) dimensions.
  • ATC (Adreno Texture Compression): Originally developed by AMD and later acquired by Qualcomm, ATC provided RGB and RGBA compression exclusively on early Adreno GPUs. It is now deprecated in favor of ETC2 and ASTC.
  • S3TC / DXT (Desktop Legacy): Standard on desktop GPUs, S3TC was natively supported on mobile only through Nvidia Tegra hardware via vendor-specific extensions (GL_EXT_texture_compression_s3tc).
