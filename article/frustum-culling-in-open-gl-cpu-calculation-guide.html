Frustum Culling in OpenGL: CPU Calculation Guide

Frustum culling is an optimization technique that removes 3D objects outside the camera's field of view before they are rendered, saving significant computational resources. This guide explains the core concepts of frustum culling and details how to extract camera frustum planes from view-projection matrices, test bounding volumes on the CPU, and filter out invisible geometry prior to dispatching OpenGL draw commands.

Understanding the View Frustum

A viewing frustum is a geometric pyramid with its apex sliced off, representing the region of world space visible to the camera. It is defined by six clipping planes: Near, Far, Left, Right, Top, and Bottom.

When a scene contains thousands of objects, submitting every mesh to OpenGL via glDrawElements or glDrawArrays introduces massive CPU driver overhead and wastes GPU vertex processing cycles on geometry that will never appear on screen. Performing frustum culling on the CPU allows you to discard non-visible objects completely, avoiding draw call overhead and state changes.

Extracting Frustum Planes from the View-Projection Matrix

A plane in 3D space is defined by the algebraic equation:

\[Ax + By + Cz + D = 0\]

Where \((A, B, C)\) represents the normal vector of the plane and \(D\) represents the signed distance from the origin.

Using the Gribb-Hartmann method, the six frustum planes can be extracted directly from the combined View-Projection matrix (\(M = \text{Projection} \times \text{View}\)). Given row vectors of matrix \(M\) denoted as \(row_0, row_1, row_2, row_3\):

  • Left Plane: \(row_3 + row_0\)
  • Right Plane: \(row_3 - row_0\)
  • Bottom Plane: \(row_3 + row_1\)
  • Top Plane: \(row_3 - row_1\)
  • Near Plane: \(row_3 + row_2\)
  • Far Plane: \(row_3 - row_2\)

After calculating each plane's \((A, B, C, D)\) coefficients, normalize them by dividing all four components by the length of the normal vector:

\[\text{Length} = \sqrt{A^2 + B^2 + C^2}\] \[A' = \frac{A}{\text{Length}}, \quad B' = \frac{B}{\text{Length}}, \quad C' = \frac{C}{\text{Length}}, \quad D' = \frac{D}{\text{Length}}\]

Normalization ensures that evaluating the plane equation for any point \((x, y, z)\) yields the true signed Euclidean distance to that plane.

Defining Bounding Volumes

Testing every vertex of a mesh against the six planes on the CPU is computationally prohibitive. Instead, wrap objects in simplified bounding volumes:

  1. Bounding Sphere: Defined by a center point \(C\) and a radius \(R\).
  2. Axis-Aligned Bounding Box (AABB): Defined by a center point \(C\) and half-extents vector \(E = (e_x, e_y, e_z)\), or minimum and maximum corner points.

Performing Intersection Tests

To determine if an object is inside the frustum, test its bounding volume against all six normalized planes. If the volume lies completely behind any single plane, it is outside the frustum and culled.

Bounding Sphere Test

Compute the signed distance from the sphere's center \((C_x, C_y, C_z)\) to the plane:

\[\text{Distance} = A \cdot C_x + B \cdot C_y + C \cdot C_z + D\]

  • If \(\text{Distance} < -R\) for any of the six planes, the sphere is outside the frustum.
  • If \(\text{Distance} \ge -R\) for all six planes, the sphere is inside or intersecting the frustum.

Axis-Aligned Bounding Box (AABB) Test

For an AABB with center \(C\) and extents \(E\), compute the projected radius \(r\) along the plane's normal:

\[r = e_x \cdot |A| + e_y \cdot |B| + e_z \cdot |C|\] \[\text{Distance} = A \cdot C_x + B \cdot C_y + C \cdot C_z + D\]

  • If \(\text{Distance} < -r\) for any plane, the box is completely outside.
  • If \(\text{Distance} \ge -r\) across all planes, the box is visible.

Integrating CPU Culling into the OpenGL Pipeline

CPU culling takes place immediately before rendering commands are recorded:

  1. Update Camera: Recalculate view and projection matrices upon camera movement.
  2. Extract Planes: Compute and normalize the six frustum planes from the updated matrix.
  3. Traverse Scene Objects: Iterate through your renderable entities.
    • Transform the object's local bounding volume into world space using its model matrix.
    • Execute the intersection test against the six planes.
  4. Issue Draw Calls: Only append visible objects to your active render list or directly invoke their respective OpenGL functions (glBindVertexArray, glUniform*, glDrawElements).

By filtering invisible geometry on the CPU, you ensure that the GPU only processes primitives that contribute to the final rendered frame.
