Surface Tension in OpenGL Compute Shaders

This article explores how surface tension calculations operate within a compute-based fluid particle simulation in OpenGL. It covers the mathematical formulation using Smoothed Particle Hydrodynamics (SPH), the multi-pass GPU architecture required for neighbor evaluation, the derivation of interface normals and curvature, and how OpenGL Compute Shaders execute these physical models efficiently through Shader Storage Buffer Objects (SSBOs).

Particle Representation and GPU Memory Layout

In an OpenGL-based fluid simulation, particles are stored within Shader Storage Buffer Objects (SSBOs). Each particle is assigned a state containing its position, velocity, density, pressure, and accumulated forces. These buffers are bound to compute shader stages via binding points:

layout(std430, binding = 0) buffer ParticlePositions { vec4 positions[]; };
layout(std430, binding = 1) buffer ParticleVelocities { vec4 velocities[]; };
layout(std430, binding = 2) buffer ParticleProperties { vec4 properties[]; }; // x: density, y: pressure
layout(std430, binding = 3) buffer ParticleForces     { vec4 forces[]; };

Using vec4 alignment ensures data matches the GPU's native memory alignment standards, avoiding padding overhead and misaligned read/write cycles.

Spatial Partitioning and Neighbor Discovery

Surface tension is an inter-particle force that only acts within a defined smoothing kernel radius \(h\). Calculating interactions across all particle pairs results in an \(O(N^2)\) algorithmic complexity, which is impractical for real-time applications.

To solve this, a preliminary compute pipeline partitions the simulation domain into a uniform 3D grid:

  1. Cell Hash Computation: A compute pass calculates a spatial grid cell index for each particle: \(\text{hash} = \lfloor x / h \rfloor + \lfloor y / h \rfloor \times D_x + \lfloor z / h \rfloor \times D_x D_y\).
  2. Sorting: Particles are sorted by grid cell index using a GPU-accelerated parallel radix sort or bitonic sort.
  3. Cell Start/End Construction: An index table records the starting and ending offsets of each cell within the sorted particle array.

Subsequent passes iterate only through the 27 neighboring cells (the current cell plus 26 adjacent neighbors) to locate nearby interacting particles.

The Mathematics of Surface Tension in SPH

Surface tension arises from attractive intermolecular forces (cohesion) between fluid molecules. Inside the fluid volume, these forces cancel out. At the boundary, an imbalance creates a net inward force that minimizes surface area. In compute shaders, two primary models are implemented:

1. Color Field and Curvature (Müller’s Formulation)

Müller’s model defines a smooth marker function called the "color field" (\(c\)), which equals 1 at fluid particles and 0 outside. For particle \(i\):

\[c_i = \sum_j \frac{m_j}{\rho_j} W(\mathbf{r}_i - \mathbf{r}_j, h)\]

Where \(m_j\) is particle mass, \(\rho_j\) is particle density, and \(W\) is a radially symmetric smoothing kernel (typically the Poly6 kernel).

The gradient of this color field yields the inward-pointing surface normal vector \(\mathbf{n}_i\):

\[\mathbf{n}_i = \nabla c_i = \sum_j \frac{m_j}{\rho_j} \nabla W(\mathbf{r}_i - \mathbf{r}_j, h)\]

The surface curvature \(\kappa\) is derived from the divergence of the normalized normal vector, often computed using the Laplacian of the color field:

\[\kappa_i = -\frac{\nabla^2 c_i}{|\mathbf{n}_i|}\]

The surface tension force \(\mathbf{F}_{\text{st}}\) is applied only when \(|\mathbf{n}_i|\) exceeds a defined threshold (to prevent false forces in the fluid's interior):

\[\mathbf{F}_{i, \text{st}} = -\sigma \kappa_i \frac{\mathbf{n}_i}{|\mathbf{n}_i|} = -\sigma \nabla^2 c_i \frac{\mathbf{n}_i}{|\mathbf{n}_i|}\]

Where \(\sigma\) is the tension coefficient of the fluid.

2. Pairwise Cohesion (Akinci’s Formulation)

Because the second-order derivative (\(\nabla^2 c\)) in Müller's model is prone to numerical instability, modern engines often implement Akinci's pairwise approach. This separates surface tension into a direct cohesion force \(\mathbf{F}_{\text{cohesion}}\) and a surface minimization force \(\mathbf{F}_{\text{curvature}}\):

\[\mathbf{F}_{i, \text{cohesion}} = -\sigma \sum_j m_j C(\|\mathbf{r}_i - \mathbf{r}_j\|) \frac{\mathbf{r}_i - \mathbf{r}_j}{\|\mathbf{r}_i - \mathbf{r}_j\|}\]

\[\mathbf{F}_{i, \text{curvature}} = -\sigma \sum_j (\mathbf{n}_i - \mathbf{n}_j)\]

Where \(C(r)\) is a spline kernel designed specifically to provide strong cohesion at medium distances and zero force at short distances to prevent particle clustering.

Compute Shader Execution Stages

To implement this pipeline in OpenGL, multiple compute shader dispatches are coordinated via host code using execution barriers:

  1. Pass 1: Density and Normal Evaluation

    • Computes density \(\rho_i\) via summation over neighbors.
    • Computes the interface normal vector \(\mathbf{n}_i\) by evaluating the color field gradient.
    • Writes the normal vectors to an intermediate SSBO.

  2. Synchronization:

    glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT);

  3. Pass 2: Force Evaluation

    • Binds the normal vector SSBO as input.
    • Reads neighboring normals to calculate the Laplacian \(\nabla^2 c_i\) or normal differences \((\mathbf{n}_i - \mathbf{n}_j)\).
    • Combines surface tension with pressure forces, viscosity forces, and gravity: \[\mathbf{F}_{\text{total}} = \mathbf{F}_{\text{pressure}} + \mathbf{F}_{\text{viscosity}} + \mathbf{F}_{\text{st}} + m\mathbf{g}\]
    • Writes the final force into the forces SSBO.

  4. Synchronization:

    glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT);

  5. Pass 3: Time Integration

    • Employs Symplectic Euler or Verlet integration: \[\mathbf{v}_{t+\Delta t} = \mathbf{v}_t + \frac{\mathbf{F}_{\text{total}}}{m}\Delta t\] \[\mathbf{x}_{t+\Delta t} = \mathbf{x}_t + \mathbf{v}_{t+\Delta t}\Delta t\]
    • Handles boundary collisions with domain walls.

Optimization Strategies

Compute-based surface tension calculations are bound by memory bandwidth and thread divergence during neighbor evaluations. Performance is preserved using several key techniques:

  • Shared Memory Caching: Nearby particle positions can be collectively loaded into compute workgroup shared memory arrays to eliminate redundant global SSBO memory fetches.
  • Kernel Truncation: Specialized smoothing kernels that flatten to zero at the cutoff radius \(h\) remove the need for non-linear branches in the inner interaction loop.
  • Vectorized Pack Formats: Storing normal vectors and scalar curvature values in packed vec4 buffers allows OpenGL to maximize memory bus throughput during write operations.
