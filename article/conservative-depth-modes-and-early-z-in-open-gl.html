Conservative Depth Modes and Early-Z in OpenGL

This article explains how conservative depth output modes resolve a major GPU rendering bottleneck in OpenGL. By default, modifying depth inside a fragment shader forces the graphics pipeline to disable early depth testing (Early-Z), resulting in wasted fragment processing. Conservative depth declarations provide the driver and hardware with specific guarantees about fragment depth modifications, allowing the GPU to maintain early depth culling and preserve rendering performance.

The Problem: Early-Z and Custom Fragment Depth

Modern GPUs optimize rendering throughput via Early-Z testing, where the depth test is evaluated before the fragment shader executes. If an incoming fragment is determined to be occluded by previously rendered geometry, the GPU discards it immediately. This avoids running complex, performance-heavy fragment shading operations on invisible pixels.

However, if a fragment shader writes to the built-in variable gl_FragDepth (common in techniques like depth-peeling, displacement mapping, or impostor rendering), the GPU cannot determine the fragment's final depth value ahead of time. Consequently, the hardware is forced to disable Early-Z, execute the fragment shader in its entirety, and only then evaluate the depth test. In fill-rate-limited scenes with high overdraw, this causes significant performance degradation.

What Are Conservative Depth Output Modes?

Introduced in the ARB_conservative_depth extension and integrated into core OpenGL 4.2, conservative depth allows developers to declare how the custom depth generated by the fragment shader relates to the fixed-function interpolated depth (gl_FragCoord.z).

Instead of treating gl_FragDepth as an unpredictable arbitrary value, the shader specifies constraints via layout qualifiers. These guarantees allow the GPU's fixed-function units to perform conservative depth tests—specifically against coarse rejection mechanisms like Hierarchical-Z (Hi-Z)—before the fragment shader runs.

GLSL Conservative Depth Qualifiers

To enable conservative depth, the layout qualifier is applied to the depth output redeclaration at the top of the fragment shader:

layout (depth_<qualifier>) out float gl_FragDepth;

The available qualifiers are:

  • depth_any: The default behavior. Depth can change in any direction. Early-Z culling is fully disabled.
  • depth_greater: Guarantees the written depth will always be greater than or equal to gl_FragCoord.z (gl_FragDepth >= gl_FragCoord.z).
  • depth_less: Guarantees the written depth will always be less than or equal to gl_FragCoord.z (gl_FragDepth <= gl_FragCoord.z).
  • depth_unchanged: Guarantees that if gl_FragDepth is written, its value will be identical to gl_FragCoord.z.

How Conservative Depth Preserves Early-Z

Conservative depth preserves culling efficiency by enabling directional pruning based on the active depth comparison function (glDepthFunc).

Consider a standard depth test setup using GL_LESS (where objects closer to the camera pass):

  1. With layout (depth_greater): The shader guarantees that the final depth will only be pushed further away from the camera compared to the triangle's interpolated surface. If the hardware-interpolated depth gl_FragCoord.z is already behind the value stored in the depth buffer, the final depth is guaranteed to fail the GL_LESS test as well. The GPU can safely discard the fragment prior to running the fragment shader.
  2. With layout (depth_less): The final depth is guaranteed to move closer to the camera. While early rejection is not possible under GL_LESS (a fragment that currently fails might move forward and pass), this mode enables early rejection if the depth function is configured to GL_GREATER.

By matching the appropriate qualifier with the scene's depth test direction, the hardware's coarse-grained culling structures reject fully occluded fragments prior to shader execution, recovering much of the performance lost when writing custom depth values.
