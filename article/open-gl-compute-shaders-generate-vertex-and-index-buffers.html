OpenGL Compute Shaders: Generate Vertex and Index Buffers

OpenGL compute shaders can generate and populate geometry data directly on the GPU, bypassing costly CPU round-trips before rendering. By treating standard OpenGL buffer objects interchangeably as Shader Storage Buffer Objects (SSBOs) during compute passes and as Vertex Buffer Objects (VBOs) or Element Buffer Objects (EBOs) during render passes, you can procedurally build or modify geometry on the fly. This workflow requires proper buffer allocation, binding the buffers to the compute pipeline, enforcing synchronization via memory barriers, and then issuing standard indexed draw calls.

1. Buffer Allocation

OpenGL buffers are simply blocks of linear GPU memory; their usage depends entirely on how they are bound. Allocate your vertex and index buffers using modern direct state access (glCreateBuffers and glNamedBufferStorage) or traditional buffer functions (glGenBuffers and glBufferData). Ensure you allocate enough capacity up front for the maximum number of vertices and indices the compute shader will generate.

GLuint vbo, ebo;
glGenBuffers(1, &vbo);
glBindBuffer(GL_SHADER_STORAGE_BUFFER, vbo);
glBufferData(GL_SHADER_STORAGE_BUFFER, maxVertices * sizeof(Vertex), NULL, GL_DYNAMIC_DRAW);

glGenBuffers(1, &ebo);
glBindBuffer(GL_SHADER_STORAGE_BUFFER, ebo);
glBufferData(GL_SHADER_STORAGE_BUFFER, maxIndices * sizeof(GLuint), NULL, GL_DYNAMIC_DRAW);

2. Compute Shader Writing to SSBOs

Within GLSL, declare the buffers as write-capable SSBOs. Use explicit layouts and alignment rules (such as std430) to ensure data layout consistency between compute and vertex fetch stages.

#version 430 core
layout(local_size_x = 64, local_size_y = 1, local_size_z = 1) in;

struct Vertex {
    vec4 position;
    vec4 normal;
};

layout(std430, binding = 0) writeonly buffer VertexBuffer {
    Vertex vertices[];
};

layout(std430, binding = 1) writeonly buffer IndexBuffer {
    uint indices[];
};

void main() {
    uint id = gl_GlobalInvocationID.x;
    
    // Procedural vertex generation
    vertices[id].position = vec4(float(id), sin(float(id)), 0.0, 1.0);
    vertices[id].normal   = vec4(0.0, 1.0, 0.0, 0.0);

    // Procedural index generation (e.g., line or triangle lists)
    indices[id] = id;
}

3. Compute Dispatch and Synchronization

Before dispatching, bind the buffers to the SSBO binding points matching the GLSL declaration. After dispatching, you must insert a memory barrier. This tells OpenGL that writes from the compute shader must complete and become visible to subsequent vertex array and element array fetch operations.

glUseProgram(computeProgram);

glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 0, vbo);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 1, ebo);

glDispatchCompute((numElements + 63) / 64, 1, 1);

// Ensure compute writes finish before vertex and index fetching occurs
glMemoryBarrier(GL_VERTEX_ATTRIB_ARRAY_BARRIER_BIT | GL_ELEMENT_ARRAY_BARRIER_BIT);

4. Direct Rendering

Configure a Vertex Array Object (VAO) that treats the generated buffers as a standard VBO and EBO. Because synchronization was handled by glMemoryBarrier, the GPU can immediately use the generated contents in a rasterization pass without pipeline stalls or CPU readbacks.

glBindVertexArray(vao);

// Bind the generated buffers for rendering
glBindBuffer(GL_ARRAY_BUFFER, vbo);
glVertexAttribPointer(0, 4, GL_FLOAT, GL_FALSE, sizeof(Vertex), (void*)offsetof(Vertex, position));
glEnableVertexAttribArray(0);

glVertexAttribPointer(1, 4, GL_FLOAT, GL_FALSE, sizeof(Vertex), (void*)offsetof(Vertex, normal));
glEnableVertexAttribArray(1);

glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, ebo);

// Draw the geometry directly
glUseProgram(renderProgram);
glDrawElements(GL_TRIANGLES, indexCount, GL_UNSIGNED_INT, 0);

By unbinding SSBO targets and attaching the buffers to the VAO targets across a synchronization barrier, data generated in the compute pipeline flows seamlessly into subsequent draw calls entirely within GPU memory.
