glPolygonOffset Math: Factor and Units Explained

This article breaks down the mathematical formulation behind OpenGL's glPolygonOffset function, detailing how the factor and units parameters combine with polygon slope and depth buffer precision to offset fragment depth values. Understanding this calculation is essential for preventing visual artifacts such as Z-fighting in coplanar rendering, decals, and shadow mapping.

The glPolygonOffset(GLfloat factor, GLfloat units) function modifies the depth values (\(z\)) of fragments generated during rasterization. The calculation evaluates an offset value \(o\), which is added to each fragment's depth before the depth test and depth write take place.

The mathematical formula used to compute the offset is:

\[o = (m \times \text{factor}) + (r \times \text{units})\]

The Depth Slope Component (\(m\))

The variable \(m\) represents the maximum depth slope (gradient) of the polygon being rasterized. It reflects how sharply the depth changes across the screen space coordinates (\(x, y\)):

\[m = \max\left( \left| \frac{\partial z}{\partial x} \right|, \left| \frac{\partial z}{\partial y} \right| \right)\]

  • \(\frac{\partial z}{\partial x}\) is the rate of depth change along the screen-space X-axis.
  • \(\frac{\partial z}{\partial y}\) is the rate of depth change along the screen-space Y-axis.

When a polygon is parallel to the viewport (near/far planes), \(m = 0\), meaning the factor parameter produces no offset. As the polygon tilts and forms a steeper angle relative to the view plane, \(m\) increases significantly. Multiplying \(m\) by factor scales the depth shift proportionally to the polygon's steepness, preventing coplanar surfaces from clipping through each other at oblique viewing angles.

The Minimum Resolvable Difference (\(r\))

The variable \(r\) represents the smallest value guaranteed to produce a resolvable difference in the depth buffer. This is an implementation-dependent constant determined by the window system and depth buffer format:

  • Fixed-point depth buffers: For a buffer using \(n\) bits of precision, \(r\) is constant across the entire buffer, defined mathematically as: \[r = 2^{-n}\] For example, in a standard 24-bit fixed-point depth buffer, \(r = 2^{-24} \approx 5.96 \times 10^{-8}\).
  • Floating-point depth buffers: For buffers such as GL_DEPTH_COMPONENT32F, \(r\) varies dynamically based on the magnitude of the floating-point exponent at the evaluated depth value, scaling according to the precision of the mantissa.

Multiplying \(r\) by units ensures that the polygon is offset by a fixed number of depth buffer increments, independent of the polygon's orientation.

Final Fragment Depth

Once the total offset \(o\) is calculated, it is added to the fragment’s original interpolated depth coordinate \(z\):

\[z_{\text{final}} = \text{clamp}(z + o, 0.0, 1.0)\]

The resulting depth is clamped to the range defined by glDepthRange (normally \([0.0, 1.0]\)) before depth comparisons occur. A negative value for factor or units pulls the polygon closer to the near clipping plane, while a positive value pushes it further toward the far plane.
