Barycentric Coordinates in OpenGL Fragment Shaders

This article provides a technical overview of how to access hardware-generated barycentric coordinates directly within OpenGL fragment shaders using dedicated GPU extensions. Historically, acquiring barycentric weights required passing custom attributes through vertex or geometry shaders, introducing performance overhead and geometry pipeline complexity. By using vendor and multi-vendor extensions such as GL_EXT_fragment_shader_barycentric and GL_NV_fragment_shader_barycentric, developers can directly read built-in barycentric coordinate inputs per fragment to implement wireframe rendering, custom interpolation, and procedural edge anti-aliasing.

Overview of Barycentric Extensions

Modern GPUs calculate barycentric coordinates during the rasterization phase to interpolate vertex attributes across primitives. OpenGL exposes this internal data through two primary extensions:

  1. GL_EXT_fragment_shader_barycentric: The cross-vendor extension supported by modern drivers (AMD, Intel, NVIDIA) and modern SPIR-V/Vulkan-to-OpenGL workflows.
  2. GL_NV_fragment_shader_barycentric: The NVIDIA-specific extension that introduced hardware-level access on Turing and newer architectures.

Both extensions introduce built-in inputs containing the \((u, v, w)\) coordinates of the current fragment relative to the vertices of the generating primitive, satisfying the condition \(u + v + w = 1.0\).

Built-In Fragment Shader Variables

When enabling these extensions, the shading language provides specialized built-in variables representing barycentric coordinates:

  • Perspective-Correct Coordinates:
    • in vec3 gl_BaryCoordEXT; (or gl_BaryCoordNV)
    • Represents the perspective-interpolated barycentric coordinates of the fragment. This is optimal for texturing, physically based attribute reconstruction, and depth-aware geometric patterns.
  • Non-Perspective (Screen-Space) Coordinates:
    • in vec3 gl_BaryCoordNoPerspEXT; (or gl_BaryCoordNoPerspNV)
    • Represents linear screen-space coordinates without perspective division. This is ideal for screen-constant effects, such as rendering uniform-width wireframe outlines regardless of distance from the camera.

Implementation in GLSL

To utilize barycentric coordinates, request the extension at the top of the fragment shader. Below is an example using GL_EXT_fragment_shader_barycentric to render a single-pass wireframe:

#version 450 core
#extension GL_EXT_fragment_shader_barycentric : require

layout(location = 0) out vec4 fragColor;

// Thickness and color configurations
const float wireframeThickness = 0.02;
const vec4 edgeColor = vec4(0.0, 1.0, 0.0, 1.0);
const vec4 surfaceColor = vec4(0.1, 0.1, 0.1, 1.0);

void main()
{
    // gl_BaryCoordEXT contains (u, v, w) where each component corresponds
    // to the proximity to a triangle edge.
    vec3 bary = gl_BaryCoordEXT;

    // Determine the minimum distance to any edge
    float minBary = min(min(bary.x, bary.y), bary.z);

    // Apply screen-space derivatives for uniform line thickness if preferred,
    // or threshold directly on the barycentric coordinates:
    if (minBary < wireframeThickness) {
        fragColor = edgeColor;
    } else {
        fragColor = surfaceColor;
    }
}

If targeting NVIDIA hardware specifically where only the NV extension is available, replace the extension declaration and variable name:

#version 450 core
#extension GL_NV_fragment_shader_barycentric : require

layout(location = 0) out vec4 fragColor;

void main()
{
    vec3 bary = gl_BaryCoordNV;
    // Calculation continues...
}

Host-Side Verification

Before deploying shaders that rely on these built-in inputs, confirm hardware support on the host application by querying the OpenGL extension registry:

GLint numExtensions = 0;
glGetIntegerv(GL_NUM_EXTENSIONS, &numExtensions);

bool hasBarycentrics = false;
for (GLint i = 0; i < numExtensions; ++i) {
    const char* ext = (const char*)glGetStringi(GL_EXTENSIONS, i);
    if (strcmp(ext, "GL_EXT_fragment_shader_barycentric") == 0 ||
        strcmp(ext, "GL_NV_fragment_shader_barycentric") == 0) {
        hasBarycentrics = true;
        break;
    }
}

Advanced Usage: Direct Vertex Attribute Access

In addition to vector inputs, these extensions introduce the pervertexEXT (or pervertexNV) storage qualifier. This allows fragment shaders to read un-interpolated, raw vertex attributes directly from the triangle vertices:

#extension GL_EXT_fragment_shader_barycentric : require

layout(location = 0) pervertexEXT in vec3 inPosition[];

void main()
{
    // Explicitly interpolate attributes using custom barycentric weights
    vec3 customPosition = gl_BaryCoordEXT.x * inPosition[0] +
                          gl_BaryCoordEXT.y * inPosition[1] +
                          gl_BaryCoordEXT.z * inPosition[2];
}

Using this approach eliminates the memory bandwidth and geometry shader amplification previously required to pass primitive topological information down the pipeline.
