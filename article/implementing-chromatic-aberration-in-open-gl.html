Implementing Chromatic Aberration in OpenGL

Chromatic aberration is an optical phenomenon caused by a lens failing to focus all colors to the same convergence point, resulting in visible color fringing around high-contrast edges. In real-time rendering, this lens imperfection is frequently simulated as a post-processing effect to enhance visual realism or convey physical camera mechanics. This article details how to implement a chromatic aberration pass in OpenGL by rendering the scene to a framebuffer object (FBO) and shifting the texture coordinates of individual color channels inside a fullscreen post-processing fragment shader.

The Render Pipeline Setup

Simulating chromatic aberration requires rendering your 3D scene to an offscreen texture before drawing it to the default backbuffer. The standard workflow follows these steps:

  1. Create a Framebuffer Object (FBO): Attach a standard 2D color texture and a depth/stencil renderbuffer to an FBO.
  2. Render the Scene: Bind the FBO and draw the geometry normally. The final scene color will be stored in the attached color texture.
  3. Execute Post-Processing: Unbind the FBO (returning to the default screen buffer), bind the rendered scene texture to a texture unit, and draw a fullscreen quad using the chromatic aberration shader program.

Fragment Shader Implementation

The core visual effect occurs in the fragment shader. Because red, green, and blue light refract at different angles through a lens, the displacement is typically radial, increasing in intensity toward the edges of the screen while remaining negligible at the center.

Below is an effective GLSL fragment shader implementation:

#version 330 core

in vec2 TexCoords;
out vec4 FragColor;

uniform sampler2D sceneTexture;
uniform float uAberrationStrength; // Recommended start value: 0.005 to 0.02

void main()
{
    // Compute direction vector from the screen center (0.5, 0.5)
    vec2 dir = TexCoords - vec2(0.5);
    
    // Calculate radial distance squared to concentrate distortion at the edges
    float dist = dot(dir, dir);
    
    // Define per-channel UV offset vectors
    vec2 offset = dir * (dist * uAberrationStrength);
    
    // Sample channels individually with shifted coordinates
    float r = texture(sceneTexture, TexCoords + offset).r;
    float g = texture(sceneTexture, TexCoords).g;
    float b = texture(sceneTexture, TexCoords - offset).b;
    
    FragColor = vec4(r, g, b, 1.0);
}

Key Components of the Shader

  • Radial Direction Vector: Computing TexCoords - vec2(0.5) aligns the distortion with the natural perspective of a circular lens. Offsetting along this vector pushes fringes outward from the center.
  • Distance Falloff: Multiplying by dot(dir, dir) applies a quadratic falloff. This preserves image sharpness at the center of the frame and confines the color fringing to the screen margins, mirroring the behavior of real-world optical lenses.
  • Opposing Offset Directions: Adding the offset vector for the red channel while subtracting it for the blue channel creates symmetrical separation, leaving the green channel centered to anchor the luminance of the original image.

Fine-Tuning and Considerations

  • Aspect Ratio Correction: To prevent elliptical distortion on non-square viewports, normalize the direction vector using the screen's aspect ratio:

    vec2 aspectCorrectedDir = dir;
aspectCorrectedDir.x *= (screenWidth / screenHeight);

  • Clamp to Edge: Ensure the scene texture uses GL_CLAMP_TO_EDGE for GL_TEXTURE_WRAP_S and GL_TEXTURE_WRAP_T. If coordinates extend beyond [0.0, 1.0] at the viewport boundaries, this setting prevents sampling artifacts from wrapping around the opposite edges.

  • Performance: This method requires only three texture fetches per fragment, making it computationally lightweight and suitable for modern rendering pipelines without noticeable performance overhead.
