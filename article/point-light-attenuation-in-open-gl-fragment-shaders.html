Point Light Attenuation in OpenGL Fragment Shaders

Point light attenuation mathematically simulates how light diminishes as it travels through space away from its source. In OpenGL fragment shaders, calculating this distance falloff requires deriving the Euclidean distance between the fragment and the light source, evaluating an attenuation equation, and scaling the resulting diffuse and specular lighting components accordingly. This article breaks down the mathematical foundations of light falloff, the standard polynomial model, and its practical implementation in GLSL.

The Physics of Falloff vs. Real-Time Approximations

In real-world physics, light follows the inverse-square law:

\[\text{Intensity} = \frac{I_0}{d^2}\]

Where \(I_0\) is the initial light intensity and \(d\) is the distance from the emitter. While physically accurate, directly applying this pure inverse-square formula in real-time rendering often causes visual artifacts. When \(d\) approaches zero, the value approaches infinity, blowing out local surfaces. Furthermore, lights with pure inverse-square decay never mathematically reach zero, meaning every light source must theoretically be evaluated for every pixel in a scene.

The Standard OpenGL Attenuation Formula

To solve these visual and computational constraints, real-time graphics commonly relies on a polynomial attenuation function:

\[\text{Attenuation} = \frac{1.0}{K_c + K_l \cdot d + K_q \cdot d^2}\]

The terms in this equation fulfill specific operational roles:

  • \(d\) (Distance): The Euclidean distance between the light source and the current surface fragment.
  • \(K_c\) (Constant Factor): Usually set to \(1.0\). It ensures the denominator is never less than one, preventing division by zero and clamping the maximum attenuation factor to \(1.0\) at distance zero.
  • \(K_l\) (Linear Factor): Scales linearly with distance, dampening light smoothly over shorter distances.
  • \(K_q\) (Quadratic Factor): Scales with the square of the distance, replicating the physically realistic inverse-square decay as distance increases.

Mathematical Derivation in the Fragment Shader

In an OpenGL fragment shader using GLSL, the calculation takes place on per-fragment interpolated coordinates:

  1. Calculate the displacement vector: Subtract the fragment's world-space position from the light's world-space position: \[\vec{L}_{\text{diff}} = \vec{P}_{\text{light}} - \vec{P}_{\text{frag}}\]

  2. Compute Euclidean distance: Calculate the magnitude of the displacement vector: \[d = \sqrt{L_x^2 + L_y^2 + L_z^2} = \|\vec{L}_{\text{diff}}\|\]

  3. Compute the attenuation scalar: Apply the polynomial formula using the pre-configured attenuation constants.

  4. Modulate lighting terms: Multiply the computed ambient, diffuse, and specular components by the attenuation scalar (ambient light is sometimes left unattenuated or scaled separately to prevent complete darkness).

GLSL Implementation Example

#version 330 core

in vec3 FragPos;
in vec3 Normal;

out vec4 FragColor;

struct PointLight {
    vec3 position;
    vec3 color;
    
    float constant;
    float linear;
    float quadratic;
};

uniform PointLight light;
uniform vec3 viewPos;

void main()
{
    // 1. Calculate distance
    float distance = length(light.position - FragPos);
    
    // 2. Calculate attenuation factor
    float attenuation = 1.0 / (light.constant + light.linear * distance + light.quadratic * (distance * distance));
    
    // 3. Normal lighting calculations
    vec3 norm = normalize(Normal);
    vec3 lightDir = normalize(light.position - FragPos);
    
    float diff = max(dot(norm, lightDir), 0.0);
    vec3 diffuse = diff * light.color;
    
    vec3 viewDir = normalize(viewPos - FragPos);
    vec3 reflectDir = reflect(-lightDir, norm);
    float spec = pow(max(dot(viewDir, reflectDir), 0.0), 32.0);
    vec3 specular = spec * light.color;
    
    // 4. Apply attenuation
    diffuse *= attenuation;
    specular *= attenuation;
    
    vec3 result = diffuse + specular;
    FragColor = vec4(result, 1.0);
}

Range-Limited Attenuation (Culling)

To optimize performance, rendering engines often define a maximum cutoff radius (\(r_{\text{max}}\)). Any fragment where \(d \ge r_{\text{max}}\) skips lighting calculations entirely. A smooth windowing function can be combined with the attenuation to smoothly bring the intensity to zero at the cutoff radius:

\[\text{Window}(d) = \left( \max\left(0.0, 1.0 - \left(\frac{d}{r_{\text{max}}}\right)^4\right) \right)^2\]

Multiplying the polynomial attenuation by this windowing function ensures that light drops cleanly to absolute black at the outer boundary, eliminating sharp rendering borders at the edge of the light's effective sphere.
