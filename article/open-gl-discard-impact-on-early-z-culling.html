OpenGL Discard Impact on Early-Z Culling

Using the discard keyword inside an OpenGL fragment shader directly interferes with hardware-level early depth testing (Early-Z), frequently leading to reduced rendering throughput and unnecessary GPU overhead. This article explains how Early-Z culling operates under normal circumstances, why invoking discard forces hardware to alter its depth-testing behavior, the specific performance penalties incurred, and how to mitigate these issues in rendering pipelines.

Understanding Early-Z Culling

In standard graphics pipelines, depth testing occurs naturally after fragment shading (Late-Z). However, modern GPUs optimize this process by performing an Early-Z test before the fragment shader executes. If an incoming fragment is obscured by existing geometry, the GPU culls it immediately. This optimization prevents the pipeline from executing computationally expensive fragment shader instructions on invisible pixels, drastically reducing shading cost and memory bandwidth.

Why discard Compromises Early-Z

The discard keyword conditionally terminates the execution of a fragment shader and prevents the fragment from updating the framebuffer or the depth buffer. This conditional behavior creates a dependency hazard for the depth testing pipeline:

  1. Uncertainty of Pixel Existence: The GPU cannot write a fragment's depth value to the depth buffer before the shader runs because it does not yet know whether the shader will execute a discard.
  2. Disabling Depth Pre-Writes: Because writing depth early could erroneously mask geometry behind a discarded pixel, the hardware must disable early depth writes.
  3. Fallback to Late-Z: On many GPU architectures, the presence of discard completely disables Early-Z optimization for the affected draw call, shifting both the depth test and depth write to the Late-Z stage.

Primary Performance Consequences

1. Wasted Fragment Shading (Lost Occlusion Culling)

When Early-Z is disabled, the GPU must execute the fragment shader for every rasterized pixel, regardless of whether it is hidden behind already-rendered opaque geometry. In scenes with high depth complexity (dense overdraw), this causes significant performance drops as hidden pixels consume arithmetic logic units (ALU) and texture filtering resources.

2. Hierarchical Z (HiZ) Degradation

GPUs rely on hierarchical depth buffers (HiZ) to reject entire tiles of hidden pixels at once. When shaders introduce dynamic discards, the hardware often cannot update or maintain HiZ data accurately for that draw call. In severe cases, HiZ might be temporarily disabled or partially invalidated, causing performance degradation that spills into subsequent draw passes.

3. Pipeline Stalls and Cache Serialization

Deferred depth writes require the GPU to manage fragments longer in memory. Rather than retiring a quad as soon as the test finishes, the rasterizer must track dependencies between overlapping fragments to ensure they write back to the depth and color buffers in the correct API order. This tracking increases pressure on fragment caches and can create serialization bottlenecks.

Partial Mitigations by Modern Hardware

Modern GPU architectures implement varying levels of mitigation:

  • Early-Z Test with Late-Z Write: Many desktop architectures allow an Early-Z read/test even if discard is present, provided the shader does not write to gl_FragDepth. If the incoming fragment is already occluded by previously written opaque depth, it is discarded immediately. However, if the fragment passes, it cannot write to the depth buffer early. Consequently, if another object is rendered behind it within the same pass, that subsequent object cannot be culled early.

Best Practices to Minimize Overhead

  • Use a Depth Pre-Pass: Render your scene geometry to the depth buffer first using a minimal shader with depth writes enabled. In the secondary color pass, set the depth mask to false (glDepthMask(GL_FALSE)) and depth func to equal (glDepthFunc(GL_EQUAL)). Early-Z will successfully cull all fully hidden fragments before they hit the shader containing discard.
  • Sort Draw Calls Front-to-Back: If a depth pre-pass is too costly, drawing opaque geometry before masked (discarding) geometry ensures that fully opaque objects establish depth values that can cull masked objects via partial Early-Z tests.
  • Consider Alpha-to-Coverage: For cutouts such as foliage, MSAA-based alpha-to-coverage can replace manual discard statements in the shader, allowing the hardware to retain standard depth evaluation behaviors.
