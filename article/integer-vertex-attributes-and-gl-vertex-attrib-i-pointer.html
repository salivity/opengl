Integer Vertex Attributes and glVertexAttribIPointer

In modern OpenGL, vertex data often includes non-spatial information such as bone indices for skeletal animation, material IDs, or bitmask flags that require integer representation in vertex shaders. This article explains what integer vertex attributes are, how the OpenGL pipeline processes them, and why developers must initialize them using glVertexAttribIPointer rather than the traditional glVertexAttribPointer to avoid silent data corruption.

What Are Integer Vertex Attributes?

Integer vertex attributes are per-vertex data fields that bind directly to integer types inside a GLSL shader—such as int, ivec2, ivec4, uint, uvec3, and related variants. Unlike standard attributes that represent continuous spatial properties like positions, normals, and UV coordinates (which use floating-point types like float or vec3), integer attributes represent discrete data. Common use cases include:

  • Skeletal animation: Bone indices pointing to transformation matrices.
  • Instancing and batching: Object or draw-call identifiers.
  • Texture arrays: Layer indices specifying which texture slice to sample.
  • Logic masks: Bitfields representing state flags or rendering modes.

The Problem with glVertexAttribPointer

OpenGL provides the standard glVertexAttribPointer function to describe the layout of vertex buffer data. A common mistake is attempting to configure integer attributes by setting the type parameter of glVertexAttribPointer to an integer enum, such as GL_INT or GL_UNSIGNED_INT:

// Incorrect configuration for an 'in ivec4 boneIDs' shader attribute
glVertexAttribPointer(index, 4, GL_INT, GL_FALSE, stride, pointer);

While this compiles and runs without generating an explicit GL_INVALID_OPERATION error, it causes data corruption. glVertexAttribPointer instructs the driver to load the data from the buffer and convert it into a floating-point value before delivering it to the shader:

  1. Normalized (normalized = GL_TRUE): Integer values are mapped to floating-point values in the range [0.0, 1.0] or [-1.0, 1.0].
  2. Un-normalized (normalized = GL_FALSE): Integer values are directly converted to floating-point numbers (for example, the integer 5 becomes 5.0f).

Because the shader input is declared as an integer type (int or ivec*), feeding it float-converted data causes a type mismatch. The hardware expects pure bit-pattern integers, but it receives floating-point registers. As a result, the shader reads undefined values, zeroes, or corrupted IDs.

Why glVertexAttribIPointer Must Be Used

The OpenGL specification introduced glVertexAttribIPointer (with the I standing for "Integer") specifically to bind integer buffer data to integer shader attributes without intermediate floating-point conversions.

// Correct configuration for an 'in ivec4 boneIDs' shader attribute
glVertexAttribIPointer(index, 4, GL_INT, stride, pointer);

Notice that glVertexAttribIPointer does not contain a normalized parameter. This omission is intentional: integer vertex attributes are never normalized. Instead, the function preserves raw integer binary data throughout the input assembly stage:

  • Type Consistency: It explicitly informs the driver that both the buffer source and the destination GLSL attribute are integers.
  • Bit Preservation: Byte, short, and integer data types (GL_BYTE, GL_UNSIGNED_BYTE, GL_SHORT, GL_UNSIGNED_SHORT, GL_INT, GL_UNSIGNED_INT) are sign-extended or zero-extended directly into 32-bit integer shader registers without touching floating-point execution units.
  • Correct Indexing: Integer lookups, such as array indices and bitwise operators (&, |, ^), function as expected inside the shader without rounding errors or precision loss.

Summary of Pointer Functions

To ensure data reaches shaders correctly, choose the attribute configuration function that matches the GLSL input declaration:

  • Use glVertexAttribPointer for attributes declared as floating-point types (float, vec2, vec3, vec4), even if the underlying buffer data uses packed integer formats intended for normalization or float conversion.
  • Use glVertexAttribIPointer strictly for attributes declared as integer types (int, ivec*, uint, uvec*).
  • Use glVertexAttribLPointer for attributes declared as 64-bit double-precision types (double, dvec*).
