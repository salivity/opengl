Reconstruct World Coordinates from Depth in OpenGL

Reconstructing 3D world coordinates directly from depth buffer values is a fundamental optimization in modern computer graphics pipelines, particularly in deferred shading and post-processing effects. Instead of storing explicit geometry or position buffers, developers can derive the original world-space position of any fragment using only its 2D screen coordinates, its sampled non-linear depth value, and the inverse of the camera's view-projection matrix. This article explains the underlying mathematics and provides a concise GLSL implementation to perform this transformation accurately.

The Coordinate Pipeline in Reverse

During standard rendering, a vertex travels from world space to screen space through a sequence of matrix multiplications:

\[\text{World Space} \xrightarrow{\text{View Matrix}} \text{View Space} \xrightarrow{\text{Projection Matrix}} \text{Clip Space} \xrightarrow{\text{Perspective Divide}} \text{NDC} \xrightarrow{\text{Viewport Transform}} \text{Screen Space}\]

To retrieve the original world coordinates, this pipeline must be run entirely in reverse:

  1. Convert screen-space pixel coordinates and the depth sample into Normalized Device Coordinates (NDC).
  2. Multiply the NDC position by the inverse view-projection matrix (\((\mathbf{P} \cdot \mathbf{V})^{-1}\)) to return to homogeneous clip space.
  3. Perform perspective division by dividing the resulting vector by its \(W\) component to obtain Euclidean world-space coordinates.

Step 1: Mapping Screen Space to NDC

In OpenGL, screen coordinates typically map to Normalized Device Coordinates in the range \([-1, 1]\) across all three axes (\(X, Y, Z\)).

A depth texture sampled via standard samplers returns a value \(d \in [0, 1]\). In OpenGL's default clip space, depth spans from \(-1.0\) (near plane) to \(1.0\) (far plane). Therefore, the coordinates must be remapped:

  • \(X_{ndc} = UV.x \times 2.0 - 1.0\)
  • \(Y_{ndc} = UV.y \times 2.0 - 1.0\)
  • \(Z_{ndc} = \text{depth} \times 2.0 - 1.0\)

This yields the complete homogeneous coordinate in NDC:

\[\mathbf{P}_{ndc} = \begin{bmatrix} X_{ndc} \\ Y_{ndc} \\ Z_{ndc} \\ 1.0 \end{bmatrix}\]

Step 2: Inverse Matrix Multiplication

Combine the camera's view matrix (\(\mathbf{V}\)) and projection matrix (\(\mathbf{P}\)) on the CPU, invert the combined matrix, and pass it to the shader as a uniform:

\[\mathbf{M}_{inv} = (\mathbf{P} \cdot \mathbf{V})^{-1}\]

Multiplying \(\mathbf{M}_{inv}\) by \(\mathbf{P}_{ndc}\) transforms the point back into homogeneous world space (\(\mathbf{P}_{clip\_world}\)):

\[\mathbf{P}_{clip\_world} = \mathbf{M}_{inv} \cdot \mathbf{P}_{ndc}\]

Step 3: Perspective Division

Because the projection step applies a perspective warp encoded in the \(W\) component, the unprojected vector is still scaled by \(W\). To recover the exact Cartesian world coordinates \((X, Y, Z)\), divide the vector by its \(W\) component:

\[\mathbf{P}_{world} = \frac{\mathbf{P}_{clip\_world}.xyz}{\mathbf{P}_{clip\_world}.w}\]

GLSL Implementation

Below is a complete GLSL function that extracts the world-space coordinate from a depth texture sample and screen-space UV coordinates:

#version 330 core

uniform sampler2D uDepthTexture;
uniform mat4 uInverseViewProjection;

in vec2 vTexCoord; // Screen-space UVs in [0, 1]
out vec4 FragColor;

vec3 getWorldPositionFromDepth(vec2 uv, float depthSample) {
    // Step 1: Map [0, 1] range to [-1, 1] NDC
    vec4 clipSpacePosition = vec4(uv * 2.0 - 1.0, depthSample * 2.0 - 1.0, 1.0);

    // Step 2: Multiply by inverse view-projection matrix
    vec4 worldSpacePosition = uInverseViewProjection * clipSpacePosition;

    // Step 3: Perspective divide
    return worldSpacePosition.xyz / worldSpacePosition.w;
}

void main() {
    float depth = texture(uDepthTexture, vTexCoord).r;

    // Discard background fragments at the far plane if necessary
    if (depth >= 1.0) {
        discard;
    }

    vec3 worldPos = getWorldPositionFromDepth(vTexCoord, depth);

    // Example: Output reconstructed world position directly
    FragColor = vec4(worldPos, 1.0);
}

Key Technical Considerations

  • Matrix Precision: Computing \((\mathbf{P} \cdot \mathbf{V})^{-1}\) on the CPU using 64-bit double-precision floats before casting to 32-bit floats for the shader uniform helps reduce precision artifacts, particularly in scenes with expansive view distances.
  • Coordinate Conventions: If targeting APIs or modern OpenGL extensions that use a zero-to-one clip control (glClipControl with GL_ZERO_TO_ONE), do not remap \(Z\) to \([-1, 1]\). Use \(Z_{ndc} = \text{depth}\) directly.
  • View-Space Reconstruction: If calculations only require view-space positions (such as standard deferred lighting calculations), pass the inverse projection matrix (\(\mathbf{P}^{-1}\)) alone instead of the combined inverse view-projection matrix.
