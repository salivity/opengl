Depth-Based Ocean FFT Simulation in OpenGL

Simulating realistic ocean surfaces that react accurately to varying seabed topography requires extending classical statistical ocean models into depth-dependent regimes. This article explores the mathematical frameworks and algorithms that implement depth-based Fast Fourier Transform (FFT) ocean wave simulations using OpenGL compute shaders. It covers finite-depth dispersion modifications, shallow-water wave spectra such as TMA, computational strategies for handling spatially varying bathymetry, and practical GPU pipeline implementations.

The Finite-Depth Dispersion Relation

Standard ocean simulations based on Jerry Tessendorf’s formulation assume infinite water depth (deep water), where the dispersion relation simplifies to:

\[\omega^2(k) = gk\]

Where \(g\) is the acceleration due to gravity, \(k = \|\mathbf{k}\|\) is the wavenumber, and \(\omega\) is the angular frequency.

To simulate waves interacting with the seabed, the deep-water model must be replaced with the finite-depth dispersion relation from linear Airy wave theory:

\[\omega^2(k, h) = gk \tanh(kh)\]

Where \(h\) represents the local water depth. As water depth \(h \to \infty\), \(\tanh(kh) \to 1\), naturally degenerating into the deep-water model. As water becomes shallow (\(kh < \pi/10\)), \(\tanh(kh) \approx kh\), simplifying wave speed directly to \(c = \sqrt{gh}\), leading to wave deceleration, wavelength compression (shoaling), and refraction.

Depth-Limited Wave Spectra: The TMA Spectrum

While the Phillips or Pierson-Moskowitz spectra model deep-water seas, the Texel-MARSEN-ARSLOE (TMA) spectrum explicitly accounts for depth-limited energy dissipation.

The TMA spectrum modifies the JONSWAP spectrum \(S_J(\omega)\) by multiplying it with a depth-attenuation factor \(\Phi_{KMA}(\omega_h)\):

\[S_{TMA}(\omega, h) = S_J(\omega) \cdot \Phi_{KMA}(\omega_h)\]

Where \(\omega_h = \omega \sqrt{h / g}\), and \(\Phi_{KMA}\) is approximated by:

\[\Phi_{KMA}(\omega_h) \approx \begin{cases} 0.5 \omega_h^2 & \text{for } \omega_h \le 1 \\ 1 - 0.5 (2 - \omega_h)^2 & \text{for } 1 < \omega_h < 2 \\ 1 & \text{for } \omega_h \ge 2 \end{cases}\]

Using the TMA spectrum dynamically restricts wave amplitudes in shallow regions, preventing non-physical tall waves from persisting near the shoreline.

Handling Spatially Varying Depth with FFT

The core limitation of the classical 2D Inverse FFT (IFFT) is that it computes a global transform over a uniform grid, requiring depth \(h\) to be spatially constant. Modern OpenGL implementations resolve this using one of three architectural approaches:

1. Depth-Slab Blending (Multi-Grid FFT)

The simulation executes multiple simultaneous IFFTs across discrete depth tiers (e.g., \(h \in \{2\text{m}, 10\text{m}, 50\text{m}, \infty\}\)) within the same OpenGL compute pass.

  • A bathymetry texture maps local depth \(h(x, y)\) per vertex or fragment.
  • The GPU samples the two nearest depth displacement textures and linearly interpolates displacement and normal vectors based on the local depth.

2. Phase-Distorted Spatial Modulation

Instead of executing multiple transforms, a single deep-water or intermediate-depth IFFT produces global displacement vectors. A subsequent compute pass applies local phase and amplitude corrections directly derived from bathymetry:

  • Waves are compressed along the gradient of the seabed: \(\nabla h(x, y)\).
  • Horizontal displacement vectors are magnified using the shallow-water choppy wave term \(\coth(kh)\), steepening wave crests prior to breaking.

3. Hybrid FFT-Shallow Water Equation (SWE) Coupling

For high-fidelity shorelines, FFT simulations run exclusively for deep regions and are coupled dynamically to a 2D Eulerian Shallow Water Equation solver running on an OpenGL compute grid near the shore. The FFT outputs provide the boundary Dirichlet conditions driving the SWE domain.

OpenGL Implementation Pipeline

An efficient depth-based FFT simulation uses OpenGL 4.3+ Compute Shaders and Shader Storage Buffer Objects (SSBOs) using the following algorithmic passes:

  1. Spectrum Generation (Compute Shader): Generate initial complex frequency amplitudes \(h_0(\mathbf{k})\) using Gaussian random numbers and the TMA spectrum, accounting for a baseline depth.
  2. Time Evolution (Compute Shader): Update the spectrum at time \(t\): \[h(\mathbf{k}, t) = h_0(\mathbf{k})e^{i\omega(k, h)t} + h_0^*(-\mathbf{k})e^{-i\omega(k, h)t}\] Simultaneously evaluate the horizontal choppy components: \[\mathbf{D}(\mathbf{k}, t) = -i \frac{\mathbf{k}}{k} \coth(kh) h(\mathbf{k}, t)\]
  3. Row/Column IFFT (Compute Shader): Execute the Radix-2 or Stockham formulation of the Cooley-Tukey algorithm. Compute shaders utilize shared memory (shared vec2 tile[...]) and barrier() calls to perform horizontal and vertical 1D IFFTs entirely in on-chip cache without global memory roundtrips.
  4. Displacement Assembly and Normal Mapping (Compute Shader): Combine the vertical and horizontal outputs into a single floating-point displacement texture (GL_RGBA32F). A Sobel filter or cross-product pass computes screen-space normals, folding in Jacobian evaluation to compute foam masks where \(\det(J) < 0\).
  5. Surface Rendering (Vertex/Fragment Shaders): Tessellate a projected grid, sample the combined displacement and bathymetry textures, and shade using Fresnel transmission, subsurface scattering, and foam modulation.
