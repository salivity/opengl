Dual Quaternion Skinning in OpenGL Shaders

Dual quaternion skinning (DQS) is an advanced skeletal animation technique designed to eliminate the unnatural volume-loss artifacts—often referred to as the "candy-wrapper" effect—inherent in standard Linear Blend Skinning (LBS). This article provides a comprehensive breakdown of the mathematics behind dual quaternions and explains how to implement and evaluate dual quaternion skinning directly inside an OpenGL vertex shader using GLSL.

Understanding Dual Quaternion Skinning

In traditional skeletal animation, Linear Blend Skinning interpolates standard \(4 \times 4\) transformation matrices using vertex bone weights. Because linear matrix interpolation does not inherently preserve orthogonality, severe twisting or bending causes the mesh to collapse inward.

Dual quaternions resolve this by representing rigid spatial transformations (rotation and translation) as a single mathematical entity. A dual number has the form \(a + \varepsilon b\), where \(\varepsilon\) is the dual unit satisfying \(\varepsilon^2 = 0\). Extending this to quaternions yields a dual quaternion \(\hat{q}\):

\[\hat{q} = q_r + \varepsilon q_d\]

  • Real part (\(q_r\)): A unit quaternion representing 3D rotation.
  • Dual part (\(q_d\)): A quaternion encoding translation \(t = (t_x, t_y, t_z)\), defined as \(q_d = \frac{1}{2} t q_r\), where \(t\) is treated as a pure quaternion \((0, t_x, t_y, t_z)\).

By linearly blending dual quaternions (Dual quaternion Linear Blending, or DLB) and normalizing the result, the transformation retains its rigid structure, preserving vertex volume across joint limits without computationally expensive matrix polar decompositions.

Data Representation for the Vertex Shader

To pass dual quaternions to an OpenGL vertex shader, each bone's transform is packaged into two 4-component vectors: one for \(q_r\) and one for \(q_d\). This is typically submitted using a uniform buffer object (UBO) or uniform array of type mat2x4 or paired vec4 arrays:

// Uniform block holding bone dual quaternions
layout(std140, binding = 0) uniform BoneData {
    mat2x4 bones[128]; // [0] = real part (rotation), [1] = dual part (translation)
};

Standard vertex attributes are required per vertex:

  • in vec3 inPosition;
  • in vec3 inNormal;
  • in uvec4 inBoneIndices;
  • in vec4 inBoneWeights;

Processing Inside the GLSL Vertex Shader

Computing skinning inside the vertex shader involves three core operations: handling antipodality during blending, normalizing the blended dual quaternion, and transforming the vertex position and normal.

1. Handling Antipodal Alignment

Quaternions \(q\) and \(-q\) define identical 3D rotations, but interpolating between opposite signs cancels them out rather than blending them. Before accumulating influences, the shader checks the dot product of the current bone's real quaternion against the primary bone's real quaternion. If the dot product is negative, the sign of the dual quaternion is inverted.

2. Dual Quaternion Blending (DLB)

The bone transforms are linearly combined according to their normalized weights:

mat2x4 blendDualQuat(uvec4 indices, vec4 weights) {
    mat2x4 dq0 = bones[indices[0]];
    mat2x4 blended = dq0 * weights[0];

    for (int i = 1; i < 4; ++i) {
        mat2x4 dqi = bones[indices[i]];
        // Antipodal handling: flip sign if orientation differs
        float sign = dot(dq0[0], dqi[0]) < 0.0 ? -1.0 : 1.0;
        blended += dqi * (weights[i] * sign);
    }

    return blended;
}

3. Normalization and Position Transformation

After summing, the accumulated dual quaternion must be normalized. The magnitude of the blended dual quaternion is determined exclusively by the magnitude of its real component:

\[s = \frac{1}{\|q_r\|}\] \[\hat{q}_{\text{norm}} = (s \cdot q_r) + \varepsilon (s \cdot q_d)\]

Once normalized, the vertex position \(v\) can be transformed directly using vector algebra instead of converting back to a \(4 \times 4\) matrix:

\[v' = v + 2 q_r \times (q_r \times v + q_d.xyz) + 2 (q_r.w \cdot q_d.xyz - q_d.w \cdot q_r.xyz)\]

Complete GLSL Vertex Transformation Example

#version 450 core

layout(location = 0) in vec3 inPosition;
layout(location = 1) in vec3 inNormal;
layout(location = 2) in uvec4 inBoneIndices;
layout(location = 3) in vec4 inBoneWeights;

layout(std140, binding = 0) uniform BoneData {
    mat2x4 bones[128];
};

uniform mat4 uViewProjection;

out vec3 fragNormal;

void main() {
    // 1. Blend influences
    mat2x4 dq0 = bones[inBoneIndices[0]];
    mat2x4 blended = dq0 * inBoneWeights[0];

    for (int i = 1; i < 4; ++i) {
        mat2x4 dqi = bones[inBoneIndices[i]];
        float sign = dot(dq0[0], dqi[0]) < 0.0 ? -1.0 : 1.0;
        blended += dqi * (inBoneWeights[i] * sign);
    }

    // 2. Normalize dual quaternion
    float invLen = 1.0 / length(blended[0]);
    vec4 qr = blended[0] * invLen;
    vec4 qd = blended[1] * invLen;

    // 3. Transform vertex position
    vec3 position = inPosition + 2.0 * cross(qr.xyz, cross(qr.xyz, inPosition) + qr.w * inPosition);
    vec3 translation = 2.0 * (qr.w * qd.xyz - qd.w * qr.xyz + cross(qr.xyz, qd.xyz));
    vec3 skinnedPosition = position + translation;

    // 4. Transform vertex normal (pure rotation by real part)
    fragNormal = inNormal + 2.0 * cross(qr.xyz, cross(qr.xyz, inNormal) + qr.w * inNormal);

    gl_Position = uViewProjection * vec4(skinnedPosition, 1.0);
}

Performance and Precision Considerations

Dual quaternion skinning requires less uniform storage than matrix skinning (8 floats per bone instead of 16 for a \(4 \times 4\) or 12 for an affine \(4 \times 3\) matrix), substantially reducing GPU bandwidth and uniform buffer footprints. While the vertex shader executes slightly more algebraic operations to apply the transformation directly, the savings in memory bus traffic and the elimination of rotational collapse make DQS a standard solution for modern real-time skeletal pipelines.
