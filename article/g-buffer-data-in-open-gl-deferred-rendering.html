G-Buffer Data in OpenGL Deferred Rendering

In OpenGL deferred rendering, the geometry pass decouples geometry processing from lighting calculations by rendering scene attributes to an off-screen collection of textures known as the Geometry Buffer (G-Buffer). This article breaks down the standard data components typically written to Multiple Render Targets (MRTs) during this initial pass, explaining the specific attributes stored, their common internal formats, and how they are packaged to optimize GPU memory and bandwidth.

1. Surface Position (or Depth)

To calculate light attenuation and view-dependent reflections, the lighting pass requires spatial coordinates for every pixel.

  • World-Space or View-Space Coordinates: Stored using a high-precision floating-point format, typically GL_RGB16F or GL_RGB32F.
  • Depth Optimization: Instead of storing explicit \((x, y, z)\) position vectors, modern pipelines often omit the position texture entirely. Instead, they use the standard hardware depth buffer (GL_DEPTH_COMPONENT24 or GL_DEPTH_COMPONENT32F) to reconstruct world-space or view-space positions mathematically using the screen coordinates, the depth value, and the inverse projection/view matrix. This significantly reduces memory bandwidth.

2. Surface Normals

Lighting models rely on surface normals to compute diffuse (Lambertian) and specular components.

  • Normal Vectors \((x, y, z)\): Mapped from the \([-1.0, 1.0]\) range to texture space. Floating-point formats such as GL_RGB16F provide sufficient precision without quantization artifacts.
  • Encoding Techniques: Normals can be compressed into two components (e.g., spherical coordinates or octahedron encoding) and stored in formats like GL_RG16F. The third component (\(z\)) is reconstructed in the lighting fragment shader.

3. Albedo (Base Color)

The albedo buffer holds the unlit, intrinsic color of the surface.

  • Format: Typically GL_RGBA8 or GL_SRGB8_ALPHA8 if working in linear color space.
  • Channels: The RGB channels store the diffuse color (in traditional Phong/Blinn-Phong) or the base color (in physically based rendering / PBR). The alpha channel is commonly repurposed to store scalar values like specular intensity or a material ID.

4. Material and PBR Attributes

For physically based shading pipelines, surfaces require parameters that dictate how light scatters and reflects. These scalar values are commonly packed into a single four-channel GL_RGBA8 texture:

  • Roughness / Perceptual Roughness: Determines surface microfacet distribution (sharpness of specular reflections).
  • Metalness / Metallic: Distinguishes between dielectric (non-metal) and conductive (metal) surfaces.
  • Ambient Occlusion (AO): Pre-baked micro-occlusion details mapped across the mesh.
  • Cavity or Specular Tint: Additional data controlling localized reflectance.

5. Emission

Objects that produce light, such as neon signs or glowing elements, store their color in an emissive buffer.

  • Format: Usually GL_RGB16F to support High Dynamic Range (HDR) values greater than \(1.0\), which are often combined with post-processing effects like bloom.
  • Packing: If dynamic range requirements are low, emission can be packed into unused channels of other textures or conditionally rendered in a separate pass.

Standard OpenGL G-Buffer Attachment Example

A balanced OpenGL G-Buffer layout balancing quality and bandwidth consumption typically utilizes four attachments bound to a single Framebuffer Object (FBO):

  1. GL_COLOR_ATTACHMENT0 (GL_RGBA8): RGB = Albedo, A = Ambient Occlusion
  2. GL_COLOR_ATTACHMENT1 (GL_RGB16F): RGB = Surface Normals
  3. GL_COLOR_ATTACHMENT2 (GL_RGBA8): R = Metallic, G = Roughness, B = Material/Model ID, A = Unused
  4. GL_DEPTH_ATTACHMENT (GL_DEPTH_COMPONENT24): Hardware Depth (used for both depth testing and world-position reconstruction)
