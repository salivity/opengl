Gamma Correction and Texture Sampling in OpenGL

Gamma correction in OpenGL is critical for achieving physically accurate lighting, correct color blending, and consistent visual output. Standard digital images and consumer monitors operate in a non-linear, gamma-encoded color space (typically sRGB) to compensate for human perception, whereas computer graphics calculations require a linear color space to be mathematically correct. Without proper gamma management, an OpenGL rendering pipeline will perform calculations on distorted color values, resulting in harsh light falloff, incorrect color bleeding, dark halo artifacts around blended edges, and an overall unnatural image.

The Non-Linear Problem in Rendering

Monitors natively display colors using a power curve—traditionally approximated by a gamma value of 2.2—which darkens linear input values. To make efficient use of limited bit depth (such as standard 8-bit per channel formats), digital images and authored textures are pre-curved into sRGB space.

When a fragment shader calculates physics-based lighting, such as Lambertian diffuse or Cook-Torrance specular models, it assumes that an input value of 0.5 represents half the physical photons of 1.0. However, in an uncorrected pipeline, sampling an sRGB texture directly returns non-linear data. Performing linear operations (multiplication, addition) on non-linear inputs skews the mathematical foundation of the entire pipeline, leading to disproportionately rapid light decay and overly dark mid-tones.

Texture Sampling with Hardware sRGB Formats

To ensure texture sampling accuracy, color data must be converted from sRGB to linear space before the shader performs any calculations. While this conversion can be done manually within GLSL using the approximation pow(color, 2.2), doing so incurs a significant performance overhead and complicates shader code.

OpenGL resolves this through hardware-accelerated sRGB textures. When creating texture storage with functions like glTexImage2D or glTexStorage2D, specifying internal formats such as GL_SRGB8 or GL_SRGB8_ALPHA8 signals the GPU that the image data is stored in the sRGB color space. When the fragment shader samples this texture, the hardware automatically decodes the RGB components into linear space on the fly, with zero performance cost. The alpha channel remains strictly linear and is left uncorrected.

It is important to apply sRGB formats selectively:

  • Color textures (albedo, diffuse maps) contain human-authored color data and must use GL_SRGB formats.
  • Data textures (normal maps, roughness, metallic, height, and ambient occlusion) store mathematical vectors or scalar values, not color. These must remain in linear formats like GL_RGB8 or GL_R8 to prevent corruption of the underlying data.

Linear Pipeline and Alpha Blending

Once textures are correctly converted to linear space, the fragment shader computes all lighting, shadowing, and post-processing accurately. However, rendering pipeline accuracy also extends to alpha blending.

When translucent surfaces overlap, OpenGL blends the destination and source fragments. If blending occurs in a non-linear color space, the calculated intermediate values produce dark, dirty borders along transparent edges. A fully gamma-correct pipeline maintains linear values in the framebuffer, ensuring that additive and alpha-based blending accurately simulate physical light transmission.

Outputting to the Framebuffer

After the fragment shader produces a linear color result, that value must be converted back to non-linear sRGB space before it is sent to a standard display, canceling out the monitor's native gamma curve.

OpenGL provides a dedicated mechanism for this step via glEnable(GL_FRAMEBUFFER_SRGB). When enabled, if the currently bound framebuffer is sRGB-capable (such as a default framebuffer created with an sRGB pixel format, or a custom framebuffer with a GL_SRGB8_ALPHA8 texture attached), the GPU automatically applies the linear-to-sRGB transfer function right before writing pixels to memory. If the target is a standard linear framebuffer (such as an HDR floating-point format like GL_RGBA16F), the conversion is bypassed, allowing intermediate rendering passes to remain completely linear.
