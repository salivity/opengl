GLSL layout(depth_unchanged) Depth Optimization

The layout(depth_unchanged) qualifier in GLSL tells the GPU driver that a fragment shader writing to gl_FragDepth will not alter the hardware-interpolated depth value. By guaranteeing this invariant, the OpenGL pipeline can keep hardware-level Early Depth Testing (Early-Z) and Hierarchical-Z (Hi-Z) culling enabled. This prevents the rasterizer from de-optimizing the render pass, ensuring that occluded fragments are discarded before computationally expensive fragment shaders ever execute.

The Problem: Fragment Depth Writes Disable Early-Z

Under standard rendering pipelines, modern GPUs execute Early Depth Testing before fragment shading. If a fragment is hidden behind existing geometry, the hardware discards it immediately, saving significant GPU cycles, memory bandwidth, and execution resources.

However, if a fragment shader explicitly writes to the built-in variable gl_FragDepth, the rasterizer faces an ambiguity: it cannot determine the fragment's final depth value prior to executing the shader code. Consequently, the GPU must disable Early-Z and defer depth testing until after the fragment shader finishes (Late-Z testing). This causes hidden, fully occluded fragments to run their entire shader workload before ultimately being rejected by the depth buffer.

How layout(depth_unchanged) Restores Optimization

The depth_unchanged qualifier—part of the conservative depth extension integrated into core OpenGL—resolves this stall. It is declared in the fragment shader as follows:

layout (depth_unchanged) out float gl_FragDepth;

This declaration guarantees to the compiler and rasterizer that any write to gl_FragDepth inside the shader will evaluate strictly to the original, fixed-function interpolated depth coordinate (gl_FragCoord.z).

Because the pipeline knows in advance that the depth buffer value remains predictable, the hardware can perform several critical optimizations:

  • Early-Z Execution: The rasterizer safely tests fragments against the depth buffer before dispatching warps or wavefronts to execution units, immediately discarding occluded pixels.
  • Hierarchical-Z (Hi-Z) Preservation: The GPU retains low-resolution, tile-based depth representations that discard entire screen-space blocks of pixels at the coarse raster stage. Without this qualifier, coarse rejection is largely compromised when depth writes are present.
  • Double-Sided Depth Testing: Certain architectures run both Early-Z (to kill occluded pixels) and Late-Z (to write or confirm depth). Declaring the depth unchanged allows the hardware to completely bypass the late validation stage.

Common Use Cases

While writing an unchanged depth may seem redundant, layout(depth_unchanged) is valuable in scenarios such as:

  • Conditional Discards with Depth Access: Shaders that read or assign depth based on control flow without altering the final value.
  • Uber-Shaders and Modular Codebases: Fragment shaders designed to output custom depth only in specific configurations or branches, allowing branches that maintain default depth to retain hardware acceleration without requiring a separate shader program.
  • Side-Effect Pipelines: Passes that utilize depth values for image-space operations or atomic storage counters while still maintaining traditional depth-buffer sorting behavior.
