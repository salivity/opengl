OpenGL Framebuffer Blit Scaling Constraints

In OpenGL, copying and resizing pixel regions between framebuffers is performed using the glBlitFramebuffer command. While this function provides an efficient way to transfer and scale image data, several strict constraints dictate when and how scaling can be performed. These limitations involve sample counts, supported filtering methods, buffer attachments, and pixel format types.

Multisampling Restrictions

The most rigid constraint on scaling involves multisample anti-aliasing (MSAA). If either the source framebuffer or the destination framebuffer has a sample count greater than zero (GL_SAMPLES > 0):

  • No Scaling Permitted: The dimensions of the source rectangle must precisely match the dimensions of the destination rectangle. That is, |srcX2 - srcX1| must equal |dstX2 - dstX1|, and |srcY2 - srcY1| must equal |dstY2 - dstY1|.
  • Resolution Resolution: To scale a multisampled surface, you must first resolve the multisampled buffer to an intermediate single-sampled framebuffer without scaling, and subsequently blit and scale from that intermediate framebuffer to the final destination.

Attempting to scale while either buffer is multisampled triggers a GL_INVALID_OPERATION error.

Filtering Mode Limitations

When scaling pixel data, glBlitFramebuffer accepts either GL_NEAREST or GL_LINEAR as the interpolation filter parameter. Several restrictions apply to the choice of filter:

  • Depth and Stencil Buffers: Scaling depth or stencil data using GL_LINEAR is strictly prohibited. If GL_DEPTH_BUFFER_BIT or GL_STENCIL_BUFFER_BIT is present in the buffer mask, the filter must be GL_NEAREST. Passing GL_LINEAR generates a GL_INVALID_OPERATION.
  • Integer Formats: Color buffers backed by signed or unsigned integer internal formats (such as GL_RGBA32UI or GL_R16I) do not support linear interpolation. Blitting these formats requires GL_NEAREST.
  • Float and Normalized Formats: Standard normalized fixed-point and floating-point color formats support both GL_NEAREST and GL_LINEAR scaling.

Attachment and Format Constraints

The presence and compatibility of target attachments introduce additional rules:

  • Combined Blits: If scaling both a color buffer and a depth/stencil buffer in a single glBlitFramebuffer call, you are forced to use GL_NEAREST because depth/stencil cannot accept GL_LINEAR. To achieve bilinear filtering on color while copying depth, you must separate the operation into two distinct blit calls.
  • Format Conversion: While color attachments can often convert between compatible internal formats during a scale operation, depth and stencil formats generally require matching internal precision across the source and destination to ensure valid output.

Coordinate Mapping and Scissoring

  • Image Flipping: OpenGL allows source and destination coordinates to be reversed (for example, srcX1 > srcX2) to invert an axis while scaling. While permissible, standard boundary clipping applies to both axes.
  • Scissor Box Constraints: The scissor test applies to the destination framebuffer during a blit. If GL_SCISSOR_TEST is enabled, destination pixels outside the specified scissor rectangle are discarded, while pixels within the scissor box are scaled according to the full coordinate ratios specified in the function call.
