Spotlight Angles Using Dot Product in OpenGL Shaders

This article explains how spotlight illumination is calculated in an OpenGL fragment shader using vector mathematics. By computing the dot product between the spotlight's orientation vector and the vector pointing toward the surface fragment, shaders determine whether a fragment falls within the spotlight’s cone of influence. You will learn the underlying vector geometry, how to optimize the calculation by working entirely in cosine space, and how to implement both hard and soft spotlight edges in GLSL.

Vector Geometry of a Spotlight

A standard spotlight requires three primary spatial vectors to determine illumination:

  1. Light Position (lightPos): The world- or view-space origin of the spotlight.
  2. Spot Direction (spotDir): A normalized vector defining the central direction the spotlight is pointing.
  3. Fragment Vector (lightToFrag): The normalized vector from the spotlight position to the fragment position (normalize(fragPos - lightPos)). Alternatively, shaders often use the direction from the fragment to the light (fragToLight), reversing the spotlight direction vector accordingly.

Evaluating Angles with the Dot Product

Computing raw angular differences in radians or degrees using inverse trigonometric functions like acos() is computationally expensive for GPUs. Instead, OpenGL shaders evaluate spotlight angles using the geometric definition of the dot product:

\[\mathbf{A} \cdot \mathbf{B} = \|\mathbf{A}\| \|\mathbf{B}\| \cos(\theta)\]

When both vectors \(\mathbf{A}\) and \(\mathbf{B}\) are normalized to unit length (\(\|\mathbf{A}\| = 1\) and \(\|\mathbf{B}\| = 1\)), their dot product simplifies directly to the cosine of the angle between them:

\[\cos(\theta) = \mathbf{A} \cdot \mathbf{B}\]

In a shader, taking the dot product of the normalized vector pointing from the light to the fragment and the normalized spotlight direction yields the cosine of the angle between the center of the beam and the fragment:

vec3 lightDir = normalize(fragPos - light.position);
float currentCos = dot(lightDir, normalize(light.direction));

The Cosine Threshold Comparison

The spotlight’s field of view is defined by a cutoff angle (\(\phi\)). Because the cosine function decreases monotonically from \(1.0\) at \(0^\circ\) to \(0.0\) at \(90^\circ\), a smaller angle results in a larger cosine value.

To determine if a surface point is illuminated:

  • Calculate \(\cos(\phi)\) on the CPU once and pass it to the shader as a uniform (cutoff).
  • Compare currentCos against cutoff.
  • If currentCos > cutoff, the angle is smaller than the cutoff threshold, meaning the fragment is inside the spotlight cone.

Soft Edges and Attenuation

Hard cutoffs create abrupt, pixelated circular borders. To create realistic, soft edges, define two angles: an inner cutoff (\(\phi_{inner}\)) and an outer cutoff (\(\phi_{outer}\)).

The shader interpolates intensity across the transition zone using the cosine values:

\[I = \frac{\cos(\theta) - \cos(\phi_{outer})}{\cos(\phi_{inner}) - \cos(\phi_{outer})}\]

In GLSL, this can be written using clamp() or smoothstep():

float epsilon = light.innerCutoff - light.outerCutoff;
float intensity = clamp((currentCos - light.outerCutoff) / epsilon, 0.0, 1.0);

Because \(\phi_{inner} < \phi_{outer}\), the cosine uniform values satisfy innerCutoff > outerCutoff, ensuring a positive gradient from the edge of the beam to its bright center.

Complete GLSL Fragment Shader Implementation

Below is a focused GLSL snippet demonstrating the spotlight calculation:

#version 330 core
out vec4 FragColor;

in vec3 FragPos;
in vec3 Normal;

struct Spotlight {
    vec3 position;
    vec3 direction;     // Normalized direction vector
    float innerCutoff;   // cos(innerAngle)
    float outerCutoff;   // cos(outerAngle)
    
    vec3 color;
};

uniform Spotlight light;

void main()
{
    // Compute direction from light to the fragment
    vec3 lightToFrag = normalize(FragPos - light.position);
    
    // Evaluate cosine of the angle using the dot product
    float currentCos = dot(lightToFrag, normalize(light.direction));
    
    // Determine soft-edge intensity
    float epsilon = light.innerCutoff - light.outerCutoff;
    float intensity = clamp((currentCos - light.outerCutoff) / epsilon, 0.0, 1.0);
    
    // Apply intensity to final fragment color
    vec3 result = light.color * intensity;
    FragColor = vec4(result, 1.0);
}

This method avoids inverse trigonometric overhead entirely, keeping the fragment evaluation down to basic vector subtraction, normalization, a single dot product, and a multiply-add operation.
