OpenGL Transform Feedback Queries and Vertex Counts

This article explores how transform feedback queries bridge the gap between GPU-driven geometry operations and the CPU in OpenGL. It details the mechanics of capturing primitives generated in vertex and geometry pipelines, explains how query objects record these metrics, and demonstrates how CPU processes retrieve accurate vertex counts to manage memory, drive logic, and optimize future rendering passes.

The Role of Transform Feedback

Transform feedback is an OpenGL mechanism that captures primitives processed by the vertex, tessellation, or geometry shader stages and writes them directly into one or more buffer objects before rasterization occurs. This pipeline feature enables the GPU to perform physics simulations, particle updates, or procedural mesh generation without routing the data back through the CPU.

Because geometry shaders can cull or amplify geometry dynamically, the final number of generated vertices often cannot be predicted prior to execution. If a buffer overflows or if subsequent pipeline stages require an exact count of the output data, the application needs a reliable way to determine precisely how many elements were generated.

Understanding Transform Feedback Queries

Transform feedback queries are specialized asynchronous performance and diagnostic tools used to count the number of primitives that pass through the transform feedback pipeline. They rely on OpenGL's standard query object infrastructure, created via glGenQueries and operated using glBeginQuery and glEndQuery.

Two primary query targets manage these metrics:

  • GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN: Counts the number of primitives that were successfully written to the bound transform feedback buffer objects. If a buffer runs out of space, writing ceases, and this counter stops incrementing.
  • GL_PRIMITIVES_SUBMITTED: Counts the total number of primitives sent to the transform feedback stage, regardless of whether there was sufficient buffer space to store them.

Comparing the values from both query targets allows developers to detect buffer overflow conditions.

How Queries Inform the CPU of Vertex Counts

The CPU cannot directly inspect GPU operations in real time without causing pipeline stalls. Transform feedback queries provide a structured, asynchronous bridge to deliver vertex metrics to the host application through a defined lifecycle.

1. Query Activation and Primitive Generation

The query must enclose the transform feedback rendering call:

GLuint query;
glGenQueries(1, &query);

glBeginQuery(GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, query);
glBeginTransformFeedback(GL_TRIANGLES);

// Issue rendering commands (e.g., glDrawArrays, glDrawElements)
glDrawArrays(GL_TRIANGLES, 0, vertexCount);

glEndTransformFeedback();
glEndQuery(GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN);

During this sequence, the GPU hardware counter increments for every primitive emitted and written to the destination buffer.

2. Querying Availability

Because the GPU executes asynchronously, the counter's final value is not instantly available when glEndQuery returns. The CPU can poll the status of the query to prevent CPU-GPU synchronization stalls:

GLuint available = 0;
glGetQueryObjectuiv(query, GL_QUERY_RESULT_AVAILABLE, &available);

if (available) {
    // Result is ready to be fetched without blocking the CPU
}

3. Retrieving the Result

Once execution completes on the GPU, the CPU retrieves the primitive count using glGetQueryObjectuiv or glGetQueryObjectui64v:

GLuint primitivesWritten = 0;
glGetQueryObjectuiv(query, GL_QUERY_RESULT, &primitivesWritten);

Requesting GL_QUERY_RESULT before the GPU has finished processing will force the CPU to wait until the pipeline drains, introducing latency. To maintain high frame rates, applications typically read the query results one or more frames after the query was executed.

4. Deriving the Vertex Count

The retrieved value represents the number of primitives written, not individual vertices. To calculate the final vertex count, the CPU multiplies the primitive count by the number of vertices that define the active primitive topology:

  • GL_POINTS: 1 vertex per primitive.
  • GL_LINES: 2 vertices per primitive.
  • GL_TRIANGLES: 3 vertices per primitive.

For example, if the primitive mode is GL_TRIANGLES and primitivesWritten is 150, the total vertex count written to the buffer is:

\[\text{Vertex Count} = 150 \times 3 = 450\]

Applications of CPU-Side Vertex Data

Transform feedback queries are essential in scenarios where the CPU must orchestrate application logic based on GPU simulation results:

  • Dynamic Buffer Allocation: If dynamic geometry generation approaches buffer limits, the CPU can allocate larger vertex buffers for subsequent frames.
  • Bounding Box and Frustum Calculations: Knowing the count of active elements allows the CPU to adjust spatial partitioning algorithms and manage object lifetimes.
  • Conditional Updates: If a query returns zero primitives written (e.g., all particles have decayed or all triangles were culled), the CPU can disable downstream passes entirely, saving processing power.

While modern OpenGL provides glDrawTransformFeedback to draw captured data entirely on the GPU without CPU intervention, transform feedback queries remain the sole mechanism for conveying exact primitive and vertex counts back to CPU memory space.
