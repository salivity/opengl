Frustum Clustering Algorithms in OpenGL Compute Shaders

This article explores the primary compute shader algorithms used to subdivide a camera view frustum into clustered 3D bins in modern OpenGL. Clustered shading eliminates the depth-discontinuity performance penalties found in traditional 2D tiled rendering by organizing the view volume into a 3D grid of view-space or screen-space bounding volumes. Below, we examine the mathematics and implementation strategies behind grid subdivision, logarithmic depth slicing, view-space Axis-Aligned Bounding Box (AABB) construction, and light assignment using Shader Storage Buffer Objects (SSBOs).

1. View Frustum Grid Parameterization

Clustered shading discretizes the view frustum into a three-dimensional grid defined by \(S_x \times S_y \times S_z\) cells:

  • \(X\) and \(Y\) Dimensions: The viewport is divided into equal-sized rectangular tiles, typically \(16 \times 16\) or \(32 \times 32\) pixels.
  • \(Z\) Dimension: View depth is subdivided into discrete depth slices.

Because perspective projection causes objects farther away to project to smaller screen footprints, linear depth distribution produces clusters that are too small near the camera and unnecessarily huge in the distance. Consequently, standard implementations employ exponential (logarithmic) depth distribution.

2. Logarithmic Depth Slicing Algorithm

To allocate resolution proportional to perceptual scale and view-space perspective compression, the \(Z\) bounds for each slice index \(k \in [0, S_z - 1]\) are computed exponentially:

\[Z_{\text{slice}}(k) = Z_{\text{near}} \cdot \left( \frac{Z_{\text{far}}}{Z_{\text{near}}} \right)^{\frac{k}{S_z}}\]

In an OpenGL compute shader, determining the slice index \(k\) for an arbitrary view-space depth \(z\) uses the inverse formulation:

\[k = \left\lfloor \frac{\log(|z| / Z_{\text{near}})}{\log(Z_{\text{far}} / Z_{\text{near}})} \cdot S_z \right\rfloor\]

This ensures near-plane clusters maintain tight bounding volumes to tightly enclose nearby point and spot lights, while far clusters encompass broader areas where light density is generally lower.

3. Screen-Space Unprojection and AABB Generation

The most widely adopted algorithm for building cluster volumes generates an Axis-Aligned Bounding Box (AABB) for each cluster in view space. This compute pass executes only when camera projection parameters change.

Step-by-Step Algorithm:

  1. Invocation Mapping:
    Launch a compute shader with work groups sized to cover \(S_x \times S_y \times S_z\) total clusters.

    layout(local_size_x = 1, local_size_y = 1, local_size_z = 1) in;

  2. Compute Normalized Device Coordinates (NDC):
    Convert the discrete cluster coordinate \((x, y)\) into NDC bounds \([-1, 1]\):

    vec4 minNDC = vec4(
    (float(gl_WorkGroupID.x) / float(gridDim.x)) * 2.0 - 1.0,
    (float(gl_WorkGroupID.y) / float(gridDim.y)) * 2.0 - 1.0,
    -1.0, 
    1.0
);
vec4 maxNDC = vec4(
    (float(gl_WorkGroupID.x + 1) / float(gridDim.x)) * 2.0 - 1.0,
    (float(gl_WorkGroupID.y + 1) / float(gridDim.y)) * 2.0 - 1.0,
    -1.0, 
    1.0
);

  3. Unproject to View-Space Rays:
    Transform the NDC points using the inverse projection matrix (inverse(projectionMatrix)) and divide by the \(w\)-component to derive directional vectors from the camera origin through each tile corner.

  4. Intersect with Slice Depth Planes:
    Multiply the view-space rays by the calculated \(Z_{\text{slice}}(k)\) and \(Z_{\text{slice}}(k + 1)\) to obtain the 8 world- or view-space corner vertices of the cluster frustum.

  5. Derive View-Space AABB:
    Compute the component-wise minimum and maximum vectors among the 8 calculated corners:

    vec3 minAABB = min(corner[0], min(corner[1], ...));
vec3 maxAABB = max(corner[0], max(corner[1], ...));

  6. Write to Buffer:
    Store minAABB and maxAABB into a continuous std430 layout SSBO:

    struct VolumeAABB {
    vec4 minPoint;
    vec4 maxPoint;
};
layout(std430, binding = 1) buffer ClusterAABBBuffer {
    VolumeAABB clusters[];
};

4. Alternative Approaches: Frustum Plane Representation

While AABB representation is fast for intersection tests, it introduces empty volume padding around diagonal frustum corners, resulting in false positives during light culling.

An alternative algorithm computes the 6 bounding planes of the cluster frustum directly:

  • Near and Far Planes: Constant view-space planes \(z = -Z_{\text{slice}}(k)\) and \(z = -Z_{\text{slice}}(k+1)\).
  • Side Planes (Left, Right, Top, Bottom): Constructed by taking the cross product of the vectors from the camera origin to adjacent tile corners.

Each cluster stores 6 normalized vec4 plane equations \((a, b, c, d)\). During light culling, a light sphere defined by center \(C\) and radius \(R\) intersects the cluster if:

\[a \cdot C_x + b \cdot C_y + c \cdot C_z + d \geq -R\]

for all 6 planes. This completely eliminates empty-corner conservatism at the cost of higher memory bandwidth and increased arithmetic overhead per intersection test.

5. Cluster Light Culling Pass

Once clusters are defined, a second compute shader assigns light indices to each cluster:

  1. Work Distribution: One thread or thread group per cluster reads the corresponding AABB from the SSBO.

  2. Sphere-AABB Intersection: The thread iterates over scene lights and evaluates the squared distance from the sphere center to the cluster AABB:

    float sqDist = 0.0;
for (int i = 0; i < 3; ++i) {
    float v = lightPos[i];
    if (v < minAABB[i]) sqDist += (minAABB[i] - v) * (minAABB[i] - v);
    if (v > maxAABB[i]) sqDist += (v - maxAABB[i]) * (v - maxAABB[i]);
}
bool visible = sqDist <= (radius * radius);

  3. Atomic Index Writing: Visible light indices are written to a global light-index list using atomic counters (atomicAdd), and an offset/count pair is stored in an index grid buffer for subsequent shading passes.
