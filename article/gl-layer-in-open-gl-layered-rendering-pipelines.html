gl_Layer in OpenGL Layered Rendering Pipelines

Layered rendering in OpenGL allows an application to draw into multiple slices of a layered framebuffer attachment—such as a 2D texture array, 3D texture, or cubemap—within a single draw call. The built-in shading language variable gl_Layer acts as the routing mechanism in this pipeline, dictating precisely which slice or face of a layered attachment receives each generated primitive. By dynamically assigning layer indices during shader execution, developers can streamline rendering tasks that historically required multiple passes, drastically reducing CPU-to-GPU state overhead.

What is gl_Layer?

gl_Layer is a built-in output variable in GLSL that accepts an integer value. When rendering to a layered framebuffer object (FBO), the value assigned to gl_Layer instructs the hardware rasterizer to send the current primitive to the attachment layer corresponding to that index.

If layered rendering is active and a primitive does not explicitly write to gl_Layer, the layer index defaults to zero. If the assigned index falls outside the range of valid layers for the currently bound framebuffer, the primitive is discarded.

Pipeline Stages and Execution

Historically, gl_Layer was strictly an output of the Geometry Shader (GS). In a typical geometry shader workflow:

  1. The application binds a layered texture (e.g., GL_TEXTURE_2D_ARRAY or GL_TEXTURE_CUBE_MAP) to an FBO attachment using glFramebufferTexture.
  2. The geometry shader processes incoming primitives and determines the destination layer.
  3. The shader writes the target index to gl_Layer for every emitted vertex via EmitVertex().
  4. A single incoming primitive can be amplified and duplicated across multiple layers by altering gl_Layer between batches of EmitVertex() and EndPrimitive() calls.

With the introduction of extensions such as GL_ARB_shader_viewport_layer_array (and core adoption in OpenGL 4.5), gl_Layer can also be written directly from Vertex Shaders and Tessellation Shaders. This eliminates the geometry shader stage entirely, circumventing the performance penalties traditionally associated with geometry shader amplification.

Key Use Cases

  • Omnidirectional Point-Light Shadows: Instead of rendering a scene six times with six separate draw calls to populate each face of a cubemap, a single pass can direct geometry to the appropriate cubemap face (indices 0 through 5) using gl_Layer.
  • Cascaded Shadow Maps (CSM): Slices of a 2D texture array representing different shadow cascades can be populated concurrently.
  • Stereoscopic and VR Rendering: Geometry can be duplicated to left and right eye viewports or texture array slices in a single execution pass.
  • Voxelization and 3D Texture Generation: Primitives can be routed along slices of a 3D texture based on dominant projection axes.

Performance Impact

The primary advantage of gl_Layer is the minimization of draw calls and pipeline reconfiguration. By replacing multiple distinct rendering passes with a single layered pass, applications reduce CPU driver overhead, avoid redundant vertex buffer binding, and improve overall GPU throughput.
