Billboard Particles Using OpenGL Geometry Shaders

This article explores billboard particle rendering and demonstrates how to implement it efficiently using OpenGL geometry shaders. You will learn the core concept of billboarding, understand why offloading quad generation to the GPU improves performance, and review the shader pipeline required to transform single 3D points into camera-facing textured quads.

What is Billboard Particle Rendering?

Billboard particle rendering is a computer graphics technique where 2D textured planes (quads) are positioned in a 3D world and oriented so they continuously face the camera. Instead of rendering complex 3D geometry for volumetric or amorphous effects, developers use flat textures representing elements like smoke, fire, sparks, clouds, and raindrops.

Because the plane automatically rotates to align with the camera's view plane, the viewer cannot easily perceive that the object is flat. This technique drastically reduces the polygon count of a scene while maintaining visual fidelity for large-scale visual effects.

Why Use an OpenGL Geometry Shader?

Traditionally, billboarding required the CPU to calculate four vertices for every particle, update their orientations toward the camera, and upload the full quad mesh to the GPU every frame. This creates significant CPU-to-GPU bandwidth bottlenecks when managing tens of thousands of particles.

An OpenGL geometry shader solves this problem by generating new geometry directly on the GPU. Instead of sending four vertices per particle, the application sends a single point primitive containing the particle's position, size, and other attributes (such as color or rotation). The geometry shader then dynamically expands this single point into a screen-aligned quad consisting of two triangles (four vertices) before rasterization.

Implementing Billboarding with Geometry Shaders

Implementing this technique requires configuring a pipeline across the vertex, geometry, and fragment shaders, typically using view-space mathematics for straightforward camera alignment.

1. The Vertex Shader

The vertex shader accepts point coordinates and particle attributes, passing them downstream. To simplify billboarding in the geometry shader, the vertex shader transforms the particle's position from world space into view space (camera space) using the Model-View matrix.

#version 330 core
layout (location = 0) in vec3 aPos;
layout (location = 1) in float aSize;

out float vSize;

uniform mat4 uModelView;

void main()
{
    vSize = aSize;
    // Transform position to view space
    gl_Position = uModelView * vec4(aPos, 1.0);
}

2. The Geometry Shader

The geometry shader takes points as input and emits a triangle_strip with a maximum of four vertices. Because the coordinates are already in view space, the camera's viewing plane is parallel to the X-Y plane. Offsetting the point along the local X and Y axes automatically creates a camera-facing billboard without requiring complex vector math or trigonometric functions.

#version 330 core
layout (points) in;
layout (triangle_strip, max_vertices = 4) out;

in float vSize[];
out vec2 TexCoords;

uniform mat4 uProjection;

void main()
{
    vec4 center = gl_PositionIn[0];
    float halfSize = vSize[0] * 0.5;

    // Bottom-Left
    gl_Position = uProjection * (center + vec4(-halfSize, -halfSize, 0.0, 0.0));
    TexCoords = vec2(0.0, 0.0);
    EmitVertex();

    // Bottom-Right
    gl_Position = uProjection * (center + vec4(halfSize, -halfSize, 0.0, 0.0));
    TexCoords = vec2(1.0, 0.0);
    EmitVertex();

    // Top-Left
    gl_Position = uProjection * (center + vec4(-halfSize, halfSize, 0.0, 0.0));
    TexCoords = vec2(0.0, 1.0);
    EmitVertex();

    // Top-Right
    gl_Position = uProjection * (center + vec4(halfSize, halfSize, 0.0, 0.0));
    TexCoords = vec2(1.0, 1.0);
    EmitVertex();

    EndPrimitive();
}

3. The Fragment Shader

The fragment shader receives the texture coordinates generated by the geometry shader, samples the particle texture, and outputs the final color. It often applies alpha testing or color tinting.

#version 330 core
in vec2 TexCoords;
out vec4 FragColor;

uniform sampler2D uParticleTexture;

void main()
{
    vec4 texColor = texture(uParticleTexture, TexCoords);
    if (texColor.a < 0.05)
        discard;
    FragColor = texColor;
}

OpenGL State Considerations

To correctly display particles, the application must configure the OpenGL rendering state properly:

  • Blending: Enable GL_BLEND using appropriate blend functions. Additive blending (GL_SRC_ALPHA, GL_ONE) is ideal for glowing effects like fire and magic, while standard alpha blending (GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA) is suited for smoke and dust.
  • Depth Testing: Enable depth testing (GL_DEPTH_TEST), but consider disabling depth writes (glDepthMask(GL_FALSE)) while drawing transparent particles to avoid unwanted clipping and sorting artifacts.
  • Draw Calls: Render particles using glDrawArrays(GL_POINTS, 0, particleCount) to feed the geometry shader.
