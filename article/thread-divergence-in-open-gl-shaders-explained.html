Thread Divergence in OpenGL Shaders Explained

Thread divergence occurs in OpenGL shaders when adjacent threads within the same hardware execution unit—a warp on NVIDIA hardware or a wavefront on AMD—execute different code paths due to conditional branching. Because GPUs rely on a Single Instruction, Multiple Threads (SIMT) architecture, threads in a single warp must execute the same instruction simultaneously. When dynamic conditions cause these threads to branch in different directions, the GPU must serialize each divergent path, reducing compute utilization, wasting clock cycles, and degrading overall shader execution speed.

The SIMT Execution Model

Modern GPUs bundle fragment, vertex, or compute shader invocations into groups, typically 32 threads for NVIDIA warps and 32 or 64 threads for AMD wavefronts. In an ideal execution pass, every thread in that group processes the exact same instruction at the exact same clock cycle, but operates on unique data, such as distinct pixel coordinates or vertex attributes. The hardware utilizes a single instruction fetch and decode unit for the entire warp, driving multiple execution lanes in lockstep.

How Dynamic Branching Causes Divergence

When an OpenGL shader contains conditional logic (if-else blocks, switch statements, or data-dependent for and while loops), the execution path may depend on dynamic values such as per-fragment varying inputs or texture samples.

If all threads in a warp evaluate a condition identically, the entire warp follows a single branch, incurring minimal overhead. However, if some threads evaluate a condition as true and others as false, the warp diverges. The hardware cannot split itself to run two different instructions concurrently for separate threads in the same lockstep group.

The Cost of Path Serialization

To handle divergence, the GPU serializes execution:

  1. Masking: The GPU disables (masks off) the threads that evaluated the condition as false.
  2. First Path Execution: The active threads execute the true branch instructions while the masked threads sit idle.
  3. Inversion and Second Path Execution: The GPU inverts the mask, enabling the previously idle threads and disabling the threads that already finished the true block. It then executes the else branch instructions.
  4. Reconvergence: Once all alternative branches are evaluated, the threads reconverge, and the warp resumes unified execution.

The total execution time for a divergent warp equals the sum of the time required to execute both the if and else blocks, rather than just the time for the taken path. Even if only one thread out of 32 takes an expensive code path, the other 31 threads must wait through that execution, cutting hardware arithmetic throughput by up to 50% or more for that duration.

Impact on Loops and Memory Latency

The performance degradation multiplies with data-dependent loops. If threads in a warp iterate a variable number of times, the warp must remain active until the single thread with the highest iteration count finishes. Threads that complete their loops early remain stalled, consuming register resources and preventing the GPU scheduler from utilizing those functional units for other tasks.

Furthermore, divergence disrupts memory coalescing. In lockstep execution, contiguous threads access contiguous memory addresses, allowing the memory controller to combine multiple requests into a single memory transaction. Divergent branches break this spatial locality, producing scattered memory access patterns that trigger cache misses, saturate memory bandwidth, and stall execution pipelines.

Mitigating Divergence in GLSL

To maintain optimal throughput in OpenGL shaders:

  • Use Built-in Functions: Replace conditional assignments with branch-free GLSL intrinsics like mix(), step(), clamp(), and min()/max(), which often map directly to hardware-level conditional select instructions that avoid warp serialization.
  • Group Divergent Work: Ensure that divergent conditions depend on uniform variables rather than varying inputs or textures whenever possible, as uniforms guarantee that all threads in a draw call evaluate the branch identically.
  • Sort Geometry: For compute passes or compute shaders, organize input data spatially so that invocations requiring similar execution paths are dispatched within the same work group or warp.
