How OpenGL Conditional Rendering Works

Conditional rendering in OpenGL is an optimization technique that allows the GPU to discard draw calls internally based on the results of an occlusion query, eliminating the need to stall the rendering pipeline to transfer data back to the CPU. By pairing bounding-volume visibility tests directly with complex geometry rendering commands on the device timeline, the graphics driver delegates culling decisions entirely to hardware. This approach maximizes rendering throughput by preventing the CPU from waiting on query results while simultaneously avoiding redundant vertex processing, fragment shading, and memory bandwidth usage for occluded objects.

In a standard occlusion query workflow without conditional rendering, the CPU issues an occlusion query for a simplified bounding box, finishes other work, and then queries the result using functions such as glGetQueryObjectuiv. This call creates a massive performance bottleneck: if the GPU has not finished rasterizing the query geometry, the CPU must stall until the GPU completes execution and writes the sample count back to host-accessible memory. Only then can the CPU decide whether to submit the high-detail draw call for that object.

Conditional rendering solves this synchronization problem via the glBeginConditionalRender and glEndConditionalRender functions. Instead of reading the query outcome on the host, the CPU immediately submits both the occlusion query (typically on a low-poly bounding proxy) and the full-resolution draw calls in sequence. The detailed draw calls are wrapped inside a conditional block referencing the query's ID. When the GPU processes this command block in its command queue, it evaluates the query result directly in hardware. If the query recorded that no samples passed the depth test, the GPU automatically discards the enclosed draw commands before executing expensive vertex fetching and fragment shading stages.

OpenGL offers several operational modes to balance culling efficiency against GPU pipeline stalls:

  • GL_QUERY_WAIT: The GPU pauses execution of the command stream at the conditional block until the referenced query completes. Once the result is available, the GPU decides whether to render or discard the commands. This guarantees that fully occluded objects will never execute their draw calls, but it can introduce GPU pipeline bubbles if the query takes long to resolve.
  • GL_QUERY_NO_WAIT: The GPU checks if the query has finished execution. If the result is ready, the GPU applies the culling decision. If the query is still in flight, the GPU assumes the object is visible and executes the draw calls anyway. This completely avoids GPU execution bubbles at the cost of occasionally rendering occluded geometry.
  • GL_QUERY_BY_REGION_WAIT and GL_QUERY_BY_REGION_NO_WAIT: These modes function similarly to their standard counterparts but allow the GPU to discard draw calls for specific screen regions or tiles if the query results within that region indicate no visibility, which is particularly beneficial for tiled architectures.

By keeping all visibility decisions local to the graphics hardware, conditional rendering bypasses the latency of bus transfers between host memory and video memory. The CPU continues feeding draw calls without interruption, and the GPU dynamically prunes hidden workloads, ensuring high frame rates in complex, densely occluded scenes.
