Mouse Picking in Early OpenGL Using GL_SELECT

In early fixed-function OpenGL, mouse picking was accomplished using a dedicated selection mode (GL_SELECT) paired with the gluPickMatrix utility and an internal name stack. Instead of rendering pixels to the frame buffer, the pipeline processed geometry against a restricted viewing volume centered around the cursor, recording intersecting primitives into an application-defined selection buffer as "hit records." This article explains the architectural components of OpenGL's selection mode mechanism, the workflow required to capture user clicks, the structure of the resulting hit data, and why the technique was eventually replaced in modern graphics programming.

The Selection Render Mode

OpenGL operated as a state machine with three render modes controlled by glRenderMode(): GL_RENDER (normal drawing), GL_FEEDBACK (returning transformed vertices), and GL_SELECT (hit testing).

Switching the state to GL_SELECT stopped the rasterization stage from writing pixel colors to the color buffer. Instead, primitives that fell within the viewing frustum generated hit events. Before switching modes, the developer allocated an array of unsigned integers in client memory and bound it using glSelectBuffer(size, buffer) to hold the results.

Restricting the Viewport with gluPickMatrix

Because a standard projection matrix tests geometry against the entire screen, picking required modifying the projection to test only the region immediately beneath the cursor. The OpenGL Utility Library (GLU) provided gluPickMatrix() to automate this:

  1. The projection matrix was set to identity (glMatrixMode(GL_PROJECTION); glLoadIdentity();).
  2. gluPickMatrix(x, y, width, height, viewport) was called, where x and y were the mouse coordinates (inverted to match OpenGL's bottom-left origin), and width and height defined a small bounding box (typically 2x2 to 5x5 pixels).
  3. The normal camera projection (such as gluPerspective or glOrtho) was multiplied immediately after gluPickMatrix.

This sequence scaled and translated the viewing volume so that only objects within the picking box survived clipping.

The Name Stack

To identify specific objects during rendering, OpenGL provided an internal name stack managed by four commands:

  • glInitNames(): Clears the stack.
  • glPushName(GLuint name): Pushes an identifier onto the stack.
  • glPopName(): Removes the top identifier.
  • glLoadName(GLuint name): Replaces the identifier currently at the top of the stack.

During the picking pass, the scene was drawn just as it would be normally. When an object produced a primitive inside the restricted viewing frustum, the contents of the name stack at that moment were logged to the select buffer. This hierarchical design allowed developers to identify both parent objects and their individual sub-components (for example, selecting a specific wheel on a specific car).

Reading Hit Records

Exiting selection mode was done by calling glRenderMode(GL_RENDER). This function returned an integer indicating the total number of hits recorded.

The developer then parsed the memory buffer specified earlier by glSelectBuffer. Each hit record in the buffer consisted of:

  1. Number of names: An integer stating how many names were on the name stack when the hit occurred.
  2. Minimum depth (\(Z_{min}\)): The minimum normalized device coordinate depth value of the intersecting primitive, scaled to an unsigned 32-bit integer.
  3. Maximum depth (\(Z_{max}\)): The maximum depth value of the intersecting primitive.
  4. Name contents: The actual integer identifiers from the name stack, listed from bottom to top.

If multiple objects overlapped under the cursor, the developer sorted the hits using the \(Z_{min}\) value to select the object closest to the camera.

Deprecation and Modern Replacements

Selection mode was deprecated in OpenGL 3.0 and removed in the Core Profile. It relied heavily on the fixed-function pipeline, lacked hardware acceleration on many consumer GPUs, and forced CPU-GPU synchronization bottlenecks. Modern picking is typically handled in one of two ways:

  • Ray Casting: Converting the 2D screen coordinate into a 3D world-space ray via un-projection and testing for intersections with bounding volumes or polygons on the CPU or in a compute shader.
  • Color Picking (ID Buffering): Rendering the scene offscreen to a Framebuffer Object (FBO), where each object is drawn with a unique color corresponding to its ID, and reading the single pixel under the cursor using glReadPixels.
