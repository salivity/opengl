Using Multiple Transform Feedback Streams in OpenGL

OpenGL allows applications to capture vertex data generated by shaders directly into GPU buffers through transform feedback. By leveraging the Geometry Shader and the multi-stream capabilities introduced in OpenGL 4.0, developers can route different primitive groups into up to four separate buffer objects simultaneously. This article outlines the architecture of multiple transform feedback streams, how to write the Geometry Shader to partition data, how to configure the OpenGL host code with buffer separators, and the hardware constraints involved.

Core Requirements and Hardware Limits

Directing primitives to multiple transform feedback buffers requires the Geometry Shader stage; vertex or tessellation shaders alone cannot route to independent streams.

OpenGL defines the following constraints:

  • Stream Limit: OpenGL supports up to four independent streams (indices 0 through 3), queried using glGetIntegerv(GL_MAX_VERTEX_STREAMS, &maxStreams).
  • Rasterization Restriction: Only primitives emitted to Stream 0 can continue down the pipeline to the rasterizer. Streams 1, 2, and 3 are exclusively captured into transform feedback buffers and cannot be rasterized directly.
  • Primitive Type: All streams must output point primitives (points) when emitting to multiple streams.

Step 1: Assigning Streams in the Geometry Shader

In GLSL, individual output variables or output interface blocks must be tagged with the stream layout qualifier. The geometry shader uses EmitStreamVertex(int stream) and EndStreamPrimitive(int stream) instead of the standard single-stream equivalents.

#version 400 core

layout(triangles) in;
layout(points, max_vertices = 4) out;

// Stream 0: Standard data that can proceed to the rasterizer
layout(stream = 0) out vec3 outPosition;

// Stream 1: Secondary diagnostic or simulation data
layout(stream = 1) out vec4 outVelocity;

void main() {
    // Emit to Stream 0
    outPosition = gl_in[0].gl_Position.xyz;
    EmitStreamVertex(0);
    EndStreamPrimitive(0);

    // Emit to Stream 1
    outVelocity = vec4(1.0, 0.0, 0.0, 0.0);
    EmitStreamVertex(1);
    EndStreamPrimitive(1);
}

Step 2: Specifying Varyings on the Host

Before linking the shader program, you must declare which outputs are captured and assign them to distinct buffer binding points using glTransformFeedbackVaryings.

To split data across different buffer binding points, use the special delimiter token "gl_NextBuffer" in the varying array, while setting the buffer mode to GL_INTERLEAVED_ATTRIBS:

const char* varyings[] = {
    "outPosition",   // Assigned to Buffer Binding 0 (Stream 0)
    "gl_NextBuffer", // Advance to Buffer Binding 1
    "outVelocity"    // Assigned to Buffer Binding 1 (Stream 1)
};

glTransformFeedbackVaryings(programID, 3, varyings, GL_INTERLEAVED_ATTRIBS);
glLinkProgram(programID);

Each occurrence of "gl_NextBuffer" increments the target buffer index by one.

Step 3: Binding Buffers and Executing the Draw

Each assigned index must be bound to a separate buffer object using glBindBufferBase or glBindBufferRange with the GL_TRANSFORM_FEEDBACK_BUFFER target.

// Bind buffer for Stream 0 (index 0)
glBindBufferBase(GL_TRANSFORM_FEEDBACK_BUFFER, 0, bufferStream0);

// Bind buffer for Stream 1 (index 1)
glBindBufferBase(GL_TRANSFORM_FEEDBACK_BUFFER, 1, bufferStream1);

// Optional: Disable rasterization if you only need the feedback data
glEnable(GL_RASTERIZER_DISCARD);

glBeginTransformFeedback(GL_POINTS);
glDrawArrays(GL_TRIANGLES, 0, vertexCount);
glEndTransformFeedback();

glDisable(GL_RASTERIZER_DISCARD);

When glDrawArrays executes, the Geometry Shader evaluates each input primitive and routes attributes tagged with stream = 0 to bufferStream0, while attributes tagged with stream = 1 are captured in bufferStream1.
