OpenGL Texture Array vs 3D Texture Differences

While both 2D texture arrays and 3D textures in OpenGL store collections of two-dimensional image slices, they serve fundamentally different architectural purposes in the graphics pipeline. The primary difference lies in how OpenGL handles coordinate addressing, mipmapping, and inter-slice filtering: a 3D texture represents a continuous volumetric space with filtering between slices, whereas a texture array represents a collection of independent 2D textures that share the same dimensions and format without any cross-slice interpolation.

Filtering and Interpolation Between Slices

The most significant functional difference between these two texture types is how OpenGL samples data along the third axis.

  • 3D Textures (GL_TEXTURE_3D): When using linear filtering (GL_LINEAR), sampling a 3D texture interpolates data across all three dimensions (\(X\), \(Y\), and \(Z\)). If you sample between slice \(0\) and slice \(1\), the GPU performs trilinear interpolation, blending the texels of both adjacent slices together.
  • 2D Texture Arrays (GL_TEXTURE_2D_ARRAY): Texture arrays strictly forbid filtering between slices. Even with linear filtering enabled, the GPU only performs bilinear filtering within the bounds of a single slice. The layer coordinate is evaluated as an integer index (via rounding), ensuring that adjacent layers never bleed into one another.

Coordinate Addressing

The coordinate systems used to sample these textures reflect their structural purposes.

  • 3D Textures: Sampled using normalized floating-point coordinates \((s, t, r)\), where \(r\) ranges from 0.0 to 1.0. The value of \(r\) represents a continuous position within the volume.
  • Texture Arrays: Sampled using coordinates \((s, t, layer)\), where \(s\) and \(t\) are standard normalized coordinates (0.0 to 1.0), but the third component represents the specific zero-based layer index. While passed as a floating-point value in GLSL shaders (vec3), the layer value is clamped to the range \([0, \text{layers}-1]\) and rounded to the nearest integer to select a distinct slice.

Mipmap Generation

Mipmaps behave differently to accommodate either continuous volume reduction or independent image reduction.

  • 3D Textures: Mipmap downsampling occurs in all three spatial dimensions simultaneously. Each successive mip level halves the width, height, and depth (\(W/2 \times H/2 \times D/2\)) until reaching a \(1 \times 1 \times 1\) voxel.
  • Texture Arrays: Mipmaps are generated strictly for the two-dimensional surface of each layer. While the width and height halve at each mip level (\(W/2 \times H/2\)), the total number of layers remains completely constant across the entire mip chain.

Typical Use Cases

  • Use a 3D Texture for: True volumetric datasets where continuous density is required, such as smoke, fog, medical imaging (CT/MRI scans), 3D noise generation, and volumetric light scattering.
  • Use a Texture Array for: Managing collections of discrete 2D materials, such as terrain splatting, voxel game blocks, particle effects, or rendering dynamic character skins. Texture arrays serve as a modern, robust alternative to texture atlases, eliminating edge-bleeding artifacts caused by mipmapping and texture wrapping.
