Global vs Local Invocation ID in OpenGL Compute Shaders

In an OpenGL compute shader, execution is parallelized across multiple compute units divided into distinct work groups, requiring unique identifiers to coordinate data access. This article explains the technical differences between gl_GlobalInvocationID and gl_LocalInvocationID, demonstrating how each variable functions within the compute shader execution model and how they are calculated.

The Compute Dispatch Hierarchy

To understand these IDs, it is essential to understand how OpenGL organizes compute tasks. When you issue a compute dispatch via glDispatchCompute(num_groups_x, num_groups_y, num_groups_z), you define a three-dimensional grid of work groups. Inside the shader code, the layout(local_size_x, local_size_y, local_size_z) in; declaration defines how many individual threads, or invocations, exist inside each work group.

What is gl_LocalInvocationID?

gl_LocalInvocationID is a built-in uvec3 variable that identifies the current invocation's position relative only to its own work group.

  • Range: The values range from (0, 0, 0) to gl_WorkGroupSize - 1.
  • Scope: It resets for every work group. Multiple invocations across different work groups will share the exact same gl_LocalInvocationID.
  • Primary Use Case: Indexing into work-group-shared memory declared with the shared keyword, and synchronizing threads using barrier() or memoryBarrierShared().

What is gl_GlobalInvocationID?

gl_GlobalInvocationID is a built-in uvec3 variable that identifies the current invocation across the entire compute dispatch, uniquely identifying it among all invocations.

  • Range: The values range from (0, 0, 0) up to (gl_NumWorkGroups * gl_WorkGroupSize) - 1.
  • Scope: It is globally unique within the dispatch. No two active invocations will share the same gl_GlobalInvocationID.
  • Primary Use Case: Indexing into global resources, such as Shader Storage Buffer Objects (SSBOs) or storage textures (image2D), ensuring that each thread reads or writes to a unique element in the global memory space.

The Mathematical Relationship

The OpenGL specification defines gl_GlobalInvocationID directly using gl_LocalInvocationID, along with the work group ID and work group size:

gl_GlobalInvocationID = gl_WorkGroupID * gl_WorkGroupSize + gl_LocalInvocationID;
  • gl_WorkGroupID: The three-dimensional index of the current work group within the global dispatch grid.
  • gl_WorkGroupSize: The static dimensions defined by layout(local_size_x, local_size_y, local_size_z).

Summary of Differences

  • Scope: gl_LocalInvocationID is local to the current work group; gl_GlobalInvocationID spans the entire dispatch.
  • Uniqueness: gl_LocalInvocationID repeats across every work group; gl_GlobalInvocationID is unique across all threads.
  • Target Memory: gl_LocalInvocationID is primarily used for shared memory operations; gl_GlobalInvocationID is used for global buffers and images.
