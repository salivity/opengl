How GL_ARB_sparse_texture Allocates Mipmap Memory

The GL_ARB_sparse_texture extension enables OpenGL applications to decouple a texture's virtual dimensions from its physical memory footprint. Instead of allocating memory for an entire texture up front, the driver sets up a virtual address space and allocates physical memory on-demand to specific subregions across mipmap levels. This process relies on fixed-size virtual pages, explicit page commitment calls, and a dedicated strategy for managing small, lower-resolution mipmaps known as the mip tail.

Virtual Pages and Tile Alignment

When sparse textures are enabled, the GPU divides mipmap levels into discrete, uniform 2D or 3D blocks called virtual pages (or tiles). Before physical memory can be mapped, the application must query the supported tile dimensions for a specific texture format and target using glGetInternalformativ with the GL_VIRTUAL_PAGE_SIZE_X_ARB, GL_VIRTUAL_PAGE_SIZE_Y_ARB, and GL_VIRTUAL_PAGE_SIZE_Z_ARB parameters.

Memory is allocated at the granularity of these virtual pages. Any physical allocation must be aligned to the tile dimensions of the corresponding mipmap level.

Physical Memory Allocation via glTexPageCommitmentARB

Physical memory is not assigned during texture creation. The texture storage is declared virtually using standard immutable texture storage commands (such as glTexStorage2D or glTexStorage3D) after setting GL_TEXTURE_SPARSE_ARB to GL_TRUE.

To back a specific mipmap region with physical memory, the application calls:

void glTexPageCommitmentARB(
    GLenum target,
    GLint level,
    GLint xoffset,
    GLint yoffset,
    GLint zoffset,
    GLsizei width,
    GLsizei height,
    GLsizei depth,
    GLboolean commit
);
  • level: Specifies the exact mipmap level to target.
  • xoffset, yoffset, zoffset: The starting coordinates within that mipmap level, which must be integer multiples of the virtual page dimensions for that level.
  • width, height, depth: The dimensions of the region to allocate, which must also be exact multiples of the virtual page dimensions (unless the region extends to the outer edge of the mipmap level).
  • commit: When set to GL_TRUE, the driver allocates physical GPU memory and updates the page tables to map the virtual addresses to this storage. When set to GL_FALSE, the physical pages are deallocated, unbinding memory and returning it to the GPU pool.

Handling Lower Mip Levels: The Mip Tail

As mipmap levels decrease in resolution, their dimensions eventually become smaller than a single virtual page size. Because individual pages cannot be efficiently subdivided among different mip levels, the extension transitions from tile-based allocation to a packed region called the mip tail.

  1. Identifying the Mip Tail: Applications query the index where the mip tail starts by reading GL_NUM_SPARSE_LEVELS_ARB. Any mip level index equal to or greater than this value resides in the mip tail.
  2. All-or-Nothing Allocation: Mip levels inside the tail cannot be committed independently. The entire mip tail is treated as a single physical allocation unit.
  3. Committing the Tail: To commit memory to the mip tail, glTexPageCommitmentARB is called targeting the first level of the tail (or level zero for certain array/cube targets depending on configuration flags like GL_SPARSE_TEXTURE_FULL_ARRAY_CUBE_MIPMAPS_ARB). The application specifies the dimensions returned by querying GL_SPARSE_TEXTURE_PAGE_SIZE_ARB metadata, committing or decommitting all tail levels simultaneously.
