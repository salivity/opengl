Uniform vs Attribute Variables in OpenGL Shaders

In OpenGL Shading Language (GLSL), uniform and attribute variables serve as two distinct mechanisms for passing data from your CPU-bound application to the GPU pipeline. The core difference lies in how frequently their values change and where they are accessible: attribute variables provide unique, per-vertex data strictly to the vertex shader, while uniform variables provide constant, global data across an entire draw call that is accessible across all shader stages.

Attribute Variables

Attribute variables represent data that varies from one vertex to the next. They define the intrinsic properties of a 3D model, such as vertex coordinates, surface normals, texture coordinates (UVs), and vertex colors.

  • Data Frequency: Evaluated per vertex. If a mesh has 1,000 vertices, an attribute variable will contain 1,000 distinct sets of values.
  • Pipeline Stage: Exclusive to the vertex shader. Fragment shaders cannot access attributes directly; instead, the vertex shader must pass them along as varying variables (or out variables in modern GLSL), which are then interpolated across the surface of the primitive.
  • Source: Fed directly from Vertex Buffer Objects (VBOs) stored on the GPU and configured via Vertex Array Objects (VAOs).
  • Modern Syntax: In legacy GLSL, these are declared with the attribute keyword. In modern GLSL (version 1.30 and later), the attribute keyword is deprecated and replaced by the in qualifier within the vertex shader.

Uniform Variables

Uniform variables act as global parameters that remain constant for all vertices and fragments processed during a single draw call (such as a call to glDrawArrays or glDrawElements).

  • Data Frequency: Constant per draw call. The value does not change between individual vertices or fragments unless explicitly updated by the CPU before the next draw call.
  • Pipeline Stage: Accessible across multiple active shader stages, including vertex, fragment, geometry, and compute shaders, provided the variable is declared with the exact same name and type in each stage.
  • Source: Set directly from the host application using OpenGL API functions like glUniform* (e.g., glUniformMatrix4fv or glUniform3f).
  • Common Uses: Transformation matrices (Model, View, Projection), light source positions, material properties, and texture sampler units (sampler2D).
  • Mutability: Read-only within the shader. A shader cannot reassign or modify the value of a uniform variable internally.

Summary of Differences

Feature Attribute Variables Uniform Variables
Data Granularity Per-vertex (unique to each vertex) Per-primitive / draw call (global constant)
Shader Availability Vertex shader only Vertex, fragment, geometry, and compute shaders
Typical Data Positions, normals, UVs, vertex colors Matrices, light coordinates, samplers, time
Input Source Vertex Buffer Objects (VBOs) Host program via glUniform* calls
Modern GLSL Keyword in (formerly attribute) uniform
Shader Mutability Read-only input Read-only input
