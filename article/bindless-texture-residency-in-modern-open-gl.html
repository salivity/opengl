Bindless Texture Residency in Modern OpenGL

Bindless textures significantly reduce CPU driver overhead by bypassing standard OpenGL texture units and allowing shaders to access textures directly through 64-bit GPU memory handles. Because the OpenGL driver cannot passively inspect arbitrary shader storage buffers or uniform buffers to determine which handles a draw call will reference, developers must explicitly control texture residency. This article explains the core functions, lifecycle requirements, and synchronization mechanisms that guarantee bindless textures are resident in GPU memory before execution.

Generating Handles and Immutability

Before a texture can be made resident, it must be assigned a unique 64-bit handle using the GL_ARB_bindless_texture extension. Handles are created using either glGetTextureHandleARB (which binds the texture to its default sampling parameters) or glGetTextureSamplerHandleARB (which combines a texture with a separate sampler object).

Once a handle is created, the texture’s layout and parameters become immutable. The driver uses this immutability to establish stable virtual memory mappings and internal hardware descriptors. Attempting to modify the texture’s dimensions, format, or mipmap levels after handle creation will result in an INVALID_OPERATION error.

Explicit Residency Functions

The primary mechanism to guarantee that a texture's backing memory is accessible to shader stages is explicit residency management via the OpenGL API:

  • glMakeTextureHandleResidentARB(GLuint64 handle): Instructs the driver to page the texture data into accessible GPU memory and maintain its virtual-to-physical address mapping. This must be invoked before executing any draw or dispatch call that references the handle.
  • glMakeTextureHandleNonResidentARB(GLuint64 handle): Signals to the driver that the texture is no longer actively needed by subsequent draw calls, allowing the memory manager to evict or repurpose the underlying VRAM if required.
  • glIsTextureHandleResidentARB(GLuint64 handle): Queries the current residency state of a given handle, returning GL_TRUE or GL_FALSE.

For read-write operations via shader image load/store, a separate pair of functions is used: glGetImageHandleARB to generate the image handle and glMakeImageHandleResidentARB(GLuint64 handle, GLenum access) to mark it resident with specific access qualifiers (GL_READ_ONLY, GL_WRITE_ONLY, or GL_READ_WRITE).

Driver Behavior and Page Mapping

When glMakeTextureHandleResidentARB is called, the driver maps the physical VRAM allocations of the texture into the GPU page tables referenced by the handle. Unlike traditional glBindTexture calls, which implicitly manage residency per pipeline stage, bindless residency works globally within the OpenGL context.

Because mapping and unmapping page tables introduces CPU overhead, toggling residency on a per-draw-call basis negates the performance benefits of bindless texturing. Modern rendering pipelines manage residency in bulk:

  1. Batch Residency: Making all textures required for a scene, pass, or frame resident at initialization or frame startup.
  2. Streaming Pools: Maintaining a permanent resident pool of textures in VRAM and streaming updates into existing resident allocations using staging buffers and glTextureSubImage2D.

Synchronization and Execution Order

To avoid undefined behavior or GPU page faults, the call to glMakeTextureHandleResidentARB must be submitted to the OpenGL command stream before any draw calls that dereference the handle. The driver enforces command-stream ordering; as long as the residency call precedes the draw command on the CPU timeline, the GPU will complete the page table updates before the shader stages execute.

Textures must remain resident until all pending GPU commands referencing them have fully finished execution. If a texture is made non-resident using glMakeTextureHandleNonResidentARB while a draw call is still executing or queued on the GPU, a synchronization hazard occurs. Applications must use OpenGL sync objects (glFenceSync and glClientWaitSync) to verify that the GPU has finished reading the handles before revoking residency or deleting the underlying texture objects.
