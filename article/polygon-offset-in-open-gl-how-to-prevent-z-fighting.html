Polygon Offset in OpenGL: How to Prevent Z-Fighting

This article provides an overview of how OpenGL's rasterizer state manages polygon offset to eliminate z-fighting between coplanar surfaces. By modifying the depth values of fragments during the rasterization stage, developers can enforce a deterministic rendering order for overlapping geometry without altering world-space coordinates. Understanding how to configure rasterizer states and calculate depth offsets is essential for rendering decals, outlines, and shadow maps cleanly.

The Mechanism of Z-Fighting

Z-fighting occurs when two or more primitives share the same or nearly identical depth values in screen space. Because depth buffers possess finite floating-point or fixed-point precision, mathematical rounding errors during projection and rasterization cause the GPU to alternate unpredictably between fragments. This produces a flickering, stitched visual artifact where coplanar surfaces compete for visibility.

The Rasterizer’s Role in Depth Modification

The rasterizer is the fixed-function stage of the graphics pipeline that converts geometric primitives (triangles, lines, and points) into two-dimensional fragments. As it interpolates attributes across a primitive, it calculates a window-space depth value (\(z\)) for each fragment.

When polygon offset is enabled in the rasterizer state, the hardware intercepts this calculated depth value and applies an offset calculation before running the depth test. Because this modification occurs entirely within the rasterizer state:

  • Original mesh geometry remains untouched in vertex buffers and transformation matrices.
  • The offset is applied dynamically per-fragment based on the orientation of the surface relative to the viewpoint.
  • Depth modifications occur before the fragment reaches the depth and stencil tests, ensuring the fragment either reliably passes or fails the depth comparison against existing buffer values.

Configuring the Rasterizer State

OpenGL requires two steps to apply this bias: enabling the appropriate rasterizer capability and supplying the offset parameters.

To activate the state, call glEnable with the token matching the primitive’s rasterization mode:

  • GL_POLYGON_OFFSET_FILL for solid surfaces
  • GL_POLYGON_OFFSET_LINE for wireframe rendering
  • GL_POLYGON_OFFSET_POINT for point primitives

The offset amount is configured using the glPolygonOffset(GLfloat factor, GLfloat units) command. The rasterizer calculates the total depth offset using the following formula:

\[\text{Offset} = (m \times \text{factor}) + (r \times \text{units})\]

  • \(m\) (Maximum Depth Slope): The maximum rate of change in depth relative to screen-space coordinates across the primitive. Polygons viewed at grazing angles have steep slopes, requiring larger depth offsets to separate them reliably. The factor scales with this slope to automatically provide more separation for angled geometry.
  • \(r\) (Minimum Resolvable Difference): The smallest measurable difference in depth that the current depth buffer format can represent. The units parameter multiplies this value to create a constant baseline offset, ensuring separation even when polygons are parallel to the view plane.

Common Implementation Patterns

To draw an overlay or decal cleanly onto an existing surface:

  1. Render the base geometry normally with glPolygonOffset disabled or set to neutral values.
  2. Enable GL_POLYGON_OFFSET_FILL.
  3. Set glPolygonOffset with small positive or negative values (commonly between 1.0 and 2.0 depending on whether using a standard depth test of GL_LESS or reverse-z).
  4. Render the overlay geometry.
  5. Disable GL_POLYGON_OFFSET_FILL to prevent subsequent scene objects from shifting in the depth buffer.
