Hierarchical Z-Buffer Occlusion Culling in OpenGL

Hierarchical Z-Buffering (HZB) enables rapid GPU-driven occlusion culling by testing simplified object bounding boxes against a multi-resolution depth pyramid within an OpenGL compute shader. Instead of relying on slow CPU readbacks or hardware occlusion queries that stall the rendering pipeline, an HZB compute pass tests tens of thousands of bounding volumes in parallel. By selecting a depth mipmap level that corresponds to the screen-space size of an object, the GPU determines visibility using a single texture fetch, selectively writing visible draw commands into an indirect draw buffer before main rendering begins.

The Hierarchical Depth Pyramid

The foundation of HZB is a depth mipmap chain where each texel at mip level \(n+1\) stores the conservative depth of a \(2 \times 2\) block of texels from mip level \(n\). In a standard depth configuration (near = 0, far = 1), conservative occlusion culling requires finding the maximum depth value within the texel neighborhood. If Reverse-Z is employed (near = 1, far = 0, which provides better floating-point precision), the reduction function uses the minimum depth.

In OpenGL, this pyramid is generated immediately after an early depth pre-pass or from the previous frame's depth buffer. A compute shader or a series of downsampling passes reads the source depth buffer and writes to successive mip levels of an image texture (GL_R32F), computing:

\[\text{texel}_{n+1}(x, y) = \max_{i,j \in \{0, 1\}} \left( \text{texel}_n(2x + i, 2y + j) \right)\]

Screen-Space Bounding Box Projection

Within the culling compute shader (glDispatchCompute), each invocation processes one object or meshlet. The compute thread performs the following steps:

  1. Transform Bounding Volume: The eight corners of the object's Axis-Aligned Bounding Box (AABB) in world space are transformed into clip space using the view-projection matrix.
  2. Frustum Culling: If all vertices fall outside the view frustum boundaries, the bounding box is discarded immediately.
  3. Perspective Division and Screen Mapping: Vertices are converted to Normalized Device Coordinates (NDC) by dividing by \(w\). The coordinates are then mapped to \([0, 1]\) screen space to establish a 2D screen-space bounding rectangle defined by \([u_{\min}, v_{\min}]\) and \([u_{\max}, v_{\max}]\).
  4. Determine Nearest Depth: The minimum \(z\) coordinate across all transformed corners in NDC represents the closest point of the bounding box to the camera (\(z_{\text{nearest}}\)).

Constant-Time Footprint Sampling

The key efficiency of HZB is converting a potentially large screen area into a constant number of depth comparisons:

  1. Calculate Dimensions: The pixel width and height of the bounding rectangle are computed using the viewport resolution: \[\text{width} = (u_{\max} - u_{\min}) \times \text{viewWidth}\] \[\text{height} = (v_{\max} - v_{\min}) \times \text{viewHeight}\]
  2. Mip Level Selection: The algorithm selects a mipmap level \(L\) such that the bounding rectangle covers no more than a \(2 \times 2\) pixel area on that level: \[L = \lfloor \log_2(\max(\text{width}, \text{height})) \rfloor\]
  3. Texture Sampling: At mip level \(L\), the compute shader reads the depth values covering the bounding box. Since the mip selection bounds the footprint to roughly \(2 \times 2\) texels, sampling can be done with a small, fixed number of texture gathers or point-samples (typically 4 samples).
  4. Visibility Evaluation: The maximum depth from the sampled footprint is compared against \(z_{\text{nearest}}\). If \(z_{\text{nearest}}\) is greater than the sampled HZB depth, the bounding box lies entirely behind geometry already present in the depth buffer and is marked as occluded.

OpenGL Compute Pass and Indirect Execution

The result of the visibility test directly informs the rendering pipeline without CPU intervention. The compute shader manages an array of DrawElementsIndirectCommand structs stored in a Shader Storage Buffer Object (SSBO):

layout(std430, binding = 0) writeonly buffer DrawCommands {
    DrawElementsIndirectCommand commands[];
};

When an instance passes both frustum and HZB occlusion tests, the compute shader increments an atomic counter (atomicAdd) to allocate an output slot, writes the instance data, and sets the instanceCount parameter of the indirect command.

Following the compute dispatch, a memory barrier is placed via glMemoryBarrier(GL_COMMAND_BARRIER_BIT | GL_SHADER_STORAGE_BARRIER_BIT). The application then executes glMultiDrawElementsIndirect, rendering only the surviving visible geometry with zero CPU-GPU synchronization stalls.
