Per-Target Blending with GL_ARB_draw_buffers_blend

The GL_ARB_draw_buffers_blend extension enhances the OpenGL pipeline by allowing developers to assign distinct blend equations and blend functions to individual draw buffers attached to a Framebuffer Object (FBO). Prior to this extension, Multiple Render Targets (MRT) were constrained to a single, globally applied blend configuration, forcing all attached color attachments to process incoming fragments identically. This article explains how the extension resolves this limitation, the core API functions it introduces, and how it executes separate blending configurations across multiple render targets simultaneously.

The Limitation of Traditional MRT Blending

When Multiple Render Targets were originally introduced to OpenGL, a fragment shader could write color data to several color buffers concurrently using glDrawBuffers. However, the blending stage of the pipeline remained largely monolithic:

  • glBlendFunc and glBlendEquation (including their separate RGB/Alpha variants) applied universally to all enabled color outputs.
  • While GL_EXT_draw_buffers2 allowed toggling blending on or off per target using glEnablei(GL_BLEND, index), you could not specify different source and destination factors or equations for different buffers.

This restriction created significant bottlenecks in rendering techniques like deferred shading or packed G-buffer generation, where one target (such as an accumulation buffer) might require additive blending, while another target (such as a normal or material ID buffer) required standard alpha blending or no blending at all.

Key Indexed API Functions

GL_ARB_draw_buffers_blend eliminates this limitation by introducing indexed versions of the core blend-state commands. Each function accepts a buf parameter representing the index of the draw buffer to configure:

  • glBlendFunciARB(GLuint buf, GLenum src, GLenum dst)
    Sets the source and destination blend factors specifically for the draw buffer specified by buf.

  • glBlendFuncSeparateiARB(GLuint buf, GLenum srcRGB, GLenum dstRGB, GLenum srcAlpha, GLenum dstAlpha)
    Allows independent configuration of the RGB and Alpha source and destination blend factors for a designated draw buffer index.

  • glBlendEquationiARB(GLuint buf, GLenum mode)
    Defines the blend equation (such as GL_FUNC_ADD, GL_FUNC_SUBTRACT, GL_MIN, or GL_MAX) solely for the specified draw buffer.

  • glBlendEquationSeparateiARB(GLuint buf, GLenum modeRGB, GLenum modeAlpha)
    Configures different blend equations for the RGB and Alpha components for a single target index.

Pipeline Execution and Hardware Interaction

When a fragment shader executes, its outputs correspond to the indices defined by glDrawBuffers. At the per-fragment operations stage:

  1. Enable State Check: The pipeline determines whether blending is enabled for target \(i\) via glIsEnabled(GL_BLEND, i).
  2. State Lookup: If enabled, the blending hardware does not refer to global state registers. Instead, it inspects the indexed state table for target \(i\) to retrieve its unique modeRGB, modeAlpha, srcRGB, dstRGB, srcAlpha, and dstAlpha.
  3. Per-Target Evaluation: The incoming fragment output for location \(i\) is blended against the existing color values in attachment \(i\) using those specific parameters, entirely independent of the operations occurring simultaneously on attachment \(j\).

Relationship with Modern OpenGL

The functionality provided by GL_ARB_draw_buffers_blend proved essential for modern deferred rendering pipelines and was integrated directly into the core specification in OpenGL 4.0. In modern OpenGL, the ARB suffix is dropped, making functions like glBlendFunci and glBlendEquationSeparatei standard parts of the API for fine-grained rasterization control.
