OpenGL texelFetch vs texture Coordinate Systems

In OpenGL, fetching color data from a texture is primarily handled via the texture or texelFetch GLSL functions, each utilizing a fundamentally different coordinate system. While texture relies on normalized, floating-point coordinates ranging from 0.0 to 1.0 to sample and filter across a surface, texelFetch uses non-normalized, integer-based texel coordinates mapped directly to the texture's resolution. This distinction determines whether OpenGL applies hardware filtering and wrapping or performs an exact, raw pixel lookup from memory.

The texture Coordinate System: Normalized Floating-Point

The standard texture function takes normalized coordinates, typically represented as a vec2 (for 2D textures) with values spanning from 0.0 to 1.0.

  • Resolution Independence: Regardless of whether an image is 64×64 or 4096×4096, vec2(0.5, 0.5) always targets the exact center of the texture.
  • Filtering and Blending: Because the input is a floating-point value, coordinates often fall between discrete texels. OpenGL uses the configured texture filtering parameters (such as GL_LINEAR or GL_NEAREST_MIPMAP_LINEAR) to interpolate neighboring values.
  • Texture Wrapping: If a coordinate falls outside the [0.0, 1.0] range, the hardware applies predefined wrapping modes (such as GL_REPEAT or GL_CLAMP_TO_EDGE).

The texelFetch Coordinate System: Integer Grid Space

The texelFetch function bypasses the sampler unit and addresses the underlying image array directly using integer texel space, typically via an ivec2 for 2D textures.

  • Resolution Dependent: Coordinates range from 0 to width - 1 along the X-axis, and 0 to height - 1 along the Y-axis. The point ivec2(0, 0) addresses the texel at the lower-left corner of the image.
  • No Filtering: texelFetch treats the texture as a flat, multi-dimensional array. It performs a direct read from memory, meaning no bilinear filtering, trilinear filtering, or blending occurs.
  • Explicit Level of Detail (LOD): Because texelFetch bypasses hardware derivative calculations for mipmapping, you must provide an explicit integer mipmap level as the final argument (e.g., 0 for the base level).
  • No Automatic Wrapping: If you request coordinates outside the valid dimensions [0, size - 1], texelFetch returns an undefined value. Boundary checking must be handled manually within your shader.
