How to Use gl_PointSize in OpenGL Vertex Shaders

This article provides a practical guide to programmatically controlling point dimensions using the built-in gl_PointSize variable in an OpenGL vertex shader. It covers how gl_PointSize interfaces with the rasterizer, the necessary OpenGL context state configurations required to enable it, dynamic calculation methods such as distance attenuation, and hardware limitations to keep in mind.

What is gl_PointSize?

In OpenGL, gl_PointSize is a built-in output variable available exclusively within the vertex shader (and geometry shader, if present). When drawing primitive points using GL_POINTS, the rasterizer produces a square of fragments for each vertex. The gl_PointSize variable is a float that dictates the width and height of this square in screen pixels.

Assigning a value to gl_PointSize allows each individual vertex to dictate its own screen-space size dynamically, rather than relying on a global size specified on the CPU.

Enabling Programmatic Point Sizing

By default, OpenGL ignores vertex shader assignments to gl_PointSize and instead relies on the global state set via glPointSize() on the CPU. To instruct the pipeline to read the size directly from the vertex shader, you must explicitly enable the capability in your application code:

glEnable(GL_PROGRAM_POINT_SIZE);

If this capability is disabled, any value assigned to gl_PointSize inside your shader will have no effect on the final rendered output.

Vertex Shader Implementation

Inside the vertex shader, assigning a value to gl_PointSize is as straightforward as assigning to gl_Position.

Constant Point Size

The following example demonstrates setting a uniform screen size of 15.0 pixels for all vertices:

#version 330 core

layout (location = 0) in vec3 aPos;

uniform mat4 uModelViewProjection;

void main()
{
    gl_Position = uModelViewProjection * vec4(aPos, 1.0);
    gl_PointSize = 15.0; // Sets point size to 15x15 pixels
}

Dynamic Point Size (Distance Attenuation)

A common use case for programmatic point sizing is particle systems or starfields, where points closer to the camera should appear larger than points farther away. Because gl_PointSize operates in window space (pixels), perspective division does not automatically scale it. You must calculate the attenuation manually:

#version 330 core

layout (location = 0) in vec3 aPos;

uniform mat4 uModelView;
uniform mat4 uProjection;
uniform float uBasePointSize;

void main()
{
    // Transform vertex position into view space
    vec4 viewPos = uModelView * vec4(aPos, 1.0);
    
    // Project to clip space
    gl_Position = uProjection * viewPos;
    
    // Calculate distance to camera along the Z axis in view space
    float distance = length(viewPos.xyz);
    
    // Attenuate point size inversely proportional to distance
    gl_PointSize = uBasePointSize / distance;
}

Hardware Limits and Clamping

The graphics hardware enforces upper and lower limits on point sizes. If gl_PointSize is assigned a value outside these boundaries, OpenGL automatically clamps the value to the nearest supported limit.

You can query the supported range on the host machine using:

GLfloat range[2];
glGetFloatv(GL_POINT_SIZE_RANGE, range);
// range[0] is the minimum size, range[1] is the maximum size

Point sizes smaller than 1.0 may cause the primitive to disappear entirely or rasterize inconsistently depending on multisampling settings.

Shaping Points in the Fragment Shader

Because gl_PointSize generates a square region of pixels, square points are rendered by default. To render circular particles, you can inspect the built-in gl_PointCoord variable in the fragment shader.

gl_PointCoord ranges from vec2(0.0, 0.0) at the top-left to vec2(1.0, 1.0) at the bottom-right of the point. Fragments outside a designated radius can be discarded:

#version 330 core

out vec4 FragColor;

void main()
{
    // Center point coordinates around (0, 0)
    vec2 coord = gl_PointCoord - vec2(0.5);
    
    // Discard fragments outside the unit circle
    if (dot(coord, coord) > 0.25)
    {
        discard;
    }

    FragColor = vec4(1.0, 1.0, 1.0, 1.0);
}
