Measuring GPU Execution Time with OpenGL Timer Queries

OpenGL timer queries provide a hardware-level mechanism for measuring the precise duration of GPU workloads without introducing performance-degrading CPU-GPU pipeline stalls. Because the CPU submits commands asynchronously to a command buffer that the GPU executes later, conventional CPU-side timers only track submission latency rather than actual rendering time. By injecting hardware timestamps directly into the GPU pipeline, timer queries isolate and measure the nanosecond-level execution time of specific draw commands.

The Limitation of CPU-Side Profiling

Standard host-side timing mechanisms, such as std::chrono in C++, measure only the time it takes the CPU to record commands into the graphics driver's command buffer. Forcing the CPU to wait for the GPU via synchronization barriers like glFinish() allows CPU timers to measure GPU work, but it forces an artificial pipeline flush, empties the command queue, and invalidates realistic execution metrics like pipeline overlap and cache state.

How Timer Queries Work

OpenGL addresses this synchronization issue using query objects created via glGenQueries(). These queries work through two primary targets: GL_TIME_ELAPSED and GL_TIMESTAMP.

1. Elapsed Time Queries (GL_TIME_ELAPSED)

The GL_TIME_ELAPSED query target measures the total time the GPU spends executing all commands issued between a pair of delimiter calls.

  • Delimitation: You wrap the target draw calls between glBeginQuery(GL_TIME_ELAPSED, queryId) and glEndQuery(GL_TIME_ELAPSED).
  • Hardware Execution: When the GPU reaches the start marker in its command queue, it records an internal hardware clock cycle counter. The GPU continues executing the queued draw commands until it encounters the end marker, at which point it records a second clock counter.
  • Duration Calculation: The GPU computes the delta between the two counter values, converts it to nanoseconds, and stores it in the query object.

2. Timestamp Queries (GL_TIMESTAMP)

Instead of bounding a set of commands with begin and end markers, glQueryCounter(queryId, GL_TIMESTAMP) places a single marker into the GPU stream. When the GPU executes that marker, it writes its current clock value to the query object. By placing two distinct timestamp queries before and after commands, applications can calculate execution duration by subtracting the start timestamp from the end timestamp. This approach also allows developers to correlate GPU events with CPU system time.

Asynchronous Result Retrieval

To prevent CPU stalling, query results are retrieved asynchronously:

  1. Availability Polling: The application queries the status of the operation using glGetQueryObjectiv(queryId, GL_QUERY_RESULT_AVAILABLE, &isAvailable).
  2. Result Extraction: Once the result is available (indicating the GPU has fully processed the bounded commands), the elapsed time is retrieved using glGetQueryObjectui64v(queryId, GL_QUERY_RESULT, &timeElapsedInNanoseconds).

To achieve seamless profiling in real-time applications, developers use double- or triple-buffering for query objects across successive frames. A query issued in frame \(N\) is polled and read in frame \(N+2\) or \(N+3\), ensuring that the GPU finishes rendering before the CPU requests the data, maintaining a completely non-blocking profiling pipeline.
