GL_NEAREST vs GL_LINEAR: OpenGL Filtering Differences

Texture filtering in OpenGL determines how texel colors are mapped to screen pixels when a texture is scaled, magnified, or minified. The two fundamental magnification and minification filtering modes are GL_NEAREST (nearest-neighbor) and GL_LINEAR (bilinear interpolation). This article breaks down the computational differences between these two methods, contrasting their memory access patterns, arithmetic overhead, hardware execution paths, and performance impacts on the GPU.

Memory Access and Bandwidth

The primary divergence between GL_NEAREST and GL_LINEAR lies in memory access complexity:

  • GL_NEAREST: Requires a single memory read per fragment. The GPU determines the UV coordinate, calculates the corresponding texel index via integer rounding/truncation, and fetches only that single texel from the texture cache or VRAM.
  • GL_LINEAR (2D Textures): Requires four texel fetches per fragment. The GPU identifies the coordinate bounding box and reads the four neighboring texels surrounding the sample point.
  • GL_LINEAR (3D Textures): Extends to eight texel fetches per fragment to sample across the X, Y, and Z axes.

While modern GPU texture caches are optimized to mitigate duplicate fetches across adjacent pixels, GL_LINEAR inherently places a higher load on memory bandwidth and increases cache line utilization compared to GL_NEAREST.

Mathematical Operations and Arithmetic Cost

The computational cost of resolving the final pixel color differs substantially in the arithmetic operations (ALU or dedicated hardware logic) required:

  • GL_NEAREST: Requires almost zero floating-point arithmetic. The implementation involves a fast mapping of normalized coordinates \([0.0, 1.0]\) to integer grid indices, usually performed via basic bitwise shifts or fixed-point truncation: \[\text{Index} = \lfloor u \times \text{Width} \rfloor, \lfloor v \times \text{Height} \rfloor\]
  • GL_LINEAR: Performs weighted mathematical interpolation. For a 2D texture, it computes fractional offsets along the axes (\(s\) and \(t\)) and carries out three separate linear interpolations (lerp operations):
    1. Interpolate between top-left and top-right texels using fractional offset \(s\).
    2. Interpolate between bottom-left and bottom-right texels using fractional offset \(s\).
    3. Interpolate between the two resulting values using fractional offset \(t\).
    This process requires multiple multiply-accumulate (MAC) operations per color channel. For standard RGBA textures, this equates to 12 distinct linear interpolations across all four color channels.

Hardware Execution via Texture Mapping Units (TMUs)

Modern graphics hardware handles texture filtering via dedicated silicon known as Texture Mapping Units (TMUs):

  • Hardware Support: TMUs are natively designed to execute bilinear filtering (GL_LINEAR) in hardware without consuming general-purpose shader execution core (ALU) cycles. On modern desktop GPUs, a standard single-precision 2D GL_LINEAR sample often processes with the same or near-identical instruction throughput as GL_NEAREST.
  • Throughput Penalties: When sampling specialized formats (such as 32-bit floating-point textures GL_RGBA32F, deep integer formats, or ultra-wide textures), TMUs often lose single-cycle throughput. In these scenarios, GL_LINEAR can cause pipeline stalls or require multiple clock cycles per sample, whereas GL_NEAREST retains maximum throughput because it bypasses multi-tap blending logic.

Computational Summary

Metric GL_NEAREST GL_LINEAR (2D)

High-Precision Formats High throughput maintained Often incurs hardware throughput penalties

While GL_LINEAR eliminates the pixelated, blocky artifacts associated with GL_NEAREST, it does so by quadrupling the data points read per 2D sample and introducing multi-step floating-point interpolation into the rasterization pipeline.
