OpenGL Viewport Transform: Clip to Window Coordinates

The conversion of clip coordinates to window coordinates in OpenGL is a fundamental step in the graphics rendering pipeline that maps normalized geometric data onto the physical pixels of a screen or framebuffer. This transformation involves two main stages: perspective division, which converts 4D clip coordinates into 3D normalized device coordinates (NDC), followed by the viewport transformation, which scales and shifts these normalized values to match the specified pixel dimensions and depth ranges of the display target.

1. Clip Coordinates and Perspective Division

Before the viewport transform can occur, incoming primitive vertices exist in clip space as four-dimensional homogeneous coordinates:

\[\mathbf{P}_{clip} = (x_c, y_c, z_c, w_c)\]

To convert clip coordinates to Normalized Device Coordinates (NDC), the OpenGL pipeline performs perspective division. This step divides the \(x\), \(y\), and \(z\) components by the homogeneous coordinate \(w_c\):

\[x_{ndc} = \frac{x_c}{w_c}\]

\[y_{ndc} = \frac{y_c}{w_c}\]

\[z_{ndc} = \frac{z_c}{w_c}\]

For any geometry within the view frustum that survives clipping, the resulting NDC values fall inside a standardized cube with coordinates ranging from \(-1.0\) to \(1.0\):

\[-1.0 \le x_{ndc}, y_{ndc}, z_{ndc} \le 1.0\]

2. Viewport Transform Parameters

Once vertices are in NDC, the viewport transformation scales and translates them to window coordinates using parameters specified by two OpenGL functions:

  • glViewport(x, y, width, height): Defines the rectangular region of the target framebuffer where the final image is drawn. Here, \((x, y)\) is the lower-left corner in pixel units, and \(width\) and \(height\) are the dimensions of the viewport.
  • glDepthRange(n, f): Defines the mapping of depth values, where \(n\) represents the near clipping plane and \(f\) represents the far clipping plane. By default, \(n = 0.0\) and \(f = 1.0\).

3. Mapping NDC to Window Coordinates

The viewport transformation applies an affine mapping from the \([-1, 1]\) NDC range to the defined window boundaries. The final window coordinates \((x_w, y_w, z_w)\) are computed with the following formulas:

Horizontal Coordinate (\(x_w\))

The \(x\)-coordinate is scaled to the viewport width and translated to offset \(x\):

\[x_w = \left(\frac{width}{2}\right) x_{ndc} + \left(x + \frac{width}{2}\right)\]

Vertical Coordinate (\(y_w\))

The \(y\)-coordinate is scaled to the viewport height and translated to offset \(y\):

\[y_w = \left(\frac{height}{2}\right) y_{ndc} + \left(y + \frac{height}{2}\right)\]

Depth Coordinate (\(z_w\))

The \(z\)-coordinate is scaled and shifted to fit within the depth buffer range defined by \(n\) and \(f\):

\[z_w = \left(\frac{f - n}{2}\right) z_{ndc} + \left(\frac{f + n}{2}\right)\]

When using the default depth range (\(n = 0\), \(f = 1\)), this simplifies to:

\[z_w = \frac{z_{ndc} + 1}{2}\]

4. Output

The resulting values \((x_w, y_w)\) represent continuous floating-point screen space positions measured in pixels, where the origin \((0, 0)\) is situated at the bottom-left corner of the window. The rasterizer subsequently uses these coordinates to determine which fragments are covered by primitives, while \(z_w\) is passed directly to the depth buffer for occlusion testing.
