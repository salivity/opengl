Displacement Mapping and OpenGL Tessellation Explained

Displacement mapping is a computer graphics technique that physically alters a mesh's topology by offsetting its vertices according to data stored in a height map. Unlike bump or normal mapping, which merely simulate depth by modifying lighting calculations across flat surfaces, displacement mapping produces authentic geometric detail, accurate silhouettes, and realistic self-shadowing. This article explores the mechanics of displacement mapping and details how OpenGL tessellation shaders dynamically subdivide mesh primitives and modify vertex geometry in real time.

What Is Displacement Mapping?

Displacement mapping reads scalar or vector values from an input texture—often called a height map—and uses those values to physically reposition surface vertices. In a standard grayscale height map, black pixels typically represent minimum elevation, white pixels represent maximum elevation, and gray values represent proportional mid-levels.

Because the actual geometry changes, the rendered object demonstrates:

  • Correct silhouettes that accurately reflect the rough or bumpy contours.
  • True self-occlusion, where raised areas block the view of recessed areas from grazing angles.
  • Physically correct self-shadowing when combined with shadow-mapping techniques.

The primary limitation of displacement mapping on static meshes is resolution. A model requires a dense arrangement of vertices to reflect the intricate details of a high-resolution height map. Applying this density globally consumes excessive memory and processing power. This challenge is solved by using hardware tessellation.

The OpenGL Tessellation Pipeline

OpenGL addresses the geometry density problem through its tessellation pipeline, introduced as a core feature in OpenGL 4.0. Rather than processing pre-subdivided, heavy 3D models, OpenGL allows developers to send low-polygon base meshes—defined as "patches"—and dynamically generate new vertices on the GPU.

The tessellation pipeline consists of three distinct stages positioned between the Vertex Shader and the Geometry (or Fragment) Shader:

  1. Tessellation Control Shader (TCS): Determines the level of detail (tessellation levels) for each patch based on factors like distance from the camera or screen coverage.
  2. Primitive Generator (PG): A fixed-function hardware stage that subdivides the patch into a grid of smaller geometric primitives (triangles, quads, or isolines) according to the levels defined by the TCS.
  3. Tessellation Evaluation Shader (TES): Calculates the final positions of all newly generated vertices. This is the exact stage where displacement mapping takes place.

How OpenGL Tessellation Alters Vertex Geometry

The geometric alteration occurs within the Tessellation Evaluation Shader (TES) through a sequence of mathematical operations executed for every generated vertex:

1. Interpolation of Patch Coordinates

The Primitive Generator assigns each new vertex a set of barycentric or normalized parametric coordinates (often represented as gl_TessCoord). The TES uses these coordinates to interpolate properties from the original control points, including the base position, normal vector, and UV texture coordinates:

vec2 uv = interpolate2D(teUV[0], teUV[1], teUV[2]);
vec3 normal = normalize(interpolate3D(teNormal[0], teNormal[1], teNormal[2]));
vec3 basePosition = interpolate3D(tePosition[0], tePosition[1], tePosition[2]);

2. Texture Sampling

With the interpolated UV coordinates established, the TES samples the height map texture to retrieve the displacement magnitude for that specific point on the surface:

float displacement = texture(heightMap, uv).r;

3. Normal-Based Vertex Displacement

The shader calculates the altered vertex position by shifting the base position along the interpolated surface normal vector, scaled by the sampled displacement value and a user-defined scaling factor:

\[\text{Position}_{\text{displaced}} = \text{Position}_{\text{base}} + (\text{Normal} \times \text{Displacement} \times \text{ScaleFactor})\]

In GLSL code, this translates directly to:

vec3 displacedPosition = basePosition + (normal * displacement * displacementScale);

4. Projection to Clip Space

Once the vertex geometry has been physically displaced in object or world space, it is transformed into clip space using the standard Model-View-Projection (MVP) matrix:

gl_Position = projectionMatrix * viewMatrix * vec4(displacedPosition, 1.0);

Advantages of Combining Displacement with Tessellation

Altering vertex geometry through OpenGL tessellation provides significant operational benefits:

  • Adaptive Level of Detail (LOD): Geometry is created dynamically. Patches close to the camera receive high tessellation factors and fine displacement, while distant patches remain coarse, preserving GPU bandwidth and compute cycles.
  • Reduced Storage and Bandwidth: The application sends lightweight, low-poly models over the bus to GPU memory alongside compact textures, eliminating the need to store and transfer multi-million-polygon assets.
  • Dynamic Terrain and Deformation: By updating or animating the displacement texture (such as simulating ocean waves or footprints in snow), the physical geometry of the surface updates instantly on the GPU without CPU-side vertex recalculations.
