OpenGL Vertex to Fragment Link-Time Failures

Link-time failures between the vertex and fragment shader stages in OpenGL typically occur when the interface blocks connecting them fail to satisfy the OpenGL Shading Language (GLSL) cross-stage matching rules. When the pipeline links a program, the driver strictly validates that output interface blocks declared in the vertex shader correspond precisely to input interface blocks in the fragment shader. Discrepancies in block names, member declarations, order, types, or qualifiers violate interface matching requirements, causing the shader program linking step (glLinkProgram) to fail.

Mismatched Interface Block Names

GLSL matches stage interfaces using the block type name, not the instance name. If a vertex shader defines an output block using one name and the fragment shader declares the corresponding input block with a different name, the linker will fail to find a matching partner.

// Vertex Shader
out VertexData {
    vec3 normal;
} vs_out;

// Fragment Shader - FAILS if named differently
in FragmentData { // Must be named 'VertexData'
    vec3 normal;
} fs_in;

Even though the internal layout and instance names may be identical, the block name itself acts as the primary identifier across stages.

Member Declaration, Ordering, and Type Discrepancies

The internal structure of the interface blocks must be an exact match. The linker verifies the following criteria:

  • Member Order: Members within the block must appear in the exact same sequence. Declaring vec3 normal; vec2 uv; in the vertex stage and vec2 uv; vec3 normal; in the fragment stage triggers a link failure.
  • Member Types and Names: Every member must have an identical type and identifier. Changing a type from float to int, changing array sizes, or introducing a typo into a variable name will prevent successful linking.
  • Missing or Extra Members: Both blocks must contain the exact same number of members. Adding an auxiliary variable to the vertex output block without adding it to the fragment input block causes a validation failure.

Interpolation Qualifier Conflicts

Variables passed between the vertex and fragment stages require matching interpolation qualifiers. These include smooth (the default), flat, and noperspective. If a vertex output block member is marked with a qualifier such as flat, the matching member in the fragment stage must explicitly include the same qualifier.

If one stage omits a qualifier while the other specifies a non-default qualifier (like flat), or if the two stages specify conflicting qualifiers, the program will not link.

Auxiliary Storage and Precision Qualifiers

Mismatched auxiliary qualifiers lead to linker errors:

  • Auxiliary Qualifiers: Qualifiers such as centroid or sample alter how values are evaluated during multisampling. These must be declared identically on both the producing vertex block member and the consuming fragment block member.
  • Invariant Qualifiers: If an output variable in the vertex stage is qualified with invariant, the corresponding input variable in the fragment stage must be compatible according to GLSL scoping rules.
  • Precision Qualifiers (OpenGL ES): In OpenGL ES environments, precision qualifiers (lowp, mediump, highp) applied to interface block members must match between the vertex and fragment stages to maintain consistent binary layout expectations.

Explicit Location and Component Aliasing Errors

When using explicit layout qualifiers (e.g., layout(location = 0)), each assigned location must align properly:

  • Overlapping Locations: Assigning conflicting location or component indices to different members within the interface disrupts data slot allocation.
  • Location Inconsistencies: If locations are manually declared on the vertex outputs, matching location qualifiers must be applied consistently to the corresponding fragment inputs. A mismatch between explicit indices breaks the interface link.
