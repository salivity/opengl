How to Set gl_FragDepth in OpenGL Fragment Shaders

In OpenGL, the depth value of a fragment is calculated automatically during rasterization based on its interpolated vertex positions. However, advanced rendering techniques such as raymarching, billboarding, and analytical impostors require replacing this hardware-generated depth with a custom value. By writing directly to the built-in GLSL output variable gl_FragDepth, developers can explicitly author per-fragment depth values to control the depth buffer test and subsequent depth writes. This article covers how to implement gl_FragDepth, how window-space depth is calculated, and how to mitigate the performance penalties associated with manual depth modification.

Basic Implementation

gl_FragDepth is a built-in floating-point variable available in the fragment shader. To write a custom depth value, assign a float in the range \([0.0, 1.0]\), which corresponds to the standard OpenGL window-space depth bounds.

#version 330 core

out vec4 FragColor;

void main()
{
    // Compute your shading color
    FragColor = vec4(1.0, 0.0, 0.0, 1.0);

    // Explicitly write custom depth value (between 0.0 and 1.0)
    gl_FragDepth = 0.5; 
}

If a fragment shader does not write to gl_FragDepth, the hardware defaults to using gl_FragCoord.z. Once you write to gl_FragDepth in any execution branch, you must ensure that all code paths assign a valid value, otherwise the resulting depth for fragments following non-writing paths becomes undefined.

Calculating Normalized Device Coordinates to Window Depth

When computing custom geometry inside the fragment shader (such as finding the intersection point of a ray and a sphere), the resulting world-space or view-space position must be mapped into window-space depth to integrate seamlessly with the existing depth buffer.

  1. Transform the view-space position using the projection matrix to obtain clip-space coordinates.
  2. Divide the clip-space Z by clip-space W to get the Normalized Device Coordinate (\(Z_{ndc}\)).
  3. Transform \(Z_{ndc}\) from \([-1.0, 1.0]\) into window space \([0.0, 1.0]\).
uniform mat4 u_ProjectionMatrix;

float calculateDepth(vec3 viewSpacePosition)
{
    vec4 clipSpacePos = u_ProjectionMatrix * vec4(viewSpacePosition, 1.0);
    float ndcDepth = clipSpacePos.z / clipSpacePos.w;
    
    // Map from [-1.0, 1.0] to [0.0, 1.0]
    return (ndcDepth * 0.5) + 0.5;
}

void main()
{
    vec3 calculatedViewPos = /* ... custom calculation ... */;
    gl_FragDepth = calculateDepth(calculatedViewPos);
    FragColor = vec4(1.0);
}

Performance Impact: Early-Z Rejection

Modern GPUs utilize Early Depth Testing (Early-Z and Hierarchical-Z) to discard occluded fragments before the fragment shader executes, significantly reducing shading overhead.

Assigning a value to gl_FragDepth disables Early-Z by default. Because the GPU cannot predict what value the shader will assign to the depth buffer, it must execute the fragment shader completely for every fragment covering the polygon, regardless of whether it will eventually be occluded.

Restoring Optimizations with Conservative Depth

To regain some early rejection optimizations while still authoring custom depth values, OpenGL 4.2 introduced layout qualifiers for gl_FragDepth (also available via the GL_ARB_conservative_depth extension). These qualifiers provide hints to the GPU regarding the nature of the depth modification:

#version 420 core

// Declare depth layout qualifier before main
layout (depth_greater) out float gl_FragDepth;

out vec4 FragColor;

void main()
{
    // The shader guarantees the depth will only ever be >= gl_FragCoord.z
    gl_FragDepth = gl_FragCoord.z + 0.05;
    FragColor = vec4(0.0, 1.0, 0.0, 1.0);
}

The available layout qualifiers are:

  • layout (depth_any): The default behavior. Depth can change in any direction; early tests are disabled.
  • layout (depth_greater): The new depth value is guaranteed to be greater than or equal to gl_FragCoord.z. This allows the GPU to perform early depth rejection when using GL_LESS or GL_LEQUAL depth comparison functions.
  • layout (depth_less): The new depth value is guaranteed to be less than or equal to gl_FragCoord.z. This enables early rejection when using GL_GREATER or GL_GEQUAL depth comparison functions.
  • layout (depth_unchanged): Guarantees that if gl_FragDepth is written, it equals gl_FragCoord.z, preserving Early-Z regardless of the depth test function.
