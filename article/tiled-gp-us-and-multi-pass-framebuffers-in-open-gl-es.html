Tiled GPUs and Multi-Pass Framebuffers in OpenGL ES

Tiled GPU architectures drastically alter the performance profile of multi-pass framebuffers in OpenGL ES by shifting the primary performance bottleneck from external memory bandwidth to on-chip tile cache management. Unlike traditional immediate-mode GPUs that write each render target directly to system memory (DRAM), tiled architectures process scenes in small, screen-space chunks using ultra-fast on-chip memory. When developers understand how to keep intermediate render passes resident in this local tile storage, multi-pass rendering becomes exceptionally fast and power-efficient; conversely, naive implementations that force tile memory to repeatedly flush to DRAM can incur devastating performance penalties.

The Architectural Difference: Tiled vs. Immediate Rendering

Immediate Mode Renderers (IMRs), common in desktop hardware, process draw calls sequentially across the entire screen. Every rasterized fragment typically reads from and writes directly to external VRAM. In this paradigm, multi-pass techniques—such as deferred shading or post-processing—incur memory bandwidth costs proportional to the size and format of each render target.

Tiled-Based Renderers (TBR) and Tile-Based Deferred Renderers (TBDR), standard in mobile platforms, split the rendering pipeline into two distinct phases:

  1. Binning (Geometry Phase): The GPU processes all vertex data for a frame and categorizes primitives into a screen-space grid of small tiles (typically 16x16 or 32x32 pixels).
  2. Rasterization and Shading Phase: The GPU processes the scene tile by tile. The color, depth, and stencil data for a single tile are loaded into dedicated, low-latency, on-chip SRAM, rendered, and only written back to system RAM once the tile is fully completed.

Impact on Traditional Multi-Pass Framebuffer Objects (FBOs)

In a traditional OpenGL ES multi-pass pipeline, an application renders scene attributes (diffuse, normals, depth) to a multi-target Framebuffer Object (FBO), binds those attachments as textures in a subsequent pass, and computes lighting.

On a tiled GPU, switching FBOs naively disrupts the tiling pipeline:

  • Forced Tile Flushes: Changing the active FBO or issuing commands that read from an attachment currently being rendered forces the GPU to resolve the entire on-chip tile buffer and write it out to external DRAM.
  • Memory Reloads: When the next pass samples that target as a texture, the GPU must fetch those texels back from DRAM across the system memory bus.
  • Thermal and Bandwidth Throttling: On mobile devices where CPU and GPU share system RAM, repeatedly writing and reading large buffers (like 1080p or 4K G-buffers) consumes massive memory bandwidth, draining battery and triggering thermal throttling.

Consequently, multi-pass algorithms that are inexpensive on desktop IMRs can run significantly slower on mobile tiled architectures if implemented using conventional multi-FBO ping-ponging.

Optimizing Multi-Pass for Tiling: Staying On-Chip

Tiled GPUs offer an enormous performance advantage when intermediate data can remain inside the on-chip tile memory across multiple passes. Because on-chip SRAM bandwidth is orders of magnitude faster than system DRAM, intermediate reads and writes can occur essentially for free.

To achieve this in OpenGL ES, specific extensions and paradigms must be utilized:

1. Shader Framebuffer Fetch

Extensions like GL_EXT_shader_framebuffer_fetch and GL_ARM_shader_framebuffer_fetch allow fragment shaders to directly read the current values (color, depth, or stencil) of the pixel being shaded from the tile buffer without allocating external texture samplers. This allows multi-pass algorithms—such as blending equations not natively supported by hardware or multi-pass lighting—to execute entirely within on-chip memory in a single render pass.

2. Pixel Local Storage

Extensions such as GL_EXT_shader_pixel_local_storage allow applications to define a custom, transient memory block allocated directly in tile memory. An application can write intermediate deferred-shading parameters into this local storage during an early sub-pass and read them in a later sub-pass. The intermediate data is never resolved to external RAM, eliminating G-buffer bandwidth costs entirely.

3. Framebuffer Invalidation

When an intermediate buffer is only needed during the current frame (such as a depth buffer used solely to generate a final color image), developers must explicitly notify the driver that this data can be discarded. Using glInvalidateFramebuffer (or glDiscardFramebufferEXT in older versions) prevents the GPU from executing an expensive write-back of the depth/stencil tiles to DRAM at the end of the pass.

4. Multisampled Render to Texture

Standard MSAA on immediate GPUs requires allocating large multisample buffers in memory. Tiled GPUs handle MSAA natively within on-chip tile storage. By utilizing GL_EXT_multisampled_render_to_texture, the GPU resolves multisampled tiles to single-sampled pixels directly on-chip before writing the final result to DRAM, delivering high-quality anti-aliasing with almost no additional memory bandwidth footprint.

Summary

Tiled GPUs polarize the performance of multi-pass framebuffers in OpenGL ES. When treated like immediate-mode desktop GPUs, multi-pass workflows cause frequent DRAM flushes and texture reloads that saturate system bandwidth. However, by structuring passes to execute sequentially within the same tile using framebuffer fetch, pixel local storage, and aggressive buffer invalidation, tiled architectures reduce memory bandwidth to near zero, resulting in superior performance and power characteristics.
