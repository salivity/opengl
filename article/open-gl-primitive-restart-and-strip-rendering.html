OpenGL Primitive Restart and Strip Rendering

In OpenGL, rendering multiple disconnected shapes traditionally required separate draw calls or the insertion of degenerate triangles, both of which introduce performance and memory overhead. Primitive restart is an indexing feature that solves this problem by allowing disconnected primitive strips—such as triangle strips and line strips—to be stitched into a single index buffer and drawn in a single call. This article explains how the primitive restart index is specified, how glEnable(GL_PRIMITIVE_RESTART) operates within the rendering pipeline, and how it directly controls strip primitives.

The Challenge with Strip Primitives

Primitive types like GL_LINE_STRIP and GL_TRIANGLE_STRIP reduce vertex data duplication by sharing vertices between adjacent geometric elements. For example, in a triangle strip, every vertex after the first two creates a new triangle with the preceding two vertices.

However, continuous strips present a challenge when rendering separate, unconnected objects (such as multiple distinct terrain patches or character limbs). Historically, developers had two choices:

  1. Multiple Draw Calls: Break each separate strip into its own draw call (e.g., calling glDrawElements repeatedly), which increases CPU driver overhead.
  2. Degenerate Triangles: Insert duplicate indices to produce zero-area triangles connecting distinct geometry, which inflates index buffer size and consumes vertex-processing bandwidth.

What is Primitive Restart Index Specification?

Primitive restart introduces a designated "sentinel" or "restart" value into the index stream. When OpenGL processes this specific index during an indexed drawing command, it does not fetch vertex data or emit geometry. Instead, it terminates the current primitive and begins a new one with the subsequent vertices.

The restart index is specified using the following command:

void glPrimitiveRestartIndex(GLuint index);

Developers typically choose the maximum representable integer for the active index type to avoid colliding with valid vertex indices:

  • For GL_UNSIGNED_BYTE: 0xFF (255)
  • For GL_UNSIGNED_SHORT: 0xFFFF (65,535)
  • For GL_UNSIGNED_INT: 0xFFFFFFFF (4,294,967,295)

OpenGL 4.3 and OpenGL ES 3.0 introduced GL_PRIMITIVE_RESTART_FIXED_INDEX. When enabled via glEnable(GL_PRIMITIVE_RESTART_FIXED_INDEX), the GPU automatically designates the maximum possible value for the index type as the restart index, eliminating the need to explicitly call glPrimitiveRestartIndex.

How glEnable(GL_PRIMITIVE_RESTART) Controls Strips

The primitive restart behavior is dormant until explicitly activated:

glEnable(GL_PRIMITIVE_RESTART);

Once enabled, OpenGL's primitive assembly stage continuously compares incoming indices against the value set by glPrimitiveRestartIndex.

The Assembly Workflow

When rendering a strip with primitive restart active, the hardware handles the index sequence as follows:

  1. Active Strip Assembly: As normal indices flow through the pipeline, the GPU maintains the state required to chain elements together. For GL_TRIANGLE_STRIP, it tracks the winding order and the previous two vertices.
  2. Sentinel Encountered: When the assembly stage reads the specified restart index, it flushes the current strip and resets its internal state machine. No triangle or line segment is generated for that index.
  3. Strip Reinitialization: The next index encountered is treated as the first vertex of an entirely new strip. For triangle strips, the GPU waits until it has received three new valid indices before emitting the first triangle of the new strip.

Concrete Example

Consider rendering two separate squares using a single GL_TRIANGLE_STRIP call. The index buffer can be structured as:

[0, 1, 2, 3,  0xFFFF,  4, 5, 6, 7]
  • Indices 0, 1, 2, 3: The GPU constructs the first square using two triangles: (0, 1, 2) and (1, 2, 3).
  • Index 0xFFFF: Recognized as the restart value. The strip terminates immediately.
  • Indices 4, 5, 6, 7: A new strip begins. The GPU builds the second square using triangles (4, 5, 6) and (5, 6, 7).

By combining glEnable(GL_PRIMITIVE_RESTART) and glPrimitiveRestartIndex, complex scenes composed of hundreds of disconnected meshes can be merged into a single vertex buffer and rendered using a single glDrawElements or glDrawElementsInstanced invocation, drastically reducing CPU-GPU synchronization overhead.
