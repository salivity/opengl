Vector Displacement Mapping in OpenGL Vertex Processing

Vector displacement mapping (VDM) is an advanced rendering technique that transforms low-polygon meshes into highly detailed 3D surfaces directly on the GPU. Unlike traditional grayscale displacement maps that only push vertices along a single surface normal, VDMs encode full three-dimensional offset vectors within their color channels. By sampling these textures during the OpenGL vertex processing stage—specifically within vertex or tessellation shaders—the graphics pipeline dynamically offsets geometry in any direction, effectively sculpting complex features such as overhangs, cavities, and biological folds onto simple base meshes in real time.

Understanding Vector Displacement vs. Standard Displacement

Standard height maps use a single scalar value per texel to displace geometry strictly along the existing normal vector of a vertex. This limitation prevents standard displacement from creating complex structural silhouettes, such as mushrooms, scales, or deep undercuts.

Vector displacement maps overcome this by storing a three-dimensional displacement vector \((\Delta x, \Delta y, \Delta z)\) across the red, green, and blue color channels of a floating-point texture. Because these vectors can point in any direction relative to the surface, the GPU can pull, push, and slide geometry across multiple axes simultaneously.

The Role of Coordinate Spaces

VDM vectors are typically authored in either object space or tangent space:

  • Object Space: Vector coordinates are relative to the object's local origin. This format is computationally cheap because the vectors can be added directly to the object-space vertex positions. However, it cannot be used on deforming or animated meshes (such as rigged characters), as the displacement will not flex with the underlying skeleton.
  • Tangent Space: Vector coordinates are stored relative to the local surface orientation defined by the normal, tangent, and bitangent vectors (the TBN frame). While this requires transforming the vector in the shader using a TBN matrix, it allows the displaced geometry to deform naturally along with animated surfaces.

Implementing VDM in the OpenGL Pipeline

Because a low-detail mesh possesses too few vertices to display complex displacement on its own, vector displacement in modern OpenGL typically relies on vertex texture fetch (VTF) combined with hardware tessellation.

1. Mesh Subdivision (Tessellation Shaders)

To generate the surface density required for high-frequency details, the low-detail model is first processed through the Tessellation Control Shader (TCS) and Tessellation Evaluation Shader (TES):

  • The TCS calculates dynamic tessellation levels based on camera distance or screen-space size to manage performance.
  • The OpenGL primitive generator subdivides the coarse base patch into a dense grid of new vertices.

2. Texture Sampling in the Tessellation Evaluation Shader

Once the new vertices are generated, displacement is evaluated in the TES (or in a standard Vertex Shader if geometry is pre-tessellated).

// Example snippet within an OpenGL Tessellation Evaluation Shader
in vec3 tePosition[];
in vec2 teTexCoord[];
in vec3 teNormal[];
in vec3 teTangent[];

uniform sampler2D vdmTexture;
uniform float displacementScale;

void main() {
    // Interpolate UV coordinates and TBN vectors across the patch
    vec2 uv = interpolate2D(teTexCoord);
    vec3 N = normalize(interpolate3D(teNormal));
    vec3 T = normalize(interpolate3D(teTangent));
    vec3 B = normalize(cross(N, T));
    mat3 TBN = mat3(T, B, N);

    // Sample the vector displacement texture (unpacking from [0, 1] to [-1, 1] if normalized)
    vec3 displacementVector = texture(vdmTexture, uv).rgb * 2.0 - 1.0;

    // Transform displacement to object space
    vec3 objectSpaceOffset = TBN * (displacementVector * displacementScale);

    // Apply the offset to the interpolated base position
    vec3 finalPosition = interpolate3D(tePosition) + objectSpaceOffset;

    gl_Position = projectionMatrix * viewMatrix * modelMatrix * vec4(finalPosition, 1.0);
}

Normal and Lighting Recalculation

Displacing vertices in three dimensions invalidates the original mesh normals. To maintain realistic lighting, updated surface normals must be derived after displacement:

  1. Analytical Derivative Calculation: If the displacement map is mathematically defined, analytical partial derivatives can yield exact normal vectors.
  2. Finite Difference Sampling: The shader samples the VDM texture at neighboring texels \((\pm \Delta u, \pm \Delta v)\) to reconstruct tangent vectors on the displaced surface, taking the cross product of these vectors to form the new normal.
  3. Accompanying Normal Maps: A secondary, high-resolution normal map matching the displaced topology can be sampled during the fragment shader stage to handle fine micro-surface lighting without requiring continuous vertex recalculation.
