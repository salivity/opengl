How Flat Interpolation Works in OpenGL GLSL

In OpenGL Shading Language (GLSL), the flat interpolation qualifier alters how vertex output values are passed to the fragment shader by completely disabling attribute interpolation across primitives. Instead of blending values across a triangle or line using barycentric coordinates, the graphics pipeline assigns the exact value from a single "provoking vertex" to all fragment invocations generated by that primitive. This mechanism is essential for rendering faceted surfaces, transmitting discrete metadata such as IDs or bitmasks, and passing non-interpolatable data types like integers.

Default Interpolation vs. Flat Shading

By default, attributes passed between shader stages (such as from a vertex shader to a fragment shader) undergo perspective-correct interpolation (equivalent to using the smooth qualifier). In this standard workflow, the rasterizer calculates weighted averages of vertex values based on each fragment's distance from the primitive's vertices.

When the flat qualifier is applied, this blending process is bypassed:

// Vertex Shader
flat out int vObjectID;
flat out vec3 vFacetNormal;

// Fragment Shader
flat in int vObjectID;
flat in vec3 vFacetNormal;

The rasterizer evaluates the primitive, identifies the designated provoking vertex, and broadcasts that vertex's exact attribute values to every fragment produced by the rasterization process.

The Role of the Provoking Vertex

Because a primitive (such as a triangle or line) contains multiple vertices with potentially different attribute values, the pipeline must pick one vertex to represent the entire primitive. This vertex is known as the provoking vertex.

OpenGL governs which vertex acts as the provoking vertex depending on primitive topology and the state set by glProvokingVertex():

  • First-Vertex Convention (GL_FIRST_VERTEX_CONVENTION): The first vertex defined in the primitive index sequence serves as the provoking vertex.
  • Last-Vertex Convention (GL_LAST_VERTEX_CONVENTION): The last vertex defined serves as the provoking vertex (default in core OpenGL contexts).

For example, in a triangle strip defined by vertices [0, 1, 2, 3]:

  • The first triangle (0, 1, 2) uses vertex 2 under the last-vertex rule.
  • The second triangle (1, 2, 3) uses vertex 3.

Every fragment rendered for a given triangle will read the attributes associated strictly with that triangle's provoking vertex.

Mandatory Usage with Integer and Non-Float Types

GLSL requires the flat qualifier for data types that cannot be mathematically interpolated in a meaningful way. Any variable passed between pipeline stages with the following types must be explicitly marked as flat:

  • Signed and unsigned integers (int, uint)
  • Integer vectors (ivec2, ivec3, ivec4, uvec2, etc.)
  • Double-precision integers or booleans passed across stages

Attempting to pass an int or uint from a vertex shader to a fragment shader without the flat qualifier results in a shader compilation or linking error.

Hardware and Pipeline Implications

  1. Elimination of Barycentric Math: The rasterizer skips attribute weighting and perspective division for attributes marked with flat. The pipeline simply reads the memory footprint corresponding to the provoking vertex and copies it directly to the fragment input registers.
  2. Aliasing Across Shared Vertices: When indexing geometry via an element buffer, sharing vertices across adjacent triangles can lead to unintended values if different triangles share a provoking vertex. To avoid data bleeding between adjacent facets, models relying on flat visual attributes often duplicate vertices to ensure each primitive has independent provoking vertex data.
