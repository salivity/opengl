OpenGL Blending Equation Operations Explained

The OpenGL blending equation API governs how incoming fragment values (source) are mathematically combined with existing pixels in the framebuffer (destination). By utilizing functions like glBlendEquation and glBlendEquationSeparate, developers can configure fundamental arithmetic modes—including addition, subtraction, reverse subtraction, minimum, and maximum—to achieve transparency, compositing effects, and custom rendering passes.

The Blending Formula Context

Blending in OpenGL processes color components (\(R, G, B, A\)) according to the following general structure:

\[\text{Result} = \text{SourceTerm} \ \mathbf{op} \ \text{DestinationTerm}\]

Where:

  • \(\text{SourceTerm}\) represents the incoming fragment color multiplied by a source factor (\(C_s \times F_s\)), configured via glBlendFunc or glBlendFuncSeparate.
  • \(\text{DestinationTerm}\) represents the existing framebuffer color multiplied by a destination factor (\(C_d \times F_d\)).
  • \(\mathbf{op}\) represents the mathematical operation set by glBlendEquation.

Core Mathematical Operations

The glBlendEquation(GLenum mode) function configures the \(\mathbf{op}\) applied to all color channels. OpenGL supports five core operations:

1. Addition (GL_FUNC_ADD)

This is the default blending mode in OpenGL. It calculates the sum of the source and destination terms:

\[\text{Color}_{\text{result}} = (C_s \times F_s) + (C_d \times F_d)\]

This mode is used for standard alpha blending, transparency, additive glows, and particle systems.

2. Subtraction (GL_FUNC_SUBTRACT)

Subtracts the destination term from the source term:

\[\text{Color}_{\text{result}} = (C_s \times F_s) - (C_d \times F_d)\]

Results below zero are clamped to zero. This operation is useful for inverted effects, darkening, or shadow-mask calculations.

3. Reverse Subtraction (GL_FUNC_REVERSE_SUBTRACT)

Subtracts the source term from the destination term:

\[\text{Color}_{\text{result}} = (C_d \times F_d) - (C_s \times F_s)\]

This operation is frequently used to remove light or color contribution from an existing framebuffer image based on the incoming fragment's properties.

4. Minimum (GL_MIN)

Calculates the component-wise minimum between the source color and the destination color:

\[\text{Color}_{\text{result}} = \min(C_s, C_d)\]

In standard OpenGL specifications, when GL_MIN is selected, the blending factors (\(F_s\) and \(F_d\)) are ignored; only the unmodified source and destination color components are evaluated. This mode produces darkening effects without requiring explicit blend weight calculations.

5. Maximum (GL_MAX)

Calculates the component-wise maximum between the source color and the destination color:

\[\text{Color}_{\text{result}} = \max(C_s, C_d)\]

Similar to GL_MIN, the blending factors are ignored. The hardware compares each channel independently and writes the higher value, making it effective for light-accumulation algorithms and silhouette overlays.

Independent RGB and Alpha Equations

To provide finer control, the OpenGL API includes glBlendEquationSeparate(GLenum modeRGB, GLenum modeAlpha). This function allows developers to apply different mathematical operations to the color channels (\(R, G, B\)) and the opacity channel (\(A\)).

For example, a pipeline can be configured to add incoming color channels while tracking the maximum alpha value:

glBlendEquationSeparate(GL_FUNC_ADD, GL_MAX);

All five operations (GL_FUNC_ADD, GL_FUNC_SUBTRACT, GL_FUNC_REVERSE_SUBTRACT, GL_MIN, and GL_MAX) can be assigned independently to either parameter.
