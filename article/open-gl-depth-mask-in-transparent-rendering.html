OpenGL Depth Mask in Transparent Rendering

In OpenGL, rendering transparent objects correctly requires balancing depth testing with depth writing to prevent visual artifacts. When rendering translucent surfaces, developers use the depth mask function, glDepthMask(GL_FALSE), to turn off writes to the depth buffer while keeping the depth test active. This article explains how the depth mask operates at the hardware level, why depth writing breaks transparency, and how disabling it preserves the visibility of geometry situated behind transparent surfaces.

The Role of the Depth Buffer and the Depth Mask

The OpenGL depth buffer (or Z-buffer) stores depth values for every pixel on the screen to determine visibility. During standard rendering, each incoming fragment undergoes a depth test: its depth value is compared against the value currently stored in the depth buffer. If the test passes, the fragment's color is written to the color buffer, and its depth value overwrites the existing value in the depth buffer.

The depth mask controls whether this second step—the write operation—takes place. The function glDepthMask accepts a boolean parameter:

  • glDepthMask(GL_TRUE): Enables writing to the depth buffer (default state).
  • glDepthMask(GL_FALSE): Disables writing to the depth buffer while leaving the current depth buffer data completely read-only.

Why Transparent Render Passes Fail with Depth Writes Enabled

When drawing opaque objects, writing to the depth buffer is necessary to prevent objects that are further away from drawing over objects that are closer. However, transparent objects allow light to pass through, meaning any geometry located behind a transparent surface must remain visible.

If a transparent fragment writes its depth to the depth buffer:

  1. It registers itself as the closest surface for that pixel.
  2. Any subsequent fragments processed behind that transparent surface will fail the depth test.
  3. Those background fragments will be discarded entirely, creating an unnatural "cutout" artifact where objects behind transparent surfaces vanish instead of being blended.

How glDepthMask(GL_FALSE) Solves the Problem

Setting glDepthMask(GL_FALSE) decouples the depth test from the depth write operation. During a transparent render pass:

  1. Depth Testing Stays Active: The transparent fragment's depth is still compared against the depth buffer. If an opaque object is in front of the transparent surface, the transparent fragment fails the test and is discarded, preventing it from rendering in front of solid walls or objects.
  2. Color Blending Occurs: If the fragment passes the depth test, it proceeds to the blending stage (configured via glBlendFunc), combining its color with the pixels already in the color buffer.
  3. Depth Buffer Remains Unaltered: Because the depth mask is set to false, the fragment's depth value is never written to the Z-buffer. The depth buffer continues to store the depth of the nearest opaque surface behind the transparency.

The Standard Two-Pass Rendering Pipeline

To achieve correct rendering, graphics engines typically organize their render loop into two distinct passes:

  1. Opaque Pass:
    • glDepthMask(GL_TRUE) is enabled.
    • glEnable(GL_DEPTH_TEST) is enabled.
    • All opaque geometry is rendered. The depth buffer is fully populated with the closest solid surfaces.
  2. Transparent Pass:
    • glEnable(GL_BLEND) is enabled to allow alpha blending.
    • glDepthMask(GL_FALSE) is set to make the depth buffer read-only.
    • Transparent objects are sorted and drawn in back-to-front order.
    • Transparent fragments test against the solid geometry in the depth buffer to avoid rendering through walls, but they do not overwrite the depth values, allowing multiple layers of transparency to blend over the background.

Once the transparent pass completes, glDepthMask(GL_TRUE) is restored so subsequent frames or depth-clearing operations can write to the buffer as expected.
