Pixel Local Storage on Tiled Mobile GPUs in OpenGL ES

Pixel Local Storage (PLS) is an OpenGL ES extension that enables high-performance, multi-pass rendering pipelines on mobile devices by granting fragment shaders direct access to fast, on-chip tile memory. By keeping intermediate data—such as G-buffer attributes in deferred rendering—strictly within the GPU's local tile cache across draw calls, PLS eliminates the need to write intermediate render targets to external system memory (DRAM). This architectural optimization significantly reduces memory bandwidth, lowers latency, and minimizes heat and power consumption on mobile hardware.

Mobile Tiled Architectures (TBDR)

To understand Pixel Local Storage, one must first understand mobile GPU architectures, predominantly Tile-Based Deferred Rendering (TBDR) or Tile-Based Rendering (TBR). Unlike desktop GPUs that typically process frames in immediate mode across a unified memory bus, mobile GPUs divide the viewport into small grids or tiles (typically 16x16 or 32x32 pixels).

In a tiled pipeline, geometry processing occurs first to bin primitives into their respective screen-space tiles. The GPU then processes each tile sequentially. Rasterization, depth testing, and fragment shading take place entirely within extremely fast, low-power, on-chip SRAM cache allocated for that specific tile. Only when all rendering commands for the tile are complete does the GPU "resolve" the final color data, writing it out to the system's external DRAM.

The Problem with Traditional Multi-Pass Rendering

Complex techniques like deferred shading or order-independent transparency traditionally rely on Multiple Render Targets (MRT). In a standard desktop OpenGL pipeline, the geometry pass outputs surface properties (such as albedo, world-space normals, roughness, and depth) into several texture attachments in VRAM. Subsequent lighting passes sample these textures to compute the final pixel color.

On mobile devices, this approach creates a major performance bottleneck:

  1. The geometry pass writes megabytes of intermediate G-buffer data from on-chip tile memory out to external DRAM.
  2. The lighting pass reads that identical G-buffer data back from DRAM into the GPU.
  3. The final lit image is written to DRAM once more.

This continuous round-trip to external memory saturates system bus bandwidth, drains battery life, and causes thermal throttling on mobile devices.

What is Pixel Local Storage?

Pixel Local Storage (introduced primarily via extensions like GL_EXT_shader_pixel_local_storage and GL_EXT_shader_pixel_local_storage2) provides an API bridge to access the on-chip tile SRAM directly within fragment shaders.

Rather than treating the tile cache as a temporary staging ground that must be cleared or flushed between render passes, PLS reserves a dedicated block of storage per pixel (typically 16 to 128 bytes, depending on the GPU implementation) that persists across multiple draw passes within the same tile lifecycle.

In GLSL, PLS is defined using special storage blocks:

#extension GL_EXT_shader_pixel_local_storage : require

__pixel_localEXT FragDataLocal {
    layout(rgb10_a2) vec4 albedo;
    layout(rgb10_a2) vec4 normal;
    layout(r32f) float depth;
} gbuffer;

A fragment shader in an initial pass writes its computed properties directly to this block. Subsequent fragment shaders operating at the exact same screen coordinates in a later pass can immediately read from and modify these variables without incurring a texture lookup or memory read from DRAM.

How PLS is Leveraged in OpenGL ES

Developers leverage PLS primarily to execute single-pass deferred shading and complex blending operations efficiently:

  1. G-Buffer Construction: The application binds a single framebuffer without multiple heavy texture attachments. During the geometry draw calls, surface attributes are packed and stored into the local storage variables.
  2. Local Lighting Evaluation: Without changing the framebuffer or flushing tile data, the application executes a full-screen pass or light-volume geometry. The lighting fragment shader reads the packed attributes directly from the local storage variables, calculates the illumination model, and updates the local data.
  3. Resolve: At the end of the tile's processing, only the final computed color values are written out to the standard color attachment bound to external DRAM. The intermediate attributes in the pixel local storage are simply discarded.

Advantages and Architectural Impact

  • Bandwidth Elimination: G-buffer data never leaves the physical GPU die. Memory bandwidth is reduced strictly to the cost of loading geometry and writing the final framebuffer pixels once.
  • Power Efficiency: Off-chip memory access is one of the most energy-expensive operations on mobile SOCs. Retaining data in on-chip SRAM drastically improves battery efficiency and reduces device heat.
  • Lower Memory Footprint: Because intermediate buffers do not require full-screen texture allocations in main memory, the overall RAM footprint of the application is considerably reduced.

While Pixel Local Storage began as vendor-specific extensions (often associated with ARM Mali GPUs), its core methodology established the foundation for modern graphics APIs. Concepts like Vulkan Subpasses and Input Attachments directly mirror the execution model of PLS, ensuring that mobile tiled architectures remain capable of executing desktop-class rendering techniques efficiently.
