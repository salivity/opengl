Color Grading with 3D LUTs in OpenGL Shaders

This article explains how 3D lookup tables (LUTs) transform color grading pipelines within real-time rendering systems. It covers the structure of a 3D color texture, the mechanism of using source fragment colors as texture coordinates, the importance of hardware trilinear filtering, and the implementation details required inside an OpenGL fragment shader.

Understanding the 3D LUT Texture

A 3D LUT acts as a discrete color transformation lattice. Instead of storing spatial image data, a 3D LUT texture organizes colors along a three-dimensional coordinate system corresponding to Red, Green, and Blue channels. Standard dimensions for real-time applications are typically \(16 \times 16 \times 16\), \(32 \times 32 \times 32\), or \(64 \times 64 \times 64\) voxels.

In OpenGL, this data is uploaded to the GPU using the target GL_TEXTURE_3D. Each point in the grid contains an RGB color representing the transformed output color for that specific input coordinate.

Hardware Interpolation and Sampling

When an input pixel has an intermediate color that falls between the discrete points defined in the LUT grid, OpenGL handles the approximation through hardware trilinear interpolation. Configuring the texture parameters with GL_LINEAR filtering enables this behavior:

glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_3D, GL_TEXTURE_WRAP_R, GL_CLAMP_TO_EDGE);

Using GL_CLAMP_TO_EDGE prevents sampling artifacts at the extreme values (pure black or peak saturation/brightness).

Coordinate Mapping and Texel Offsetting

Because texture coordinates in OpenGL span the range \([0.0, 1.0]\), the unprocessed fragment color \((R, G, B)\) directly corresponds to the texture sampling coordinates \((U, V, W)\). However, directly sampling with the raw color values causes a slight distortion near the boundaries because texel centers are located at half-texel offsets rather than at \(0.0\) and \(1.0\).

To sample accurately across an \(N\)-sized dimension, the coordinate must be scaled and shifted:

\[\text{Coord} = \frac{\text{Color} \cdot (N - 1) + 0.5}{N}\]

For example, in a \(32^3\) LUT:

  • Scale factor: \(31.0 / 32.0\)
  • Offset: \(0.5 / 32.0\)

Applying this correction ensures that an input of \((0.0, 0.0, 0.0)\) lands directly at the center of the first texel, and \((1.0, 1.0, 1.0)\) lands at the center of the final texel.

Fragment Shader Implementation

The fragment shader takes the rendered scene texture, retrieves the base color, applies the coordinate offset, and queries the 3D LUT texture via a sampler3D.

#version 330 core

in vec2 TexCoords;
out vec4 FragColor;

uniform sampler2D sceneTexture;
uniform sampler3D lutTexture;
uniform float lutSize; // e.g., 32.0

void main()
{
    vec4 baseColor = texture(sceneTexture, TexCoords);

    // Apply texel-center adjustment
    vec3 scale = vec3((lutSize - 1.0) / lutSize);
    vec3 offset = vec3(1.0 / (2.0 * lutSize));
    vec3 lutCoords = baseColor.rgb * scale + offset;

    // Sample the transformed color
    vec3 gradedColor = texture(lutTexture, lutCoords).rgb;

    FragColor = vec4(gradedColor, baseColor.a);
}

Performance Advantages

Using a 3D LUT texture condenses multiple expensive mathematical operations—such as contrast curves, saturation shifts, split-toning, and color matrix multiplications—into a single \(O(1)\) memory lookup. Hardware-accelerated trilinear filtering ensures the transformation remains smooth and artifact-free without increasing arithmetic load on the GPU.
