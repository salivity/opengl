OpenGL Depth Testing and Visible Surface Determination

OpenGL resolves visible surface determination primarily through depth testing, an implementation of the classic Z-buffering algorithm. As 3D geometry is projected onto a 2D viewport, overlapping surfaces must be sorted so that closer objects correctly occlude those farther away. OpenGL achieves this automatically at the per-fragment level by storing depth values in a dedicated buffer and comparing the depth of incoming fragments against existing values before writing to the screen.

The Depth Buffer

The foundation of depth testing in OpenGL is the depth buffer (or Z-buffer). This buffer shares the same width and height as the color buffer (the screen target), but instead of color information, each pixel stores a floating-point depth value. These values typically range from 0.0 (representing the near clipping plane) to 1.0 (representing the far clipping plane). When a frame begins, the depth buffer is typically cleared to 1.0 using glClear(GL_DEPTH_BUFFER_BIT).

The Depth Testing Process

Depth testing occurs during the per-fragment operations stage of the OpenGL pipeline, after the fragment shader executes:

  1. Generation: When a primitive (such as a triangle) is rasterized, OpenGL interpolates the \(z\)-coordinate across its surface in normalized device coordinates (NDC) and maps it to the viewport's depth range, producing a depth value for each fragment (gl_FragCoord.z).
  2. Comparison: The incoming fragment's depth value is compared against the depth value already stored at the corresponding \((x, y)\) coordinate in the depth buffer.
  3. Evaluation: The outcome depends on a configured depth comparison function (set via glDepthFunc()). By default, OpenGL uses GL_LESS, meaning the test passes if the incoming fragment's depth value is strictly less than the value currently in the buffer.
  4. Update or Discard: If the test passes, the fragment replaces the current pixel in the color buffer, and its depth value overwrites the old value in the depth buffer. If the test fails, the fragment is immediately discarded, preventing occluded geometry from being drawn.

Configuration and Control

Depth testing is disabled by default in OpenGL and must be explicitly enabled:

  • Enabling Testing: Calling glEnable(GL_DEPTH_TEST) activates depth evaluation.
  • Comparison Function: glDepthFunc(GLenum func) specifies the comparison condition, with common options including GL_LESS, GL_LEQUAL, GL_GREATER, and GL_ALWAYS.
  • Depth Mask: glDepthMask(GL_FALSE) can disable writing to the depth buffer while still testing against it, which is particularly useful when rendering transparent objects or skyboxes.

Early Depth Testing

Traditionally, depth testing occurs after the fragment shader runs, which can waste GPU cycles calculating colors for fragments that will ultimately be discarded. Modern OpenGL implementations support "Early Depth Testing," where the depth test is evaluated before the fragment shader executes. This optimization is applied automatically by the driver when the fragment shader does not modify depth explicitly (e.g., without writing to gl_FragDepth) or can be enforced explicitly in GLSL using the layout(early_fragment_tests) in; qualifier.
