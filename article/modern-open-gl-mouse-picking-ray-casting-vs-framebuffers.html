Modern OpenGL Mouse Picking: Ray Casting vs Framebuffers

Mouse picking in modern OpenGL translates 2D screen coordinates from user input into interactions with 3D scene geometry, primarily achieved through mathematical ray casting or custom integer ID framebuffers. Ray casting transforms screen pixels into world-space rays using the inverse projection and view matrices, checking for intersections against bounding volumes or mesh polygons. Conversely, custom integer ID picking utilizes an off-screen Framebuffer Object (FBO) where every pickable object renders its unique ID directly to an integer-formatted texture, allowing instant pixel-perfect retrieval at the cursor position.

Ray Casting

Ray casting computes a line in 3D world space corresponding to the mouse cursor's 2D position and tests it against the geometric bounds of objects in the scene.

1. Screen to World-Space Transformation

To cast a ray, screen coordinates must be mapped back to world space using the camera's inverse view and projection matrices:

  1. Normalized Device Coordinates (NDC): Map mouse pixel coordinates \((x, y)\) to the range \([-1, 1]\). \[\text{ndc}_x = \frac{2x}{\text{width}} - 1, \quad \text{ndc}_y = 1 - \frac{2y}{\text{height}}\]
  2. Homogeneous Clip Space: Create a 4D vector pointing forward along the z-axis (e.g., \(z = -1\) for the near plane, \(w = 1\)).
  3. Eye/View Space: Multiply the clip-space ray by the inverse projection matrix \((P^{-1})\) and set \(z = -1, w = 0\) to define a direction vector.
  4. World Space: Multiply by the inverse view matrix \((V^{-1})\) and normalize the resulting vector to yield the final ray direction (\(D\)). The camera position serves as the ray origin (\(O\)).

2. Intersection Testing

Once defined by \(R(t) = O + tD\), the ray is evaluated against scene geometry:

  • Bounding Volumes: Hierarchical checks using Axis-Aligned Bounding Boxes (AABB) or bounding spheres quickly eliminate non-colliding objects.
  • Triangle Meshes: When precision is required, algorithms like Möller–Trumbore evaluate ray-triangle intersections.
  • Pros: Highly dynamic, runs completely decoupled from the rendering pipeline, integrates naturally with CPU physics engines, and does not require rendering an extra pass.
  • Cons: Becomes computationally expensive on the CPU when evaluating high-density meshes unless accelerated by spatial partition structures like BVHs or octrees.

Custom Integer ID Framebuffers

Integer ID picking, often called color picking or FBO picking, delegates the selection logic to the GPU rendering pipeline.

1. Framebuffer and Texture Setup

Instead of reading typical color channels, modern OpenGL allows integer attachments:

  • Generate an FBO using glGenFramebuffers.
  • Attach an integer texture, typically using the GL_R32UI (single-channel 32-bit unsigned integer) format via glTexImage2D.
  • Attach a standard depth buffer (GL_DEPTH_COMPONENT) so normal depth testing applies.

2. The Pick Render Pass

During a selection pass, the scene is drawn to the off-screen FBO:

  • Each mesh or entity is assigned a unique 32-bit integer identifier.

  • In the fragment shader, declare an unsigned integer output variable instead of a standard color vector:

    #version 330 core
layout(location = 0) out uint FragID;
uniform uint u_ObjectID;

void main() {
    FragID = u_ObjectID;
}

  • Standard depth testing resolves occlusions, ensuring the closest object's ID occupies the final pixel.

3. Reading the ID

When an interaction occurs, retrieve the integer value at the mouse coordinates:

glBindFramebuffer(GL_READ_FRAMEBUFFER, pickingFBO);
glReadBuffer(GL_COLOR_ATTACHMENT0);

uint32_t pixelID = 0;
glReadPixels(mouseX, viewportHeight - mouseY, 1, 1, GL_RED_INTEGER, GL_UNSIGNED_INT, &pixelID);

glBindFramebuffer(GL_READ_FRAMEBUFFER, 0);
  • Pros: Provides pixel-perfect accuracy automatically, inherently accounting for complex shaders, skeletal animations, and alpha-tested geometry without extra math.
  • Cons: Calling glReadPixels causes a synchronous CPU-GPU stall, forcing the CPU to wait until the GPU pipeline drains. This can be mitigated by offloading reads using asynchronous Pixel Buffer Objects (PBOs) or by restricting the pick pass strictly to clicks rather than continuous cursor movement.

Choosing Between the Two Approaches

  • Use Ray Casting when user interactions drive physics, require continuous hovering, need intersection points and surface normals, or when operating in environments where rendering passes are constrained.
  • Use Integer ID Framebuffers in dense CAD/DCC software, level editors, or scenes with complex, animated, or irregular geometry where mathematical intersection tests would be too expensive or difficult to implement manually.
