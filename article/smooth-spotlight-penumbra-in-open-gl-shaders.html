Smooth Spotlight Penumbra in OpenGL Shaders

Creating smooth penumbra transitions along spotlight edges in OpenGL fragment shaders is achieved primarily through cubic Hermite interpolation, implemented via the GLSL smoothstep function. This article explains the mathematics behind simulating realistic spotlight cones, how angular falloff is modeled using vector dot products, and the precise shader calculations required to blend the light intensity seamlessly between the inner and outer cutoff boundaries.

The Spotlight Cone Model

A basic spotlight model relies on a light direction vector, a light position, and a cone cutoff angle. In 3D space, the angle \(\theta\) between the spotlight's pointing direction and the vector pointing from the light to the surface fragment determines whether the fragment is illuminated.

Rather than calculating expensive inverse trigonometric functions (acos) to find \(\theta\), shaders calculate the cosine of the angle using the dot product of two normalized vectors:

\[\cos(\theta) = \hat{L}_{dir} \cdot \hat{D}\]

  • \(\hat{L}_{dir}\) is the normalized vector from the spotlight position to the fragment.
  • \(\hat{D}\) is the normalized spotlight direction vector.

A binary cutoff compares \(\cos(\theta)\) against the cosine of the cutoff angle (\(\cos(\phi)\)). However, this creates an unnatural, razor-sharp boundary.

Defining Inner and Outer Cutoffs

To create a penumbra (the soft transition zone), the spotlight defines two distinct angles:

  1. Inner Cutoff (\(\phi_{inner}\)): The core cone where the spotlight shines at maximum intensity (\(1.0\)).
  2. Outer Cutoff (\(\phi_{outer}\)): The boundary beyond which no light reaches (\(0.0\)).

Because the cosine function decreases as the angle increases from \(0^\circ\) to \(90^\circ\):

\[\cos(\phi_{inner}) > \cos(\phi_{outer})\]

Any fragment whose \(\cos(\theta)\) falls between \(\cos(\phi_{outer})\) and \(\cos(\phi_{inner})\) lies within the penumbra and requires an attenuation factor between \(0.0\) and \(1.0\).

Linear Interpolation and Its Limitations

A basic approach calculates a linear interpolation factor:

\[\epsilon = \cos(\phi_{inner}) - \cos(\phi_{outer})\] \[I = \text{clamp}\left(\frac{\cos(\theta) - \cos(\phi_{outer})}{\epsilon}, 0.0, 1.0\right)\]

While this creates a gradient, linear interpolation exhibits a first-derivative discontinuity (\(C^0\) continuity) at the transition points. This results in visible, harsh "mach bands" where the falloff begins and ends.

Smooth Hermite Interpolation (smoothstep)

To eliminate hard edges, OpenGL shaders apply cubic Hermite interpolation, commonly represented by the standard GLSL smoothstep polynomial:

\[S(x) = 3x^2 - 2x^3\]

Where \(x\) is normalized between \(0.0\) and \(1.0\). The derivative of this function:

\[S'(x) = 6x - 6x^2\]

evaluates to zero at both \(x = 0\) and \(x = 1\). This zero-derivative boundary (\(C^1\) continuity) ensures a completely smooth transition into both the full-intensity core and the total darkness outside the cone.

GLSL Fragment Shader Implementation

In GLSL, the smoothstep function inherently handles both normalization and cubic Hermite interpolation. The spotlight intensity is computed as follows:

// Uniforms passed to the shader
uniform vec3 lightPos;
uniform vec3 lightDir;
uniform float innerCutOff; // cos(phi_inner)
uniform float outerCutOff; // cos(phi_outer)

// Fragment calculations
vec3 lightToFrag = normalize(fragPos - lightPos);
float theta = dot(lightToFrag, normalize(lightDir));

// Calculate smooth penumbra factor
float intensity = smoothstep(outerCutOff, innerCutOff, theta);

// Apply intensity to final lighting output
vec3 diffuse = intensity * lightColor * diff;
vec3 specular = intensity * lightColor * spec;

Because outerCutOff represents a smaller cosine value than innerCutOff, passing outerCutOff as the lower edge and innerCutOff as the upper edge maps the cosine values correctly from 0.0 (outside) to 1.0 (inside). This mathematical method produces physically plausible soft spotlight perimeters with minimal computational overhead.
