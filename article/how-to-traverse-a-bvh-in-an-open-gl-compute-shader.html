How to Traverse a BVH in an OpenGL Compute Shader

Traversing Bounding Volume Hierarchies (BVHs) within an OpenGL compute shader enables hardware-agnostic ray tracing by using standard compute pipelines instead of dedicated ray tracing extensions. This process requires flattening the hierarchical tree into GPU-accessible buffers, implementing ray-box and ray-primitive intersection routines, and managing a traversal algorithm within the shader's execution model. By utilizing Shader Storage Buffer Objects (SSBOs) to store nodes and primitives, a compute shader can efficiently query scene geometry per thread to find ray intersections.

Flattening and Uploading the BVH

Compute shaders cannot navigate native CPU memory pointers, so the BVH tree must be flattened into a linear array. This structure is typically stored and accessed via an SSBO.

A linear BVH node typically contains:

  • Axis-Aligned Bounding Box (AABB) bounds: vec3 min and vec3 max.
  • Child or leaf information packed into integer indices. For example, an interior node can store an index to its left child (with the right child placed immediately adjacent at left + 1), while a leaf node stores an offset into a primitive buffer and the number of primitives it contains.

Negative values or bit-flags in the child index field are commonly used to distinguish interior nodes from leaf nodes.

struct BVHNode {
    vec3 aabbMin;
    int leftChild; // Leaf if negative, interior node index if positive
    vec3 aabbMax;
    int primitiveCount; // Number of triangles if leaf
};

layout(std430, binding = 0) readonly buffer NodeBuffer {
    BVHNode nodes[];
};

layout(std430, binding = 1) readonly buffer TriangleBuffer {
    vec4 vertices[]; // Packed triangle vertices
};

Ray-Box Intersection

Efficient traversal relies on the slab method for ray-AABB intersection. Precomputing the reciprocal of the ray direction avoids costly divisions inside the traversal loop:

bool intersectAABB(vec3 rayOrigin, vec3 invDir, vec3 boxMin, vec3 boxMax, float tCurrent) {
    vec3 t0 = (boxMin - rayOrigin) * invDir;
    vec3 t1 = (boxMax - rayOrigin) * invDir;
    vec3 tMin = min(t0, t1);
    vec3 tMax = max(t0, t1);

    float tNear = max(max(tMin.x, tMin.y), tMin.z);
    float tFar = min(min(tMax.x, tMax.y), tMax.z);

    return tNear <= tFar && tFar > 0.0 && tNear < tCurrent;
}

Stack-Based Traversal Loop

Because GLSL does not support recursion, traversal is performed iteratively using a local array that acts as an execution stack. Since a balanced BVH has a depth rarely exceeding 32 to 64 levels, an integer array of size 32 or 64 is sufficient to maintain the node indices being evaluated.

The general traversal loop proceeds as follows:

  1. Initialization: Push the root node index (0) onto the stack. Initialize the nearest hit distance tHit to infinity.
  2. Pop and Evaluate: While the stack is not empty, pop the top node index.
  3. Bounding Box Test: Test the ray against the current node's AABB. If it misses or if the intersection distance is greater than tHit, discard the node.
  4. Subtree Traversal:
    • If Interior Node: Test both children. To optimize execution, sort the children by ray distance and push the farther child onto the stack first, ensuring the closer child is popped and evaluated first.
    • If Leaf Node: Loop through the primitives associated with the leaf, perform ray-triangle intersection (e.g., using the Möller–Trumbore algorithm), and update tHit whenever a closer intersection occurs.
int stack[64];
int stackPtr = 0;
stack[stackPtr++] = 0; // Push root

float tHit = 1e30;
vec3 invRayDir = 1.0 / rayDir;

while (stackPtr > 0) {
    int nodeIdx = stack[--stackPtr];
    BVHNode node = nodes[nodeIdx];

    if (!intersectAABB(rayOrigin, invRayDir, node.aabbMin, node.aabbMax, tHit)) {
        continue;
    }

    if (node.leftChild < 0) {
        // Leaf node: intersect primitives
        int firstPrim = -node.leftChild - 1;
        for (int i = 0; i < node.primitiveCount; ++i) {
            intersectTriangle(rayOrigin, rayDir, firstPrim + i, tHit);
        }
    } else {
        // Interior node: push children
        // In this setup, rightChild = node.leftChild + 1
        stack[stackPtr++] = node.leftChild + 1;
        stack[stackPtr++] = node.leftChild;
    }
}

Performance Optimization

  • Stack Size and Register Pressure: Keeping the stack in local registers is critical. Large stacks increase register usage, reducing thread occupancy across compute units.
  • Warp Divergence: Adjacent pixels may traverse entirely different branches of the BVH, causing thread divergence. Sorting primary rays by direction or Morton code prior to shading minimizes divergent branches within thread warps.
  • Memory Alignment: Align all structures to 16-byte boundaries (following std430 layout rules) to prevent unaligned memory loads from the global SSBO storage.
