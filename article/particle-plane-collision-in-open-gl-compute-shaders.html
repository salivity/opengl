Particle Plane Collision in OpenGL Compute Shaders

Simulating particle systems with collision detection against simple geometric planes inside OpenGL compute shaders allows for massive parallel throughput by executing physics calculations entirely on the GPU. This article outlines the essential mathematical and shader-based techniques required to achieve efficient plane collisions, covering mathematical plane definitions, discrete signed distance testing, continuous ray-plane intersection to prevent tunneling, and physically plausible response models implemented via Shader Storage Buffer Objects (SSBOs).

Mathematical Representation of the Plane

An infinite geometric plane is most efficiently expressed in Hessian normal form:

\[\mathbf{n} \cdot \mathbf{x} - d = 0\]

Where \(\mathbf{n}\) is a normalized unit vector perpendicular to the surface (\(\|\mathbf{n}\| = 1\)), \(\mathbf{x}\) is any point on the plane, and \(d\) represents the signed distance from the world-space origin to the plane along the normal vector.

In OpenGL, you can pack this definition into a single vec4 within a Uniform Buffer Object (UBO) or Shader Storage Buffer Object (SSBO), where xyz represents the normal vector \(\mathbf{n}\) and w represents the scalar offset \(d\).

Discrete Collision Detection (Signed Distance)

For slow to moderately paced particles, discrete collision detection evaluates whether a particle has penetrated the plane during the current frame update.

  1. Distance Calculation: Compute the signed distance \(S\) from the particle's current position \(\mathbf{p}\) to the plane: \[S = \mathbf{n} \cdot \mathbf{p} - d\]
  2. Intersection Condition: If the particle is treated as a sphere with radius \(r\), a collision occurs when: \[S < r\]
  3. Position Correction: To resolve the penetration, project the particle back out of the collision half-space along the normal vector: \[\mathbf{p}_{\text{corrected}} = \mathbf{p} + (r - S) \mathbf{n}\]

Inside the compute shader, this is evaluated per thread (one thread per particle) using gl_GlobalInvocationID.x to index the particle buffer.

Continuous Collision Detection (Ray-Plane Intersection)

High-speed particles often suffer from tunneling, where a particle passes completely through a plane within a single integration time step (\(\Delta t\)). Continuous Collision Detection (CCD) solves this by treating the movement as a ray from the previous position \(\mathbf{p}_{\text{prev}}\) to the candidate position \(\mathbf{p}_{\text{curr}}\).

  1. Velocity Vector: Define the frame displacement as \(\Delta \mathbf{p} = \mathbf{p}_{\text{curr}} - \mathbf{p}_{\text{prev}}\).
  2. Time of Impact (\(t\)): Find the normalized parameter \(t \in [0, 1]\) where the particle touches the plane: \[t = \frac{d + r - (\mathbf{n} \cdot \mathbf{p}_{\text{prev}})}{\mathbf{n} \cdot \Delta \mathbf{p}}\]
  3. Validity Check: A collision occurs within the step if \(0 \le t \le 1\) and \(\mathbf{n} \cdot \Delta \mathbf{p} < 0\) (the particle is moving toward the front face of the plane).
  4. Impact Point: The exact position of impact is calculated as \(\mathbf{p}_{\text{impact}} = \mathbf{p}_{\text{prev}} + t \Delta \mathbf{p}\).

Collision Response: Restitution and Friction

Once an intersection is confirmed, the particle's velocity vector \(\mathbf{v}\) must be split into normal and tangential components to apply elasticity and surface friction:

  1. Normal Velocity: \[\mathbf{v}_n = (\mathbf{v} \cdot \mathbf{n}) \mathbf{n}\]
  2. Tangential Velocity: \[\mathbf{v}_t = \mathbf{v} - \mathbf{v}_n\]
  3. Applying Response: Multiply the normal component by the coefficient of restitution \(e \in [0, 1]\) (bounciness) and the tangential component by the friction coefficient \(\mu \in [0, 1]\): \[\mathbf{v}_{\text{new}} = -e \mathbf{v}_n + (1 - \mu) \mathbf{v}_t\]

OpenGL Compute Pipeline Integration

To execute this efficiently on the GPU:

  • Buffer Layout: Store particle positions, velocities, and radii in contiguous arrays inside an SSBO using std430 layout for optimal memory alignment.
  • Thread Execution: Dispatch compute work groups sized to multiples of the GPU warp/wavefront size (e.g., layout(local_size_x = 64) in;).
  • Looping over Planes: For static environments with a small number of bounding planes (e.g., walls, floors), iterate through an array of vec4 plane uniforms sequentially. Because the loop count is uniform across all threads, this avoids thread divergence and keeps compute utilization high.
