Bloom via Downsampling and Upsampling in OpenGL

Bloom is a post-processing technique that simulates the optical diffusion of light caused by real-world camera lenses and human eyes when viewing intensely bright surfaces. In modern OpenGL pipelines, the industry-standard approach avoids performance-heavy, large-kernel Gaussian blurs by utilizing an iterative downsampling and upsampling pyramid—most notably popularized by Jorge Jimenez in Call of Duty: Advanced Warfare. This article outlines the architectural mechanics of this technique, detailing bright-pass extraction, multi-pass downsampling with anti-flicker filters, progressive additive upsampling, and final tone-mapped compositing.

1. High-Level Pipeline Architecture

The progressive downsample/upsample bloom pipeline operates directly on a High Dynamic Range (HDR) scene color buffer across five distinct stages:

  1. Thresholding (Prefilter): Bright fragments exceeding a defined luminance threshold are extracted into a full- or half-resolution texture.
  2. Mip Chain Allocation: A series of framebuffers or an explicit texture mip-chain is prepared, typically spanning 5 to 7 levels, with each level half the dimensions of the previous one (e.g., \(1920\times1080 \to 960\times540 \to \dots \to 60\times33\)).
  3. Downsample Passes: The extracted image is progressively downsampled through each mip level using a custom 13-tap bilinear filter to minimize temporal flickering and aliasing.
  4. Upsample Passes: Starting from the lowest resolution mip, the image is progressively upsampled back to higher resolutions, utilizing a 9-tap 3x3 tent filter and OpenGL additive blending to merge layers.
  5. Final Composite: The highest-resolution blurred result is combined with the original HDR scene texture during the final tone mapping and color-grading pass.

2. Extracting Bright Pixels (Prefilter Pass)

Before downsampling, the pipeline filters out colors that should not cast a glow. The initial pass renders the HDR scene buffer into the base level of the bloom chain (mip 0).

To prevent harsh, noisy cutoffs, a smooth thresholding function (soft knee) is evaluated in the fragment shader:

vec3 Prefilter(vec3 color, float threshold, vec3 curve) {
    float brightness = max(color.r, max(color.g, color.b));
    float soft = brightness - curve.x;
    soft = clamp(soft, 0.0, curve.y);
    soft = soft * soft * curve.z;
    float contribution = max(soft, brightness - threshold) / max(brightness, 1e-4);
    return color * contribution;
}

This isolates specular highlights, emissive surfaces, and direct light sources while preserving smooth transitions.

3. Progressive Downsampling Chain

Downsampling reduces image dimensions in halves, naturally widening the effective filter footprint without increasing sample count. To prevent sample loss and sparkling (specular fireflies), Jimenez's 13-tap filter is used. This filter samples a \(4\times4\) texel area using five overlapping bilinear texture fetches: one in the center and four at the diagonal corners.

In OpenGL, the loop executes as follows:

  1. Bind the framebuffer targeting mip[i].
  2. Set glViewport(0, 0, width >> i, height >> i).
  3. Bind mip[i - 1] as the source texture with linear filtering (GL_LINEAR).
  4. Execute a full-screen quad draw.

The fragment shader for each downsample pass fetches 13 samples and uses a partial Karis average (weighting samples by luminance) on the very first downsample step to resolve temporal stability issues:

// Jimenez 13-tap pattern offsets
vec3 a = texture(srcTexture, uv + vec2(-2,  2) * texelSize).rgb;
vec3 b = texture(srcTexture, uv + vec2( 0,  2) * texelSize).rgb;
vec3 c = texture(srcTexture, uv + vec2( 2,  2) * texelSize).rgb;
// ... additional 10 taps across center and bottom ...

By the time the chain reaches the smallest mip (often around \(32\times18\) or \(16\times9\)), light has spread across hundreds of screen-space pixels with minimal computational overhead.

4. Progressive Upsampling with Additive Blending

Simply resizing low-resolution textures back to the screen creates distinct blocky artifacts. To counter this, upsampling reverses the chain with a smooth reconstruction kernel, typically a 9-tap \(3\times3\) tent filter with the following weights:

  • Center: \(4/16\)
  • Orthogonal neighbors: \(2/16\)
  • Diagonal corners: \(1/16\)

The upsampling loop progresses from the smallest mip back up to mip 0:

  1. Bind the framebuffer containing mip[i - 1].

  2. Set glViewport to the dimensions of mip[i - 1].

  3. Enable additive blending:

    glEnable(GL_BLEND);
glBlendFunc(GL_ONE, GL_ONE);

  4. Bind mip[i] as the source texture.

  5. Render the full-screen quad with the 9-tap tent shader.

Because additive blending is active, the upsampled content from mip[i] seamlessly adds directly on top of the previously generated downsampled data at mip[i - 1]. This accumulates fine-grained and wide-spread glows into a coherent, high-quality blur.

5. Final Composition and Tone Mapping

Once the upsampling chain returns to the base resolution (mip 0), the framebuffer contains a comprehensive diffusion map representing the bloom contribution. In the final rendering pass, this bloom texture and the original HDR scene texture are bound as inputs to the composite shader.

uniform sampler2D sceneColor;
uniform sampler2D bloomColor;
uniform float bloomIntensity;

void main() {
    vec3 hdrColor = texture(sceneColor, TexCoords).rgb;
    vec3 bloom = texture(bloomColor, TexCoords).rgb * bloomIntensity;
    
    vec3 combined = hdrColor + bloom;
    
    // Tone mapping (e.g., ACES or Reinhard)
    vec3 mapped = vec3(1.0) - exp(-combined * exposure);
    FragColor = vec4(mapped, 1.0);
}

Applying bloom in HDR space before tone mapping ensures that light physically bleeds across darker borders correctly, simulating natural camera sensor saturation.
