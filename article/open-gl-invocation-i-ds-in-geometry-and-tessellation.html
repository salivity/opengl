OpenGL Invocation IDs in Geometry and Tessellation

Modern OpenGL utilizes specific built-in GLSL variables to identify primitive instances and execution threads across the geometry and tessellation stages. The primary variable for distinguishing concurrent invocations is gl_InvocationID, which works alongside primitive index variables such as gl_PrimitiveID and gl_PrimitiveIDIn to allow shaders to locate and process geometry accurately.

Geometry Shader Stage

In the Geometry Shader (GS), multiple invocations can execute for a single input primitive when geometry shader instancing is enabled. This is declared in the layout qualifier:

layout(triangles, invocations = N) in;

The relevant built-in variables are:

  • gl_InvocationID: Exposes the zero-based index of the current geometry shader invocation for the active input primitive. It ranges from 0 to N - 1. This allows different invocations processing the same primitive to produce distinct output geometry (for example, rendering to multiple viewport layers or cubemap faces).
  • gl_PrimitiveIDIn: Holds the index of the current input primitive generated by the input assembler or previous shader stages within the current draw call.

Tessellation Control Shader Stage

The Tessellation Control Shader (TCS) runs in parallel across the vertices of an output patch. Each invocation writes data for a designated control point.

  • gl_InvocationID: Represents the zero-based index of the specific output control point assigned to the current invocation. It ranges from 0 to the output patch size minus one, as defined by layout(vertices = N) out.
  • gl_PrimitiveID: Provides the zero-based index of the input patch currently being processed within the current draw command.

Tessellation Evaluation Shader Stage

The Tessellation Evaluation Shader (TES) runs once for each abstract vertex produced by the fixed-function tessellation primitive generator.

  • gl_PrimitiveID: Exposes the patch ID currently being evaluated. Because the TES operates on the tessellator's generated mesh vertices rather than user-defined invocations, it does not include gl_InvocationID. Instead, the shader relies on gl_PrimitiveID to reference per-patch attributes and gl_TessCoord to identify the relative position of the vertex on the tessellated surface.
