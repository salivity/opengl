How SLI and CrossFire Handled OpenGL Frame Alternation

Legacy multi-GPU configurations, such as NVIDIA SLI and AMD CrossFire, relied heavily on Alternate Frame Rendering (AFR) to boost performance by assigning consecutive frames to alternating GPUs. Implementing automatic AFR within legacy OpenGL environments presented unique challenges due to the API's global state machine architecture and hidden inter-frame dependencies. This article explains how graphics drivers intercepted API calls, synchronized state machines, tracked resource dependencies, and managed frame-swapping routines to automate frame alternation in legacy OpenGL applications.

The Role of Driver-Level API Interception

Legacy OpenGL applications were entirely unaware of multiple physical GPUs because the API lacked native multi-adapter abstractions. To coordinate AFR automatically, NVIDIA and AMD integrated custom orchestration layers directly into their OpenGL Installable Client Drivers (ICDs).

The driver acted as a proxy between the application and the hardware. It continuously monitored the OpenGL command stream for frame delimiters, primarily looking for swap calls such as wglSwapBuffers on Windows or glXSwapBuffers on Linux. When a swap call was detected, the driver marked the completion of a logical frame and toggled the active hardware context to the alternate GPU for the subsequent draw commands.

Synchronizing the OpenGL State Machine

OpenGL operates as a persistent state machine where previously set states—such as bound shaders, blending modes, depth tests, and active textures—persist indefinitely until explicitly overwritten. This model is inherently hostile to AFR, where GPU 1 executes frame \(N\) and GPU 2 concurrently executes frame \(N+1\).

To resolve this, drivers maintained dual state trackers:

  1. State Shadowing and Duplication: The driver intercepted and mirrored non-drawing state commands (like glEnable, glBindTexture, or glUseProgram) across all participating GPUs. If a state changed during frame \(N\), the driver ensured the same state was broadcast to the alternate GPU so it could correctly render frame \(N+1\).
  2. Context Virtualization: Drivers virtualized the main OpenGL rendering context into multiple hardware-specific contexts. The driver maintained a ghost state for each GPU, applying differential state updates before dispatching rendering passes to prevent state divergence between alternate frames.

Resolving Inter-Frame Resource Dependencies

The primary bottleneck for automatic AFR in OpenGL was handling resources modified in one frame and consumed in the next. Examples include render-to-texture targets, Framebuffer Objects (FBOs), motion blur accumulation buffers, and dynamic shadow maps.

If GPU 1 generated an FBO in frame \(N\) that GPU 2 required to compute frame \(N+1\), automatic AFR would cause severe visual artifacts if executed without synchronization. Drivers resolved this through automatic dependency detection:

  • Resource Dirty-Flagging: Drivers tagged textures and buffers with generation IDs and "dirty" flags. When an application bound an FBO as a texture input on GPU 2, the driver checked whether that resource was written to by GPU 1 in a preceding frame.
  • Peer-to-Peer Interconnect Transfers: Upon detecting a dirty dependency, the driver stalled execution on the target GPU until the source GPU finished the render pass. The data was then transferred across the high-speed proprietary interconnect (the physical SLI or CrossFire bridge) or through peer-to-peer PCIe transactions.

Fallback Modes and Application Profiles

Because fully automated dependency tracking introduced CPU overhead and latency, drivers could not rely on pure runtime heuristics alone. NVIDIA (via ForceWare/GeForce drivers) and AMD (via Catalyst) utilized tailored application profiles.

These profiles contained pre-analyzed rules for specific OpenGL executable binaries:

  • Frame Throttling: Regulating the presentation queue to prevent micro-stutter caused by uneven frame completion times.
  • Selective Synchronization: Whitelisting safe buffers that did not require cross-GPU synchronization to save bridge bandwidth.
  • Mode Fallbacks: If an OpenGL title relied too heavily on persistent frame-to-frame feedback loops, AFR broke down and created bus-saturating sync penalties. Under these conditions, the driver automatically disabled AFR and fell back to Split Frame Rendering (SFR / Scissor mode), dividing individual frames into horizontal sections distributed across both GPUs.
