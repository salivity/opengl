Procedural Patterns with gl_PointCoord in OpenGL

This article explains how OpenGL utilizes the built-in gl_PointCoord fragment shader variable to procedurally render 2D patterns and textures onto point sprites. By reading localized coordinate data across individual point primitives, developers can bypass traditional quad-based geometry generation to produce circular particles, soft-edged glow effects, and analytical shapes efficiently on the GPU.

Understanding Point Sprites and gl_PointCoord

In OpenGL, rendering with the GL_POINTS primitive produces screen-aligned squares centered at the vertex's projected position. When point sizing is controlled dynamically via the vertex shader—enabled using glEnable(GL_PROGRAM_POINT_SIZE) and set through gl_PointSize—the rasterizer generates a square area covering the specified pixel dimensions.

The gl_PointCoord variable is a built-in vec2 input available exclusively in the fragment shader. As the rasterizer fills each pixel of the point's bounding box, it assigns an interpolated coordinate pair to gl_PointCoord:

  • (0.0, 0.0) corresponds to the top-left corner of the point square.
  • (1.0, 1.0) corresponds to the bottom-right corner of the point square.
  • (0.5, 0.5) marks the exact center of the point.

Unlike standard OpenGL texture coordinates, which typically originate at the bottom-left corner, gl_PointCoord originates at the top-left, matching screen-space window conventions.

Coordinate Transformation for Procedural Shapes

Because gl_PointCoord is normalized across the point quad regardless of the screen-space pixel size, it provides a consistent coordinate frame for mathematical functions.

To evaluate radial or distance-based patterns, the coordinates are commonly remapped from the default [0.0, 1.0] range to a centered coordinate system ranging from [-1.0, 1.0]:

vec2 centerCoord = gl_PointCoord * 2.0 - 1.0;

In this remapped space, the center of the point lies at (0.0, 0.0), and the outer boundary touches a radius of 1.0.

Rendering Circular Particles

By default, an OpenGL point renders as a solid square. To transform it into a circle, the fragment shader computes the distance from the fragment to the center and discards fragments that fall outside the desired radius:

#version 330 core
out vec4 FragColor;

void main() {
    vec2 circCoord = 2.0 * gl_PointCoord - 1.0;
    if (dot(circCoord, circCoord) > 1.0) {
        discard;
    }
    FragColor = vec4(1.0, 0.5, 0.2, 1.0);
}

Using dot(circCoord, circCoord) evaluates the squared Euclidean distance without calculating an expensive square root operation. Any fragment where the squared distance exceeds 1.0 is discarded, leaving a clean disk.

Antialiasing and Soft Edges

Hard discards can cause jagged edges along particle silhouettes. To produce smooth or glowing effects, gl_PointCoord can be used alongside functions like smoothstep or exponential decay to modulate the fragment's alpha channel:

#version 330 core
out vec4 FragColor;

void main() {
    float dist = length(gl_PointCoord - vec2(0.5));
    
    // Smooth boundary between radius 0.45 and 0.5
    float alpha = smoothstep(0.5, 0.45, dist);
    
    if (alpha <= 0.0) {
        discard;
    }

    FragColor = vec4(0.2, 0.6, 1.0, alpha);
}

This approach transitions alpha values smoothly to zero near the outer boundary, producing antialiased points when blended using standard alpha blending (glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)).

Procedural Texturing via Signed Distance Fields

Beyond simple circles, gl_PointCoord can drive complex analytical 2D Signed Distance Fields (SDFs). Since the input represents a local UV canvas, you can procedurally evaluate rings, stars, crosses, or geometric grids:

  • Rings and Halos: Evaluate abs(length(gl_PointCoord - vec2(0.5)) - targetRadius) to render concentric borders.
  • Directional Gradients: Use linear functions of gl_PointCoord.x or gl_PointCoord.y to generate directional lighting, fire ramps, or energy bars.
  • Normal Generation: Spherical surface normals can be calculated directly by projecting the 2D offset onto a virtual hemisphere: vec3 normal = vec3(circCoord.xy, sqrt(1.0 - dot(circCoord, circCoord)));, allowing single-vertex points to respond to 3D scene lighting as if they were true spheres.
