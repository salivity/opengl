How glDrawArrays Works in the OpenGL Pipeline

The glDrawArrays command serves as a fundamental draw call in OpenGL, instructing the GPU to render primitives by fetching vertex data sequentially from currently enabled vertex buffers without referencing an index buffer. This article explains how executing glDrawArrays triggers the unindexed rendering sequence, detailing the progression from vertex data extraction and vertex shader invocation to primitive assembly and downstream pipeline stages.

Parameters and Initial Invocation

The command signature is defined as:

void glDrawArrays(GLenum mode, GLint first, GLsizei count);

When invoked, the OpenGL context evaluates three core parameters:

  • mode: Specifies the primitive type to construct, such as GL_TRIANGLES, GL_LINES, or GL_TRIANGLE_STRIP.
  • first: The starting index within the enabled vertex attribute arrays.
  • count: The total number of sequential indices to process.

Upon execution, the driver validates the active state, confirming that a valid Vertex Array Object (VAO) and an active shader program are bound.

Unindexed Vertex Attribute Fetching

Unlike indexed drawing functions (such as glDrawElements), which rely on an Element Array Buffer to map indices to vertices, glDrawArrays operates strictly sequentially.

The pipeline determines vertex indices as an implicit linear sequence:

\[\text{Index}_i = \text{first} + i \quad \text{for } i \in [0, \text{count} - 1]\]

For each index in this range, the GPU's input assembler queries the bindings configured in the currently bound VAO. It calculates memory offsets into the associated Vertex Buffer Objects (VBOs) using each attribute’s stride, data type, and base offset. The hardware then pulls the raw attribute data (such as positions, normals, and texture coordinates) directly into the processing registers.

Vertex Shader Execution

For every index generated from first to first + count - 1, the GPU dispatches an instance of the vertex shader:

  • The system sets the built-in variable gl_VertexID to the current index value.
  • Vertex attributes defined as in variables in GLSL receive the fetched data corresponding to that index.
  • The vertex shader executes its transformation routines (e.g., model-view-projection matrix multiplications) and writes the results to output variables, including the mandatory clip-space coordinate gl_Position.

Because the drawing is unindexed, duplicate vertices across adjacent primitives are processed redundantly, resulting in independent shader invocations for every single entry within the range.

Primitive Assembly and Subsequent Stages

Once the vertex shader outputs the transformed vertices, the pipeline groups them according to the mode parameter:

  • Grouping: If mode is GL_TRIANGLES, every three consecutive vertices form an independent triangle. If mode is GL_TRIANGLE_STRIP, overlapping sets of three vertices form linked triangles.
  • Optional Intermediate Processing: If enabled, the assembled primitives pass directly to tessellation and geometry shaders for additional procedural generation or modification.
  • Clipping and Screen Mapping: Primitives are tested against the view frustum. Portions falling outside are clipped, followed by perspective division (converting homogeneous coordinates to Normalized Device Coordinates) and the viewport transform, which maps coordinates to screen space.
  • Rasterization and Fragment Shading: Finally, the rasterizer interpolates vertex outputs across the primitive faces to generate fragments, invoking the fragment shader to calculate final pixel colors for the framebuffer.
