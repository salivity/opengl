Generating Jittered Projection Matrices for TAA in OpenGL

Temporal Anti-Aliasing (TAA) mitigates geometric aliasing and specular shimmer by supersampling the scene over multiple consecutive frames. To implement TAA in OpenGL, the camera’s perspective projection matrix must be perturbed every frame by a sub-pixel offset, allowing the rasterizer to sample different locations within each pixel footprint. This article details the mathematical adjustments required to apply sub-pixel jitter to an OpenGL projection matrix, explains sample distribution patterns, and addresses the handling of motion vectors for temporal reconstruction.

Calculating the Sub-Pixel Jitter Offset

A standard pixel occupies a \([0, 1] \times [0, 1]\) area in viewport coordinates, which maps to a range of \([-1, 1]\) in OpenGL Normalized Device Coordinates (NDC). Because NDC covers a span of \(2.0\) units along both the X and Y axes, the size of a single pixel in NDC is:

\[\text{PixelSize}_{\text{NDC}} = \left( \frac{2.0}{\text{ViewportWidth}}, \frac{2.0}{\text{ViewportHeight}} \right)\]

To jitter the camera, choose a sub-pixel sample offset \((\delta_x, \delta_y)\) where each component typically lies in the range \([-0.5, 0.5]\). The required offset in NDC space is:

\[J_x = \frac{2.0 \times \delta_x}{\text{ViewportWidth}}\] \[J_y = \frac{2.0 \times \delta_y}{\text{ViewportHeight}}\]

Commonly, low-discrepancy sequences such as the Halton \((2, 3)\) sequence are used to generate \((\delta_x, \delta_y)\) across an 8- or 16-frame cycle. The raw Halton output in the range \([0, 1)\) must be mapped to \([-0.5, 0.5)\) by subtracting \(0.5\).

Modifying the OpenGL Projection Matrix

In OpenGL, a standard symmetric perspective projection matrix takes the following form (row-major display):

\[P = \begin{bmatrix} \frac{2n}{r - l} & 0 & \frac{r + l}{r - l} & 0 \\ 0 & \frac{2n}{t - b} & \frac{t + b}{t - b} & 0 \\ 0 & 0 & -\frac{f + n}{f - n} & -\frac{2fn}{f - n} \\ 0 & 0 & -1 & 0 \end{bmatrix}\]

Clipping coordinates are generated via \(V_{\text{clip}} = P \times V_{\text{eye}}\), and NDC is computed by the perspective divide:

\[X_{\text{ndc}} = \frac{X_{\text{clip}}}{W_{\text{clip}}}, \quad Y_{\text{ndc}} = \frac{Y_{\text{clip}}}{W_{\text{clip}}}\]

Because \(W_{\text{clip}} = -Z_{\text{eye}}\) in standard OpenGL perspective projections, an offset directly added to NDC space requires adjusting the terms in the projection matrix that scale with \(W_{\text{clip}}\). Specifically, the third column elements (representing the perspective center shift) must be modified:

\[P_{0,2}' = P_{0,2} + J_x\] \[P_{1,2}' = P_{1,2} + J_y\]

In column-major matrix conventions (such as standard GLSL and OpenGL Mathematics / GLM):

// Column-major representation: matrix[column][row]
glm::mat4 projection = glm::perspective(fov, aspectRatio, nearPlane, farPlane);

float jitterX = ((haltonX - 0.5f) * 2.0f) / viewportWidth;
float jitterY = ((haltonY - 0.5f) * 2.0f) / viewportHeight;

projection[2][0] += jitterX; // Row 0, Column 2
projection[2][1] += jitterY; // Row 1, Column 2

This modification directly introduces the NDC translation during the perspective divide without altering the field of view, focal length, or depth precision (\(Z_{\text{ndc}}\) remains unaffected).

Frustum Plane Alternative

Alternatively, if the projection matrix is constructed directly from asymmetric frustum boundaries \((left, right, bottom, top)\), the jitter can be introduced at the frustum definition:

\[\text{offset}_x = \delta_x \times \frac{right - left}{\text{ViewportWidth}}\] \[\text{offset}_y = \delta_y \times \frac{top - bottom}{\text{ViewportHeight}}\]

Applying these offsets updates the bounds to:

\[left' = left + \text{offset}_x, \quad right' = right + \text{offset}_x\] \[bottom' = bottom + \text{offset}_y, \quad top' = top + \text{offset}_y\]

Passing these adjusted boundaries to glFrustum produces an identical jittered projection matrix.

Implications for Velocity Buffers

When rendering motion vectors for TAA temporal reprojection, the jitter must not be included in the velocity calculation. If the jitter is incorporated into pixel motion vectors, the temporal resolver will interpret camera jitter as surface motion, resulting in severe image smearing.

Compute motion vectors using the unjittered current view-projection matrix and the unjittered previous view-projection matrix:

\[\text{Velocity} = \text{NDC}_{\text{current, unjittered}} - \text{NDC}_{\text{previous, unjittered}}\]

If unjittered matrices are unavailable during velocity calculation, subtract the current frame's \((J_x, J_y)\) and add the previous frame's \((J_x, J_y)\) manually in the motion vector shader.
