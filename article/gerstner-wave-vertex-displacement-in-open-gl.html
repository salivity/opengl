Gerstner Wave Vertex Displacement in OpenGL

This article explains how Gerstner wave mathematics are evaluated to displace vertices within an OpenGL vertex shader to create realistic water surfaces. Unlike standard sine waves that only alter elevation, Gerstner waves displace vertices horizontally toward the wave crests while pushing them upward, forming characteristic sharp peaks and broad troughs. The following sections break down the wave equations, their accumulation across multiple wave components, analytical normal calculations, and practical implementation in the OpenGL Shading Language (GLSL).

Mathematical Formulation of a Gerstner Wave

A simple sine wave displaces a vertex purely along the vertical axis (\(Y\)). A Gerstner wave introduces horizontal displacement along the direction of wave travel (\(X\) and \(Z\)), creating trochoidal motion similar to real fluid dynamics.

For a vertex at an initial horizontal position \(\mathbf{P}_0 = (x, z)\), a single Gerstner wave is defined by the following parameters:

  • Direction (\(\mathbf{D}\)): A normalized 2D vector \((d_x, d_z)\) indicating wave travel direction.
  • Amplitude (\(A\)): Half the vertical distance between crest and trough.
  • Wavelength (\(L\)): Distance between crests, from which the wave number \(k = \frac{2\pi}{L}\) is derived.
  • Speed (\(S\)): The phase speed, producing frequency \(\omega = \sqrt{g \cdot k}\) (using gravity \(g\)) or a simplified phase constant \(\phi = S \times k\).
  • Steepness (\(Q\)): A factor controlling the sharpness of the crest. \(Q\) must satisfy \(0 \le Q \le 1\); setting \(Q = 0\) yields a standard sine wave, while \(Q = 1\) generates the sharpest crest possible without self-intersection.

The phase \(\theta\) of the wave at time \(t\) is calculated as: \[\theta = k(\mathbf{D} \cdot \mathbf{P}_0) + \omega t\]

The displacement applied to the vertex position \((x, y, z)\) is:

  • \(P_x = x + Q \cdot A \cdot d_x \cdot \cos(\theta)\)
  • \(P_y = A \cdot \sin(\theta)\)
  • \(P_z = z + Q \cdot A \cdot d_z \cdot \cos(\theta)\)

Accumulating Multiple Waves

Realistic ocean rendering requires superimposing multiple waves of varying directions, wavelengths, and amplitudes. To prevent the surface from self-intersecting (looping over itself at crests), the sum of all steepness factors must not exceed 1:

\[\sum_{i=1}^{N} Q_i \le 1 \quad \text{where} \quad Q_i = \frac{\bar{Q}}{k_i A_i N}\]

Here, \(\bar{Q}\) is an artist-controlled steepness parameter between 0 and 1, and \(N\) is the total number of waves. The final displaced vertex position \(\mathbf{P}\) is the base position plus the cumulative displacement:

\[\mathbf{P} = \begin{pmatrix} x \\ 0 \\ z \end{pmatrix} + \sum_{i=1}^{N} \begin{pmatrix} Q_i A_i d_{i,x} \cos(\theta_i) \\ A_i \sin(\theta_i) \\ Q_i A_i d_{i,z} \cos(\theta_i) \end{pmatrix}\]

Analytical Normal and Tangent Calculation

Lighting models (such as Blinn-Phong or PBR) require an accurate surface normal at each displaced vertex. While normals can be estimated through finite differences by sampling neighboring points, Gerstner waves allow for exact analytical computation using partial derivatives.

The tangent (\(\mathbf{T}\)) and bitangent (\(\mathbf{B}\)) vectors are computed by differentiating the surface position \(\mathbf{P}\) with respect to \(x\) and \(z\):

\[\mathbf{T} = \frac{\partial \mathbf{P}}{\partial x} = \begin{pmatrix} 1 - \sum Q_i d_{i,x}^2 k_i A_i \sin(\theta_i) \\ \sum d_{i,x} k_i A_i \cos(\theta_i) \\ -\sum Q_i d_{i,x} d_{i,z} k_i A_i \sin(\theta_i) \end{pmatrix}\]

\[\mathbf{B} = \frac{\partial \mathbf{P}}{\partial z} = \begin{pmatrix} -\sum Q_i d_{i,x} d_{i,z} k_i A_i \sin(\theta_i) \\ \sum d_{i,z} k_i A_i \cos(\theta_i) \\ 1 - \sum Q_i d_{i,z}^2 k_i A_i \sin(\theta_i) \end{pmatrix}\]

The surface normal vector \(\mathbf{N}\) is the cross product \(\mathbf{B} \times \mathbf{T}\), which simplifies to:

\[\mathbf{N} = \begin{pmatrix} -\sum d_{i,x} k_i A_i \cos(\theta_i) \\ 1 - \sum Q_i k_i A_i \sin(\theta_i) \\ -\sum d_{i,z} k_i A_i \cos(\theta_i) \end{pmatrix}\]

This vector is normalized in the shader before being passed to the fragment stage.

GLSL Vertex Shader Implementation

The following GLSL code demonstrates the evaluation of Gerstner displacement and normals directly on a flat horizontal plane mesh:

#version 330 core

layout (location = 0) in vec3 aPos;

uniform mat4 model;
uniform mat4 view;
uniform mat4 projection;
uniform float uTime;

out vec3 vWorldPos;
out vec3 vNormal;

struct GerstnerWave {
    vec2 direction;
    float amplitude;
    float wavelength;
    float speed;
    float steepness;
};

const int NUM_WAVES = 4;
uniform GerstnerWave uWaves[NUM_WAVES];

void evaluateGerstnerWave(GerstnerWave wave, vec2 pos, float time, 
                           inout vec3 displacement, inout vec3 normal) {
    float k = 2.0 * 3.14159265 / wave.wavelength;
    float c = sqrt(9.8 / k); // Dispersion relation
    vec2 d = normalize(wave.direction);
    float f = k * (dot(d, pos) - wave.speed * time);
    float a = wave.amplitude;
    float q = wave.steepness / (k * a * float(NUM_WAVES));

    displacement.x += q * a * d.x * cos(f);
    displacement.y += a * sin(f);
    displacement.z += q * a * d.y * cos(f);

    normal.x -= d.x * (k * a) * cos(f);
    normal.y -= q * (k * a) * sin(f);
    normal.z -= d.y * (k * a) * cos(f);
}

void main() {
    vec3 displacedPos = aPos;
    vec3 normal = vec3(0.0, 1.0, 0.0);
    vec3 displacement = vec3(0.0);

    for (int i = 0; i < NUM_WAVES; ++i) {
        evaluateGerstnerWave(uWaves[i], aPos.xz, uTime, displacement, normal);
    }

    displacedPos += displacement;
    normal = normalize(normal);

    vWorldPos = (model * vec4(displacedPos, 1.0)).xyz;
    vNormal = normalize(mat3(transpose(inverse(model))) * normal);
    
    gl_Position = projection * view * vec4(vWorldPos, 1.0);
}

Performance Considerations

Because displacement is computed entirely in the vertex stage, performance depends primarily on the geometric density of the water grid rather than fragment throughput. A high-density grid is required to capture the steepness of short-wavelength waves without vertex swimming or aliasing. Geometric clipmaps or Tessellation Evaluation Shaders (TES) are commonly paired with this technique to allocate vertex density closer to the camera where wave curvature is most visible.
