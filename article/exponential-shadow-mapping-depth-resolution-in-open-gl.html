Exponential Shadow Mapping Depth Resolution in OpenGL

Exponential Shadow Mapping (ESM) solves traditional shadow mapping artifacts by replacing the binary depth test with a continuous exponential approximation. In standard shadow mapping, depth quantization and discrete depth comparisons cause severe surface acne, edge aliasing, and precision loss inside fragment shaders. ESM remaps shadow depths into exponential space, enabling pre-filtering techniques like Gaussian blurs and hardware linear filtering directly on shadow maps. This article explores how ESM eliminates depth resolution artifacts, optimizes precision within OpenGL shaders, and maintains high-performance rendering.

The Limits of Standard Shadow Mapping

Traditional shadow mapping compares the fragment's light-space depth against a value stored in a discrete depth texture. Because depth textures have finite precision (typically 16-bit or 24-bit normalized integers), rounding errors frequently occur. When multiple fragments map to the same depth texel, floating-point inaccuracies cause surface acne—a form of depth resolution artifact where surfaces erroneously shadow themselves.

To combat acne, developers typically apply an artificial depth bias. However, excessive biasing introduces "Peter Panning," where shadows detach from the geometry casting them. Furthermore, because standard shadow tests require a discrete step function:

\[f(d, z) = \begin{cases} 1 & \text{if } z \le d \\ 0 & \text{if } z > d \end{cases}\]

standard hardware filtering (such as bilinear filtering, mipmapping, or multisampling) cannot be applied directly to the depth buffer before the comparison is made.

The Exponential Approximation

ESM replaces the hard step function with an exponential decay function:

\[f(z_{receiver}, z_{caster}) \approx e^{-c (z_{receiver} - z_{caster})}\]

Here, \(z_{receiver}\) represents the light-space depth of the surface being shaded, \(z_{caster}\) represents the occluder depth stored in the shadow map, and \(c\) is a user-defined scaling constant.

By applying exponential arithmetic, the terms can be factored:

\[e^{-c (z_{receiver} - z_{caster})} = e^{-c z_{receiver}} \cdot e^{c z_{caster}}\]

This mathematical property is critical for resolving depth artifacts because \(e^{c z_{caster}}\) depends strictly on the occluder geometry. Consequently, the occluder values can be pre-filtered using standard linear interpolation, separable Gaussian blurs, or hardware-based anisotropic filtering before the fragment shader evaluates the shadow test.

Eliminating Depth Quantization Inside OpenGL

ESM eliminates depth resolution artifacts in OpenGL shaders through three primary mechanisms:

1. Transitioning to Floating-Point Textures

Standard depth buffers rely on non-linear fixed-point formats. ESM implementations in OpenGL typically render occluder depth values to a single-channel 32-bit floating-point texture (GL_R32F). When rendering to the shadow map, the fragment shader computes and stores \(e^{c z}\):

// Light-space depth write pass
#version 450 core
layout(location = 0) out float FragColor;

uniform float c; // ESM constant factor

void main() {
    float depth = gl_FragCoord.z;
    FragColor = exp(c * depth);
}

Using 32-bit floating-point textures eliminates the quantization step errors present in normalized 16-bit or 24-bit depth attachments.

2. Native Linear Filtering Support

Because the values stored are smooth exponential representations rather than discrete thresholds, OpenGL can safely apply standard texture filtering parameters:

glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR_MIPMAP_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);

Hardware bilinear filtering smoothly blends adjacent depth samples on the GPU, removing the jagged stair-stepping artifacts associated with low texture resolution.

3. Continuous Depth Evaluation in the Fragment Shader

When evaluating shadows on geometry, the fragment shader calculates the visibility factor by sampling the filtered exponential shadow texture and multiplying it by \(e^{-c z_{receiver}}\):

// Shading pass
#version 450 core
in vec4 vLightSpacePos;
out vec4 FinalColor;

uniform sampler2D uShadowMap;
uniform float c;

float CalculateESM(vec4 lightSpacePos) {
    vec3 projCoords = lightSpacePos.xyz / lightSpacePos.w;
    projCoords = projCoords * 0.5 + 0.5;

    // Early out if outside the light frustum
    if (projCoords.z > 1.0) return 1.0;

    float receiverDepth = projCoords.z;
    float filteredCasterExp = texture(uShadowMap, projCoords.xy).r;

    // Evaluate visibility
    float shadow = filteredCasterExp * exp(-c * receiverDepth);
    return clamp(shadow, 0.0, 1.0);
}

Instead of a binary result, the shader produces a continuous gradient near occlusion edges. This gradient prevents self-shadowing acne while removing the need for aggressive slope-scale depth biasing.

Managing Numerical Instability

The primary challenge of ESM in shaders is numerical overflow. As depth \(z\) approaches 1.0, high values of \(c\) can exceed the maximum range representable by 32-bit floating-point numbers (\(e^{88} \approx 1.6 \times 10^{38}\)).

To maintain depth stability and avoid underflow/overflow artifacts:

  • Keep depth in normalized light-space ranges \([0, 1]\) using a tight near and far clipping plane.
  • Select an optimal constant \(c\) (typically between \(40.0\) and \(80.0\)). A value that is too low causes light bleeding (shadow leaking through thin occluders), while a value that is too high causes floating-point overflow and clamping artifacts.
  • Alternatively, perform calculations in log-space within the shader using the formulation \(\ln(\text{sample}) - c \cdot z_{receiver}\) to completely prevent overflow before computing the final exponential.
