How OpenGL Discard Keyword Kills Fragment Execution

The discard keyword in an OpenGL fragment shader provides a mechanism to conditionally terminate the processing of a fragment, completely preventing it from writing to the framebuffer. This article covers how discard functions at the shader level, how underlying GPU architectures execute it within SIMD threads, its consequences for early depth testing, and the performance implications associated with cutout rendering.

The Purpose and Logical Behavior of discard

In GLSL (OpenGL Shading Language), discard is a jump statement used exclusively inside fragment shaders. When the execution path encounters discard, the fragment currently being processed is effectively eliminated. The pipeline halts further evaluation for that specific fragment and prevents it from updating any associated framebuffer attachments, including color, depth, and stencil buffers.

A standard application is alpha-testing or cutouts, such as rendering chain-link fences or foliage:

#version 330 core
in vec2 TexCoords;
out vec4 FragColor;

uniform sampler2D texture_diffuse;

void main()
{
    vec4 texColor = texture(texture_diffuse, TexCoords);
    if(texColor.a < 0.1)
        discard;

    FragColor = texColor;
}

If the alpha value of the sample falls below the threshold, the fragment is discarded. Any following instructions within that shader invocation are bypassed, and no values are committed to the screen.

Architectural Reality: SIMD Quads and Thread Masking

While discard logically halts the execution of a single fragment, modern GPUs do not immediately terminate the underlying hardware thread in isolation.

GPUs execute fragment shaders in parallel across lockstep groups of threads known as warps (NVIDIA) or wavefronts (AMD). Fragments are processed in 2x2 clusters called quads to allow the calculation of screen-space derivatives (dFdx, dFdy), which are necessary for tasks like texture level-of-detail (mipmapping).

If only one or two fragments within a 2x2 quad execute a discard:

  1. The hardware cannot shut down the SIMD execution lane entirely if neighboring threads in the same quad need to continue.
  2. The discarded lane is instead masked off (disabled).
  3. The masked thread may still execute subsequent instructions in lockstep with the active lanes in its quad to maintain derivative calculations, but its side effects, texture writes, and memory outputs are disabled.
  4. Only when all fragments in a warp or wavefront reach a discard point can the hardware scheduler fully terminate the entire block of execution early.

Impact on Early-Z Testing

The most significant performance consideration when using discard is its effect on Early Depth Testing (Early-Z).

Under normal conditions, modern GPUs run depth and stencil tests before the fragment shader executes. If an incoming fragment is obscured by previously rendered geometry, the GPU drops the fragment immediately, avoiding expensive fragment shading altogether.

When a shader contains the discard keyword:

  • The GPU cannot safely write to the depth buffer before the fragment shader runs, because the shader itself determines whether the fragment even exists.
  • The driver typically disables early depth writes. Some architectures can still perform early depth tests to reject fragments obscured by earlier geometry, but they must defer the final depth update until shader execution completes.
  • This deferral limits the efficiency of occlusion culling and can lead to pipeline stalls, as depth updates are serialized later in the pipeline.

Performance Considerations

Because discard disables early depth writes and can lead to thread divergence within SIMD warps, it should be used deliberately.

To mitigate performance penalties:

  • Render opaque geometry first: Draw solid geometry before cutout geometry using standard early depth testing. This ensures that fragments hidden behind solid surfaces are culled before the expensive cutout shaders are ever invoked.
  • Keep discard logic near the top: Placing the discard condition as early as possible in the shader allows the compiler to skip unnecessary arithmetic for unmasked lanes, even if the SIMD warp remains partially active.
  • Evaluate Alpha Blending vs. Discard: In high-overdraw scenes, blending can sometimes be more pipeline-friendly than branching with discard, though it requires depth sorting and incurs memory bandwidth overhead.
