OpenGL Clustered Shading Light Index Construction

This article provides an overview of how active light identification is linked to 3D view-space clusters using an OpenGL compute pass. In clustered shading architectures, screen space and view depth are subdivided into a three-dimensional grid of bounding boxes. By executing a compute shader over these clusters, the rendering pipeline evaluates geometric light-volume intersections, builds a unified global light index list using atomic operations, and populates per-cluster indirection records for efficient lookups during the final shading stage.

The Cluster Grid and Memory Architecture

Clustered shading divides the camera frustum into a three-dimensional grid of Axis-Aligned Bounding Boxes (AABBs). The \(X\) and \(Y\) dimensions are segmented along screen-space tiles, while the \(Z\) dimension is partitioned using a non-linear (often logarithmic) depth distribution to match perspective projection precision.

To link dynamic lights to these spatial volumes within OpenGL, the system relies on three primary Shader Storage Buffer Objects (SSBOs):

  1. Light Data Buffer: A read-only array containing all active scene lights (position, radius, color, and type).
  2. Global Light Index List: A flat, linear array of unsigned integers storing the IDs of lights that intersect active clusters.
  3. Cluster Grid Buffer: An array indexed by the 3D cluster coordinate, where each entry contains a pair of integers: offset (the starting position in the Global Light Index List) and count (the number of lights affecting that specific cluster).

The Compute Pass Dispatch

The assignment pass executes via an indirect or direct dispatch (glDispatchCompute) where the compute space maps to the cluster dimensions:

glDispatchCompute(gridDimX, gridDimY, gridDimZ);

Each compute workgroup or invocation identifies its unique spatial volume using gl_GlobalInvocationID. The shader retrieves the precomputed AABB for that cluster from a spatial bounds buffer or calculates the min/max extents on the fly from the camera's inverse projection matrix.

Light Culling and Local Accumulation

Processing lights directly against global memory creates high memory bus contention due to concurrent atomic writes. To mitigate this, compute shaders perform local culling using workgroup shared memory (shared uint):

  1. Workgroup Cooperative Loading: Invocations within a workgroup load scene lights in parallel batches.
  2. Bounding Intersection Test: For each light, the shader performs an intersection test between the light's volume (such as a bounding sphere for point lights or a bounding cone for spotlights) and the cluster’s AABB.
  3. Shared List Assembly: If a light intersects the cluster, its global array index is appended to a workgroup-shared list using atomicAdd on a shared counter variable.

Linking Local Lights to Global Storage

Once the intersection pass completes for all active scene lights, the locally accumulated list must be committed to the global buffers. This linking step establishes the indirection mechanism:

  1. Global Allocation: A single thread within the workgroup executes an atomic addition (atomicAdd) on a global counter located at the head of the Global Light Index List SSBO. This reservation returns a unique global offset corresponding to the starting position reserved exclusively for that cluster.
  2. Writing the Index List: Threads in the workgroup collaboratively copy the light indices from the shared memory array to the Global Light Index List SSBO, starting at the newly acquired global offset.
  3. Writing Cluster Indirection Records: The thread writes the resulting global offset and the total light count into the Cluster Grid Buffer at the index corresponding to gl_GlobalInvocationID:
// Concept within the compute shader
uint globalOffset = atomicAdd(globalIndexCounter, localLightCount);

for (uint i = gl_LocalInvocationIndex; i < localLightCount; i += gl_WorkGroupSize.x) {
    globalLightIndexList[globalOffset + i] = localLightIndices[i];
}

if (gl_LocalInvocationIndex == 0) {
    clusterGrid[clusterIndex].offset = globalOffset;
    clusterGrid[clusterIndex].count = localLightCount;
}

Consumption in Shading Passes

During the subsequent geometry or forward-plus shading pass, the fragment shader computes its fragment's cluster coordinate \((X, Y, Z)\) using screen coordinates and depth buffer values.

The fragment shader reads the cluster record from the Cluster Grid Buffer, extracts the offset and count, and loops strictly over that subset of elements within the Global Light Index List. This decouples scene light complexity from pixel evaluation, ensuring that fragments only iterate through lights that physically intersect their local 3D spatial cluster.
