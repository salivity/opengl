Floating-Point Texture Filtering in OpenGL ES

This article covers the fundamentals of floating-point texture filtering in mobile computer graphics and details the specific OpenGL ES versions that require extensions to support it. Floating-point textures allow developers to store high-precision numerical data beyond standard 8-bit color channels, but interpolating between these values requires specialized hardware capabilities. Understanding which OpenGL ES specifications mandate extensions for linear filtering is critical for implementing techniques such as high dynamic range (HDR) rendering, bloom, and shadow mapping across diverse mobile hardware.

What is Floating-Point Texture Filtering?

Standard textures store color values as normalized 8-bit integers per channel (GL_UNSIGNED_BYTE), representing values from 0.0 to 1.0. Floating-point textures instead store values as 16-bit half-precision (GL_HALF_FLOAT) or 32-bit single-precision (GL_FLOAT) numbers. These formats can represent values far outside the [0.0, 1.0] range and maintain significantly higher numerical accuracy.

Texture filtering is the process of calculating color values for texture coordinates that do not map directly to a single texel. When using nearest-neighbor filtering (GL_NEAREST), the GPU selects the closest single texel. Linear filtering (GL_LINEAR), however, interpolates between adjacent texels to produce smooth gradients and eliminate pixelation. Floating-point texture filtering specifically refers to performing this bilinear or trilinear interpolation natively on 16-bit or 32-bit floating-point data inside the GPU's texture mapping units (TMUs).

Because interpolating floating-point numbers demands substantially more memory bandwidth and dedicated arithmetic logic than standard integer formats, mobile GPU architectures historically omitted hardware-level float filtering to save silicon area and battery power.

OpenGL ES Version Support and Required Extensions

Support for floating-point texture filtering varies significantly depending on the target OpenGL ES version and whether 16-bit or 32-bit formats are used.

OpenGL ES 2.0

In OpenGL ES 2.0, floating-point textures are not part of the core specification. Both the formats themselves and the ability to filter them require dedicated extensions:

  • 16-bit float filtering: Requires GL_OES_texture_half_float to create the textures, and GL_OES_texture_half_float_linear to enable GL_LINEAR filtering modes.
  • 32-bit float filtering: Requires GL_OES_texture_float for format support, and GL_OES_texture_float_linear to enable GL_LINEAR filtering modes.

Without the corresponding linear extension, attempting to set GL_TEXTURE_MIN_FILTER or GL_TEXTURE_MAG_FILTER to GL_LINEAR results in an incomplete texture or undefined rendering behavior.

OpenGL ES 3.0 and 3.1

OpenGL ES 3.0 integrated 16-bit half-precision floating-point formats (such as GL_RGBA16F and GL_R16F) directly into the core specification, mandating linear filtering support for these formats without extensions.

However, 32-bit floating-point formats (such as GL_RGBA32F and GL_R32F) remain restricted:

  • 16-bit float filtering: Supported in the core specification. No extension is required.
  • 32-bit float filtering: Core specifications only mandate GL_NEAREST filtering. To use GL_LINEAR filtering with 32-bit floating-point textures, devices must support the GL_OES_texture_float_linear extension.

OpenGL ES 3.2

Even in OpenGL ES 3.2, 32-bit float filtering remains an optional hardware feature:

  • 16-bit float filtering: Core feature; no extension needed.
  • 32-bit float filtering: Still requires the GL_OES_texture_float_linear extension.

While almost all modern mobile chipsets support this extension, applications relying on 32-bit linear texture filtering must query the extension string at runtime to ensure compatibility before configuring linear sampler states.
