How GL_DEPTH24_STENCIL8 Conserves OpenGL Bandwidth

Packed depth-stencil formats like GL_DEPTH24_STENCIL8 conserve memory bandwidth by combining a 24-bit depth value and an 8-bit stencil value into a single, contiguous 32-bit word per pixel. Instead of requiring the GPU to issue separate memory transactions over the memory bus for independent depth and stencil buffers, this packed layout enables synchronized, single-transaction reads and writes. This structure optimizes GPU cache line utilization, aligns naturally with modern hardware memory architectures, and eliminates redundant bus traffic during rendering passes that perform simultaneous depth and stencil testing.

Native 32-Bit Alignment

Modern GPU memory controllers and cache hierarchies are fundamentally optimized for power-of-two data words, predominantly 32-bit, 64-bit, or 128-bit aligned addresses. Allocating an isolated 24-bit depth buffer causes memory alignment challenges: the hardware must either pad the 24-bit values to 32 bits—wasting 25% of the allocated memory without any functional benefit—or handle unaligned memory accesses, which degrade performance.

By pairing the 24-bit depth value with an 8-bit stencil value, GL_DEPTH24_STENCIL8 forms an exact 32-bit (4-byte) structure. This alignment matches native GPU memory channels perfectly, maximizing throughput for every byte transmitted across the memory bus.

Single-Cycle Memory Transactions

During typical rasterization, the fragment processing pipeline evaluates both depth and stencil tests simultaneously for every generated fragment. If depth and stencil data reside in distinct buffers (such as an independent GL_DEPTH_COMPONENT24 and GL_STENCIL_INDEX8), the GPU memory controller must generate two separate memory addresses, fetch from two different memory regions, and wait for two round-trip requests.

With GL_DEPTH24_STENCIL8, the GPU fetches both components in a single memory transaction. When reading the depth value to evaluate visibility, the stencil value arrives in the same payload at no additional transfer cost. When a fragment updates both buffers, a single 32-bit write operation commits both states to video memory, effectively halving the number of individual read/write operations issued over the bus.

Spatial Locality and Cache Line Efficiency

GPUs transfer data between VRAM and the L1/L2 caches in fixed-size blocks known as cache lines, usually 64 or 128 bytes wide. Storing depth and stencil values interleaved in a single texture ensures high spatial locality.

A single 64-byte cache line request brings in the complete depth and stencil payload for 16 contiguous screen pixels. If the components were decoupled, the GPU would need to load two separate cache lines—one from the depth allocation and one from the stencil allocation—to process the same 16 pixels. By doubling the functional density of each fetched cache line, GL_DEPTH24_STENCIL8 prevents cache thrashing and preserves cache capacity for color textures and geometry data.

Co-located Hierarchical Z and Stencil Traversal

Modern GPUs incorporate hardware-level compression mechanisms, such as Hierarchical Z (HiZ) and Hierarchical Stencil (HiStencil), to discard non-visible pixels prior to fragment shading. When depth and stencil share a unified surface format, the GPU's rasterizers can track tiled visibility metadata across both planes concurrently. This shared tile metadata allows the memory controller to quickly determine whether a 32-bit block needs to be fetched from main VRAM at all, avoiding memory bus round-trips for fully occluded geometry.
