OpenGL Polygon Clipping Algorithm Explained

In the OpenGL graphics pipeline, polygon clipping removes primitive geometry falling outside the visible view frustum before rasterization occurs. Under the hood, modern OpenGL hardware implementations primarily rely on the Sutherland-Hodgman algorithm adapted for 4D homogeneous coordinates, frequently augmented by guard-band clipping to optimize performance. This article explains how the Sutherland-Hodgman algorithm operates within the hardware pipeline, how clipping occurs in homogeneous space, and how modern GPUs streamline this process.

The Core Algorithm: Sutherland-Hodgman

The standard algorithm used for polygon clipping in graphics hardware is the Sutherland-Hodgman polygon clipping algorithm. It is designed specifically to clip arbitrary planar polygons against a convex volume, making it an ideal fit for the OpenGL viewing frustum.

The algorithm works through a divide-and-conquer strategy:

  1. The viewing volume is defined by a series of bounding boundary planes (near, far, left, right, top, and bottom).
  2. The polygon is clipped sequentially against one boundary plane at a time.
  3. For each plane, the algorithm iterates through the polygon's vertices edge-by-edge. Depending on whether the endpoints of an edge lie inside, outside, or cross the boundary, the algorithm either keeps the vertex, discards it, or calculates a new intersection point to emit a modified polygon.
  4. The output polygon of one plane becomes the input to the next clipping plane.

Because each plane is processed independently and in a fixed order, the Sutherland-Hodgman algorithm translates cleanly into a hardware pipeline. Each clipping plane can be implemented as a dedicated pipeline stage, allowing vertex data to stream continuously from one stage to the next without waiting for the entire polygon to be processed.

Homogeneous Coordinates Clipping (Blinn-Newell Extension)

In OpenGL, clipping does not occur in 3D Normalized Device Coordinates (NDC); it takes place immediately after the vertex or geometry shader in clip coordinates \((x_c, y_c, z_c, w_c)\), before the perspective divide (\(x_c/w_c\)).

Performing clipping prior to division avoids mathematical singularities (such as dividing by zero when a vertex lies directly on the projection plane) and prevents projection inversion for geometry behind the camera (\(w_c < 0\)).

To accomplish this, hardware implements the homogeneous variation of the Sutherland-Hodgman algorithm, often credited to Jim Blinn and Martin Newell. Instead of evaluating Euclidean distances, the hardware tests vertices against six linear inequalities:

  • \(-w_c \le x_c \le w_c\) (Left and Right planes)
  • \(-w_c \le y_c \le w_c\) (Bottom and Top planes)
  • \(-w_c \le z_c \le w_c\) (Near and Far planes, assuming default OpenGL depth ranges)

When an edge crosses a boundary, the intersection parameter \(t \in [0, 1]\) is computed directly in 4D space, and all vertex attributes (such as texture coordinates, normals, and colors) are linearly interpolated along the edge using this factor.

Hardware Optimization: Guard-Band Clipping

While the Sutherland-Hodgman algorithm represents the fundamental mathematical model, generating new vertices and primitives via geometric clipping in hardware is computationally expensive. As a result, modern GPU architectures incorporate an optimization known as guard-band clipping.

The GPU defines an internal "guard band" region in screen space that extends significantly beyond the edges of the visible viewport. If a primitive resides outside the viewport but entirely inside the guard band:

  • The hardware skips geometric clipping entirely.
  • No new vertices or triangles are created.
  • The primitive is sent directly to the rasterizer, where sample points falling outside the actual viewport are efficiently discarded via screen-space scissoring.

Hardware Sutherland-Hodgman clipping is reserved only for primitives that intersect the near and far planes, or that cross the outer boundaries of the extended guard band.
