Cascaded Shadow Mapping for Large View Distances in OpenGL

Cascaded Shadow Mapping (CSM) resolves the problem of perspective aliasing across expansive open-world scenes by dividing the camera's viewing frustum into multiple depth partitions, allocating an independent shadow map to each segment. In standard shadow mapping, a single depth texture stretched over a vast rendering distance causes severe pixelation near the viewer and wasted resolution in the distance. By scaling the light-space orthographic projection to tightly fit each depth slice, CSM distributes texels proportional to human visual perception, ensuring crisp, high-resolution shadows near the camera while gracefully scaling across far-off terrain in OpenGL.

Frustum Partitioning

The primary mechanism behind CSM is slicing the player camera's view frustum along the Z-axis into separate sub-frustums, or "cascades" (typically 3 to 5). Because perspective projection causes objects close to the camera to occupy significantly more screen space than distant objects, depth partitions are calculated non-linearly using a hybrid logarithmic and practical split scheme:

\[\text{Split}_i = \lambda \cdot n \cdot \left(\frac{f}{n}\right)^{\frac{i}{m}} + (1 - \lambda) \cdot \left(n + \frac{i}{m}(f - n)\right)\]

Where \(n\) and \(f\) are the camera near and far planes, \(m\) is the total number of cascades, \(i\) is the current cascade index, and \(\lambda\) is a balancing factor. This formula ensures that the near planes receive tighter, more concentrated slices, while distant planes span significantly larger volumes.

Fitting Light-Space Projections

For each camera sub-frustum, an optimal light-space bounding box must be determined:

  1. Frustum Corner Extraction: Transform the eight corners of each sub-frustum slice from clip space back into world space using the inverse view-projection matrix of the camera.
  2. Light-Space Transformation: Transform these world-space corners into the directional light's coordinate space using the light’s view matrix.
  3. Axis-Aligned Bounding Box (AABB): Calculate the minimum and maximum coordinates (\(X, Y, Z\)) enclosing the transformed corners.
  4. Orthographic Projection: Construct an orthographic projection matrix for each cascade using these tight bounds.

Because the nearest cascade encloses a relatively small volume of 3D space, its shadow map achieves high texel density per world unit. Successive cascades cover progressively larger areas, lowering world-space texel density where distant objects naturally occupy fewer screen pixels, matching the perspective projection of the player's eye.

Texel Stabilization and Flickering Reduction

As the player moves, the calculated bounding boxes can shift by sub-texel increments, resulting in shimmering or crawling shadow edges. To maintain stable shadow edges across frames, the light-space bounding box must be snapped to increments of the shadow map's texel size:

float worldUnitsPerTexel = (maxX - minX) / shadowMapResolution;
minX = std::floor(minX / worldUnitsPerTexel) * worldUnitsPerTexel;
maxX = std::floor(maxX / worldUnitsPerTexel) * worldUnitsPerTexel;
minY = std::floor(minY / worldUnitsPerTexel) * worldUnitsPerTexel;
maxY = std::floor(maxY / worldUnitsPerTexel) * worldUnitsPerTexel;

OpenGL Implementation Details

Efficient CSM rendering in modern OpenGL leverages specific rendering primitives and memory structures:

  • 2D Texture Arrays (GL_TEXTURE_2D_ARRAY): Rather than creating individual textures for each cascade, an array texture is allocated. This allows all cascades to share the same texture unit, avoiding state changes and texture binds during the main lighting pass.
  • Uniform Buffer Objects (UBOs): The light-space view-projection matrices and split distances for all cascades are passed to shaders via a shared UBO, providing uniform access during geometry evaluation.
  • Layered Rendering via Geometry Shaders: During the depth-pass, developers can render the scene's geometry once and use a Geometry Shader with gl_Layer to duplicate primitives into their respective cascade layers, or perform multiple instanced draws to minimize CPU draw-call overhead.

Fragment Shader Sampling and Cascade Selection

During the final shading pass, the fragment shader determines which cascade to sample based on the fragment’s view-space depth (\(z\) coordinate):

  1. Compare the fragment's linear view-space depth against the cascade split distances.
  2. Identify the appropriate cascade index \(i\).
  3. Transform the world position using the corresponding cascade light-space matrix.
  4. Perform standard Percentage Closer Filtering (PCF) using sampler2DArrayShadow.

To eliminate hard, visible boundaries between adjacent cascades where texel densities differ, a blend region is established. Fragments located within the transition zone sample both the current and adjacent cascades, linearly interpolating the resulting shadow factors to ensure a seamless visual continuum across the entire view distance.
