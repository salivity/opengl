GPU Frustum Culling in OpenGL Using Compute Shaders

This article explains how to move frustum culling from the CPU to the GPU using OpenGL compute shaders and indirect drawing. By processing bounding volumes on the graphics card and generating draw commands directly in GPU memory, applications can eliminate CPU-side traversal bottlenecks, bypass driver submission overhead, and render massive scenes with thousands of individual meshes in a single draw invocation.

The Pipeline Architecture

Traditional frustum culling requires the CPU to test every entity's bounding volume against the camera's view frustum, construct a list of visible render commands, and submit them individually or in batches to the GPU. This approach creates significant CPU-GPU synchronization overhead and driver bottlenecks.

Offloading this process to the GPU relies on three core OpenGL components:

  1. Shader Storage Buffer Objects (SSBOs): Store per-instance metadata (model matrices, bounding spheres/boxes, and mesh descriptors).
  2. Compute Shaders: Perform parallel sphere or axis-aligned bounding box (AABB) intersection tests against the camera’s view frustum planes.
  3. Indirect Draw Buffers: Store draw commands that the compute shader generates dynamically, which are then consumed by glMultiDrawElementsIndirect or glMultiDrawArraysIndirect.

1. Data Structures and Memory Layout

In modern OpenGL, indirect draw commands mirror the standard draw parameters in memory. For indexed geometry, define the command structure matching the standard specification:

struct DrawElementsIndirectCommand {
    GLuint count;         // Number of indices to draw
    GLuint instanceCount; // Number of instances to draw (typically 1 for non-instanced)
    GLuint firstIndex;    // Base index in the index buffer
    GLint  baseVertex;    // Offset added to each index
    GLuint baseInstance;  // Base instance ID for instanced rendering
};

You must allocate three primary GPU buffers:

  • Object Data Buffer (SSBO): Contains world-space bounding volumes (center and radius for spheres, or min/max extents for AABBs) and an index pointing to mesh properties.
  • Draw Command Template Buffer (SSBO): Contains pre-populated DrawElementsIndirectCommand templates for each mesh in your scene.
  • Output Indirect Command Buffer (GL_DRAW_INDIRECT_BUFFER): Receives the commands for meshes that pass the visibility test.
  • Atomic Counter / Indirect Count Buffer: Tracks the total number of visible objects passed to the final draw call.

2. Computing Frustum Planes

Extract the six frustum planes on the CPU from the camera's View-Projection matrix using the Gribb-Hartmann method, normalize them, and upload them to a uniform block or directly into the compute shader:

// A frustum plane represented as ax + by + cz + d = 0
struct Plane {
    vec3 normal;
    float distance;
};

layout(std140, binding = 0) uniform CameraData {
    mat4 viewMatrix;
    mat4 projectionMatrix;
    Plane frustumPlanes[6];
};

3. The Compute Shader Culling Pass

The compute shader executes one thread per candidate object, performs the intersection test, and writes visible commands to the output buffer.

#version 460 core

layout(local_size_x = 64, local_size_y = 1, local_size_z = 1) in;

struct BoundingSphere {
    vec3 center;
    float radius;
};

struct DrawCommand {
    uint count;
    uint instanceCount;
    uint firstIndex;
    int  baseVertex;
    uint baseInstance;
};

layout(std430, binding = 1) readonly buffer ObjectBuffer {
    BoundingSphere objects[];
};

layout(std430, binding = 2) readonly buffer CommandTemplates {
    DrawCommand inputCommands[];
};

layout(std430, binding = 3) writeonly buffer FilteredCommands {
    DrawCommand outputCommands[];
};

layout(binding = 0) uniform atomic_uint visibleCount;

bool isVisible(vec3 center, float radius) {
    for (int i = 0; i < 6; ++i) {
        if (dot(frustumPlanes[i].normal, center) + frustumPlanes[i].distance < -radius) {
            return false;
        }
    }
    return true;
}

void main() {
    uint id = gl_GlobalInvocationID.x;
    if (id >= objects.length()) return;

    BoundingSphere sphere = objects[id];

    if (isVisible(sphere.center, sphere.radius)) {
        uint outputIndex = atomicCounterIncrement(visibleCount);
        outputCommands[outputIndex] = inputCommands[id];
    }
}

4. Synchronization and Indirect Execution

Before executing the draw call, you must insert an explicit memory barrier to ensure all compute shader writes to the command buffer and counter are committed:

// 1. Reset visible counter to 0
GLuint zero = 0;
glBindBuffer(GL_ATOMIC_COUNTER_BUFFER, counterBuffer);
glBufferSubData(GL_ATOMIC_COUNTER_BUFFER, 0, sizeof(GLuint), &zero);

// 2. Dispatch compute shader
glUseProgram(cullComputeProgram);
glDispatchCompute((numObjects + 63) / 64, 1, 1);

// 3. Insert memory barriers for command and indirect buffer access
glMemoryBarrier(GL_COMMAND_BARRIER_BIT | GL_SHADER_STORAGE_BARRIER_BIT);

// 4. Bind geometry and indirect buffer
glBindVertexArray(sceneVAO);
glBindBuffer(GL_DRAW_INDIRECT_BUFFER, outputCommandBuffer);

// 5. Execute indirect rendering
// If using GL_ARB_indirect_parameters (OpenGL 4.6 core):
glBindBuffer(GL_PARAMETER_BUFFER_ARB, counterBuffer);
glMultiDrawElementsIndirectCount(
    GL_TRIANGLES,
    GL_UNSIGNED_INT,
    0,                  // Indirect buffer offset
    0,                  // Parameter buffer offset (stores draw count)
    numObjects,         // Maximum draw count
    sizeof(DrawElementsIndirectCommand)
);

If OpenGL 4.6 (or GL_ARB_indirect_parameters) is unavailable, you can read back the counter value using glGetBufferSubData to supply the draw count to glMultiDrawElementsIndirect. However, this introduces a minor GPU pipeline stall. Alternatively, set instanceCount inside the inputCommands directly to 0 for culled objects, and issue a full glMultiDrawElementsIndirect across all objects without altering array indices; hardware will skip draw instances where instanceCount == 0.
