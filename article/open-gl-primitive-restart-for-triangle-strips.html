OpenGL Primitive Restart for Triangle Strips

Primitive restart in OpenGL is a rendering mechanism that allows developers to pack multiple disconnected triangle strips into a single index buffer and render them using a single draw call. Instead of dispatching separate draw commands or artificially stitching geometry together with degenerate triangles, OpenGL monitors the index stream for a designated sentinel value. When this value is encountered, the GPU terminates the current triangle strip and begins a new one with the subsequent vertices. This approach reduces draw call overhead, optimizes memory bandwidth, and simplifies buffer management for complex, fragmented meshes.

The Problem with Disconnected Triangle Strips

A standard triangle strip (GL_TRIANGLE_STRIP) constructs each subsequent triangle using the preceding two vertices. For a continuous surface, this significantly minimizes vertex duplication compared to standard triangle lists (GL_TRIANGLES). However, complex models rarely consist of a single, continuous topological surface; they often contain holes, sharp boundaries, or multiple distinct components.

Historically, rendering multiple disjoint strips required two suboptimal solutions:

  1. Multiple Draw Calls: Invoking glDrawElements separately for every single strip. This introduces substantial CPU-to-GPU command processing overhead.
  2. Degenerate Triangles: Inserting redundant, duplicate vertices at the boundary between two strips to produce zero-area triangles. While the GPU quickly discards these degenerate triangles during rasterization, they still consume index buffer space, occupy cache, and require vertex shader invocation.

How OpenGL Executes Primitive Restart

Primitive restart solves these inefficiencies directly at the hardware pipeline level within the Input Assembler stage.

When primitive restart is active, OpenGL scans the index buffer during indexed draw calls (such as glDrawElements or glDrawElementsInstanced). As soon as the GPU reads an index value that matches the configured restart index:

  1. It immediately flushes the internal vertex assembly queue.
  2. The current triangle strip topology is finalized.
  3. The restart index itself is discarded and does not produce a vertex.
  4. The vertex pipeline resets its winding order rules.
  5. The subsequent indices are treated as the beginning of an entirely independent primitive strip, requiring three new vertices to construct the first triangle of the new strip.

Configuration in OpenGL

To use primitive restart, developers specify the restart index and enable the capability using the OpenGL API.

Manual Restart Index (OpenGL 3.1+)

In OpenGL 3.1 and later, developers can explicitly assign an arbitrary value to act as the restart sentinel:

glEnable(GL_PRIMITIVE_RESTART);
glPrimitiveRestartIndex(0xFFFFFFFF);

When rendering with 32-bit unsigned integers (GL_UNSIGNED_INT), 0xFFFFFFFF is the standard choice because it sits at the absolute limit of the addressable range, minimizing collisions with valid vertex indices.

Fixed Index Primitive Restart (OpenGL 4.3+ / Core Profile)

OpenGL 4.3 introduced fixed-index primitive restart (GL_PRIMITIVE_RESTART_FIXED_INDEX). This modern approach eliminates the need to call glPrimitiveRestartIndex by automatically using the maximum possible integer value supported by the index data type:

  • 0xFF for GL_UNSIGNED_BYTE
  • 0xFFFF for GL_UNSIGNED_SHORT
  • 0xFFFFFFFF for GL_UNSIGNED_INT

It is enabled as follows:

glEnable(GL_PRIMITIVE_RESTART_FIXED_INDEX);

Buffer Layout Example

Consider two separate triangle strips composed of four vertices each:

  • Strip 1: Vertices 0, 1, 2, 3
  • Strip 2: Vertices 4, 5, 6, 7

Without primitive restart, combining these into one strip requires degenerate indices: [0, 1, 2, 3, 3, 4, 4, 5, 6, 7]

With primitive restart enabled and a restart index of 0xFFFF, the combined index array is structured cleanly: [0, 1, 2, 3, 0xFFFF, 4, 5, 6, 7]

The GPU processes vertices 0 through 3 to draw two triangles, encounters 0xFFFF, resets its strip assembler, and processes vertices 4 through 7 to draw the second set of two triangles.

Performance Implications

Using primitive restart provides distinct performance benefits when dealing with complex triangle strips:

  • Index Density: Eliminates the extra index overhead associated with degenerate transitions.
  • Cache Efficiency: Avoids phantom vertex shader executions that can occur when generating degenerate triangles.
  • Reduced Batching Overhead: Consolidates hundreds or thousands of separate geometric fragments into a single draw command, maximizing GPU pipeline saturation.
