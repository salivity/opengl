Forsyth Vertex Cache Optimization for OpenGL

The Forsyth vertex cache algorithm optimizes 3D mesh rendering by reordering index buffers to maximize the hit rate of a graphics processing unit’s (GPU) post-transform vertex cache. By prioritizing triangles containing recently transformed vertices and vertices belonging to few remaining faces, the algorithm significantly reduces redundant vertex shader invocations during OpenGL draw calls such as glDrawElements. This article explains the mechanics of post-transform vertex caches, the scoring heuristics behind the Forsyth algorithm, and how this optimization directly improves rendering throughput in OpenGL.

The Post-Transform Vertex Cache

Modern GPUs utilize a fixed-capacity, post-transform vertex cache (typically operating with a Least Recently Used (LRU) or FIFO policy, holding roughly 16 to 64 vertices). When OpenGL processes indexed primitive rendering—such as indexed triangle lists—the vertex fetch hardware checks this cache before executing the vertex shader:

  1. Cache Hit: If an incoming vertex index has already been transformed and resides in the cache, the GPU skips vertex shader execution entirely and reuses the cached output attributes.
  2. Cache Miss: If the vertex is not present, the vertex shader executes, the result is written to the cache, and older entries may be evicted.

The performance of an indexed draw call is measured by the Average Cache Miss Ratio (ACMR), defined as the total number of vertex shader invocations divided by the total number of triangles. For an unoptimized mesh, ACMR often approaches 3.0 (each triangle misses all three vertices). A fully optimized manifold mesh can approach the theoretical lower limit of approximately 0.5.

The Forsyth Scoring Heuristic

Developed by Tom Forsyth, this algorithm simulates a local LRU vertex cache to evaluate and sort triangles. Instead of global path searches, it uses a greedy approach that assigns dynamic scores to vertices and selects the best candidate triangle at each step.

A vertex's total score is the sum of two distinct calculations:

1. Cache Position Score

Vertices currently inside the simulated cache receive a score based on their position. Vertices accessed very recently receive high scores, reflecting the high probability of a cache hit:

  • If a vertex was used in the most recent triangle (index 0 to 2), it receives a fixed maximum boost.
  • If it resides deeper in the cache, the score drops off using an exponential decay function: score = (1 - (cache_index - 3) / (cache_size - 3)) ^ power.
  • If the vertex is not in the cache, its cache score is zero.

2. Valence Score

Valence refers to the number of remaining, unrendered triangles that share a given vertex. Vertices with lower valence are prioritized using a power function: score = valence ^ (-power).

This design avoids leaving behind "stranded" or "orphaned" vertices. When a vertex is down to its last remaining triangle, completing that triangle frees the vertex permanently, ensuring it does not re-enter the cache at a later time.

The Selection and Emitting Loop

  1. Score Calculation: The algorithm computes scores for all active vertices and sums the three vertex scores for each candidate triangle to determine each triangle's score.
  2. Triangle Emission: The triangle with the highest score is appended to the optimized index buffer.
  3. State Update:
    • The emitted triangle's vertices are inserted into the simulated LRU cache.
    • The valence (unrendered triangle count) of each used vertex is decremented.
    • Scores are updated only for the affected vertices and their neighboring triangles, maintaining linear \(O(N)\) execution time.
  4. Iteration: The process repeats until all triangles are emitted. If the cache runs dry of unrendered candidates, the algorithm falls back to the remaining triangle with the highest score elsewhere in the mesh.

Integration with OpenGL Draw Passes

The Forsyth algorithm acts strictly as an offline or asset-conditioning preprocessing step. It outputs an updated element array (GL_ELEMENT_ARRAY_BUFFER) without altering the geometry or vertex attribute buffer (GL_ARRAY_BUFFER).

When passing the reordered index array to OpenGL:

  • Functions like glDrawElements or glDrawRangeElements process consecutive indices that repeatedly reference recently loaded vertices.
  • Pipeline stalls waiting on vertex shader execution stages are minimized.
  • Memory bandwidth across the bus is reduced, benefiting both desktop architectures with complex vertex shaders and mobile GPUs using tile-based deferred rendering (TBDR).
