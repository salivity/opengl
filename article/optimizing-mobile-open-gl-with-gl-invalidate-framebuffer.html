Optimizing Mobile OpenGL with glInvalidateFramebuffer

In mobile OpenGL ES development, discarding depth attachments using glInvalidateFramebuffer is a critical performance optimization that eliminates redundant memory bandwidth usage. Mobile GPUs rely heavily on tile-based architectures, and signaling to the driver that depth information is no longer needed after rendering prevents the hardware from writing transient depth data from fast on-chip memory back to the device's system RAM, dramatically reducing power consumption and frame rendering times.

Tile-Based Architectures and Memory Hierarchy

Unlike desktop GPUs that typically use immediate-mode rendering, mobile GPUs (such as ARM Mali, Qualcomm Adreno, and Imagination PowerVR) utilize Tile-Based Rendering (TBR) or Tile-Based Deferred Rendering (TBDR). In these architectures, the screen is subdivided into small grids called tiles (commonly 16x16 or 32x32 pixels).

Each tile is processed sequentially inside an extremely fast, low-latency, on-chip tile buffer. All color blending, depth testing, and stencil evaluations occur entirely within this local cache without accessing main system memory (DRAM).

The Bottleneck: Unnecessary Memory Write-Back

Once the GPU finishes rendering primitives for a specific tile, it must resolve and flush the results out of the on-chip memory into main DRAM so the final image can be displayed or used in later passes.

By default, the OpenGL ES driver assumes that every attachment—color, depth, and stencil—might be read later by the application. Consequently, the driver writes the depth buffer contents to system RAM alongside the color buffer. For a standard 1080p or 1440p frame, writing a 24-bit or 32-bit depth buffer to DRAM requires tens of megabytes of bandwidth per frame.

Because mobile devices share memory bandwidth between the CPU and GPU, and because mobile memory buses operate under strict power and thermal budgets, this write-back step introduces high latency, thermal throttling, and battery drain.

How glInvalidateFramebuffer Solves the Problem

In the vast majority of rendering pipelines, the depth buffer is only required to determine visibility during the drawing of opaque and transparent geometry within that specific frame. Once the color image is resolved, the depth data becomes completely obsolete.

Calling glInvalidateFramebuffer (or glDiscardFramebufferEXT in OpenGL ES 2.0) before unbinding the framebuffer or presenting to the screen explicitly notifies the GPU driver that the specified attachments are no longer required:

GLenum attachments[] = { GL_DEPTH_ATTACHMENT, GL_STENCIL_ATTACHMENT };
glInvalidateFramebuffer(GL_FRAMEBUFFER, 2, attachments);

When this command is issued before the tile resolve step:

  1. Avoids Write-Back: The hardware simply discards the depth data directly from the on-chip tile memory instead of streaming it out to external RAM.
  2. Saves System Bandwidth: Memory bandwidth consumption is cut significantly, often by 30% to 50% for standard render passes.
  3. Reduces Thermal Output: Limiting external bus transactions keeps GPU temperatures lower, preventing automatic clock-rate throttling during sustained gaming or intensive workloads.
  4. Improves Frame Rates: Eliminating the memory transfer decreases GPU idle wait times, smoothing out frame pacing.
