OpenGL Sampler Arrays and Dynamic Indexing Stalls

This article examines OpenGL sampler arrays, distinguishing them from texture arrays, and explains how dynamic indexing functions within GLSL shaders. It breaks down the low-level hardware architecture—specifically warp divergence and texture unit arbitration—that causes dynamically indexed sampler arrays to induce costly GPU pipeline stalls, and provides modern rendering alternatives to maintain high throughput.

What is an OpenGL Sampler Array?

In GLSL, a sampler array is an array of texture handles declared as a uniform, such as uniform sampler2D textures[8];. Each element in the array represents a distinct texture image unit bound to an independent texture object.

It is important to differentiate a sampler array from a 2D texture array (sampler2DArray). A texture array is a single OpenGL texture object containing multiple slices or layers that all share the same dimensions, format, and filtering parameters. In contrast, a sampler array is a collection of entirely separate texture samplers, each capable of pointing to different texture targets, formats, resolutions, and sampling states.

Static vs. Dynamic Indexing

When accessing elements in a sampler array, GLSL distinguishes between constant (compile-time) expressions, dynamically uniform expressions, and non-uniform dynamic expressions:

  • Static Indexing: The index is a compile-time constant (e.g., textures[2]). The compiler resolves the exact texture unit directly before execution.
  • Dynamically Uniform Indexing: The index is calculated at runtime (e.g., via a uniform variable), but it evaluates to the exact same value across all invocations within a draw call or dispatch group.
  • Non-Uniform Dynamic Indexing: The index varies across shader invocations within the same draw call, such as an index derived from vertex attributes, fragment coordinates, or texture fetches (e.g., textures[materialIndex]).

GLSL requirements around dynamic sampler indexing have historically been strict. Prior to GLSL 4.0 and the GL_ARB_gpu_shader5 extension, indexing sampler arrays with non-constant expressions was invalid. Even in modern GLSL, non-uniform dynamic indexing requires the explicit use of nonuniformEXT() to prevent undefined behavior.

Why Dynamic Indexing Triggers Pipeline Stalls

Modern GPUs process parallel work (vertices or fragments) in lockstep groups called warps (NVIDIA) or wavefronts (AMD), typically comprising 32 or 64 threads executing identical instructions via SIMD (Single Instruction, Multiple Data) or SIMT (Single Instruction, Multiple Threads).

When a shader dynamically indexes a sampler array in a non-uniform manner, it creates severe hardware bottlenecks:

1. Warp Divergence and Serialization

When threads within the same warp request different samplers simultaneously, execution diverges. Because standard hardware texture fetch units are configured to dispatch instructions against a single texture state per cycle across the warp, the GPU cannot execute the texture fetch in parallel. The warp must serialize its memory operations, executing one unique texture fetch at a time while masking out non-participating threads. This directly multiplies the latency of the texture instruction by the number of unique textures requested within that single warp.

2. Texture Descriptor Cache Thrashing

Textures are accessed via descriptors—small state blocks containing the memory address, format, mipmap levels, and filtering modes of the texture. GPUs feature small, low-latency caches specifically for these descriptors. Static access allows these descriptors to be prefetched and cached uniformly. Non-uniform dynamic indexing forces rapid, scattered reads across the texture descriptor table, evicting active descriptors, stalling the instruction unit, and waiting for descriptor fetches from higher-latency memory levels.

3. Loss of Hardware Derivative Calculations

Implicit Level of Detail (LOD) and anisotropic filtering rely on hardware derivatives (dFdx, dFdy), which calculate coordinate deltas across a \(2 \times 2\) quad of adjacent fragment pixels. If neighboring fragments in a quad index different textures, comparing their coordinates becomes meaningless. The hardware must fall back to conservative or serialized LOD evaluations, introducing pipeline stalls as the rasterizer waits for valid sampling coordinates to be resolved.

Solutions to Avoid Stalls

To bypass the performance cost of dynamic sampler indexing:

  • Use Texture Arrays (sampler2DArray): Pack textures of identical dimensions into a single array object. The layer is chosen via the third coordinate vector (u, v, layer), which is evaluated natively per fragment without triggering sampler divergence or pipeline serialization.
  • Use Bindless Textures (GL_ARB_bindless_texture): Bindless texturing converts texture objects into 64-bit GPU memory handles that can be stored in Uniform Buffer Objects (UBOs) or Shader Storage Buffer Objects (SSBOs), circumventing traditional texture unit slot limits and optimizing descriptor indirection.
  • Batch Draws by Material: Group draw calls so that all geometry sharing identical texture sets is drawn together, eliminating the need for runtime dynamic selection entirely.
