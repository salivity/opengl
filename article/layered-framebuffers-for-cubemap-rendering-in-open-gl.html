Layered Framebuffers for Cubemap Rendering in OpenGL

Layered framebuffers in OpenGL enable developers to render to all six faces of a cubemap simultaneously in a single draw call, eliminating the CPU overhead of binding individual faces sequentially. This article explains the architecture of layered rendering, how to attach an entire cubemap texture to a framebuffer object (FBO), and how to leverage the OpenGL shading pipeline using the built-in gl_Layer variable to route geometry to individual cube faces dynamically.

Traditional vs. Layered Cubemap Rendering

In a conventional rendering loop, rendering a dynamic cubemap (such as for point light shadow mapping or real-time environment reflections) requires six distinct passes. For each face, the CPU must invoke glFramebufferTexture2D to bind the specific cubemap target face (e.g., GL_TEXTURE_CUBE_MAP_POSITIVE_X), re-bind uniforms, and issue a draw call. This introduces significant state-change overhead on the CPU.

Layered rendering removes these repeated state changes. By attaching the entire cubemap as a layered texture attachment, the GPU issues one draw call per mesh, duplicating and directing geometry to the appropriate cubemap layers entirely in hardware.

Configuring the Layered Framebuffer

To support layered rendering, the cubemap must be attached to the FBO as a whole using glFramebufferTexture rather than the standard face-specific glFramebufferTexture2D.

  1. Allocate the Cubemap Texture: Create a standard GL_TEXTURE_CUBE_MAP and allocate storage across all six faces:

    GLuint cubemap;
glGenTextures(1, &cubemap);
glBindTexture(GL_TEXTURE_CUBE_MAP, cubemap);
for (GLuint i = 0; i < 6; ++i) {
    glTexImage2D(GL_TEXTURE_CUBE_MAP_POSITIVE_X + i, 0, GL_DEPTH_COMPONENT, 
                SHADOW_WIDTH, SHADOW_HEIGHT, 0, GL_DEPTH_COMPONENT, GL_FLOAT, NULL);
}
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_MIN_FILTER, GL_NEAREST);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_MAG_FILTER, GL_NEAREST);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_R, GL_CLAMP_TO_EDGE);

  2. Attach the Cubemap to the FBO: Use glFramebufferTexture to bind the entire texture array/cubemap directly to the attachment point:

    GLuint fbo;
glGenFramebuffers(1, &fbo);
glBindFramebuffer(GL_FRAMEBUFFER, fbo);
glFramebufferTexture(GL_FRAMEBUFFER, GL_DEPTH_ATTACHMENT, cubemap, 0);

// Disable color buffer reads/writes if rendering only depth
glDrawBuffer(GL_NONE);
glReadBuffer(GL_NONE);

if (glCheckFramebufferStatus(GL_FRAMEBUFFER) != GL_FRAMEBUFFER_COMPLETE) {
    // Handle incomplete framebuffer error
}
glBindFramebuffer(GL_FRAMEBUFFER, 0);

Directing Primitives with the Geometry Shader

Once the framebuffer attachment is layered, the pipeline requires a mechanism to specify which layer receives each primitive. The primary method is utilizing a Geometry Shader (GS) and the built-in variable gl_Layer.

The cubemap faces correspond directly to layer indices \(0\) through \(5\):

  • Layer 0: +X
  • Layer 1: -X
  • Layer 2: +Y
  • Layer 3: -Y
  • Layer 4: +Z
  • Layer 5: -Z

Shader Implementation

  1. Vertex Shader: The vertex shader operates in world space, passing untransformed or world-space vertices directly to the geometry shader without projecting them:

    #version 330 core
layout (location = 0) in vec3 aPos;

uniform mat4 model;

void main() {
    gl_Position = model * vec4(aPos, 1.0);
}

  2. Geometry Shader: The geometry shader accepts incoming triangles and duplicates them six times. In each iteration, it sets gl_Layer to the target face index and applies that face's view-projection matrix:

    #version 330 core
layout (triangles) in;
layout (triangle_strip, max_vertices = 18) out;

uniform mat4 shadowMatrices[6];

out vec4 FragPos;

void main() {
    for (int face = 0; face < 6; ++face) {
        gl_Layer = face; // Directs primitive to this cubemap face
        for (int i = 0; i < 3; ++i) {
            FragPos = gl_in[i].gl_Position;
            gl_Position = shadowMatrices[face] * FragPos;
            EmitVertex();
        }
        EndPrimitive();
    }
}

  3. Fragment Shader: The fragment shader processes fragments written to the respective layer. The hardware implicitly manages layer routing; no special layer handling is required in the fragment stage unless dynamic branching based on face orientation is desired.

Executing the Render Pass

To render the cubemap:

  1. Bind the layered FBO: glBindFramebuffer(GL_FRAMEBUFFER, fbo).
  2. Set the viewport to match the dimensions of a single cubemap face: glViewport(0, 0, SHADOW_WIDTH, SHADOW_HEIGHT).
  3. Clear the attachments (glClear(GL_DEPTH_BUFFER_BIT)). This clears all six faces at once.
  4. Pass the six camera matrices (90-degree field-of-view projections combined with look-at orientations toward each axis) to the geometry shader's uniform array.
  5. Issue the draw call once per model (glDrawElements or glDrawArrays).

Modern Alternative: Direct Vertex Shader Layer Assignment

While geometry shaders are standard across OpenGL 3.3+, they can introduce a performance bottleneck due to primitive amplification. In OpenGL 4.5 (or via the GL_AMD_vertex_shader_layer and GL_ARB_shader_viewport_layer_array extensions), gl_Layer can be written directly within the Vertex Shader.

When combined with instanced rendering (glDrawElementsInstanced using an instance count of 6), the vertex shader sets gl_Layer = gl_InstanceID, avoiding the geometry shader entirely and achieving maximum GPU throughput.
