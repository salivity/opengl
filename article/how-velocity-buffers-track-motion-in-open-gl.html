How Velocity Buffers Track Motion in OpenGL

A velocity buffer, or motion vector buffer, stores the per-pixel screen-space displacement of geometry between the previous frame and the current frame. In OpenGL, this is achieved by supplying both current and historical transformation matrices to the shader pipeline, calculating the clip-space positions of vertices across both frames, and computing their difference after perspective division. This data is written into an off-screen render target—typically a floating-point texture—to drive temporal post-processing techniques such as Temporal Anti-Aliasing (TAA), motion blur, and temporal upscaling.

Storing Historical Transformation Data

To compute displacement, the application must retain transformation data from the previous frame alongside the current frame's data:

  • View-Projection Matrices: The CPU-side application maintains the previous frame’s view-projection matrix (\(VP_{prev}\)) and uploads it alongside the current view-projection matrix (\(VP_{curr}\)), commonly via a Uniform Buffer Object (UBO).
  • Model Matrices: For dynamic objects, the application must track the object’s model transform from the prior frame (\(M_{prev}\)) as well as its current transform (\(M_{curr}\)). For skinned meshes, this requires maintaining the previous frame’s bone transform matrices.

Vertex Shader Transformation

The vertex shader is responsible for projecting the mesh vertex into clip space for both points in time.

#version 450 core

layout(location = 0) in vec3 aPos;

layout(std140, binding = 0) uniform FrameData {
    mat4 uCurrViewProj;
    mat4 uPrevViewProj;
};

uniform mat4 uCurrModel;
uniform mat4 uPrevModel;

out vec4 vCurrClipPos;
out vec4 vPrevClipPos;

void main() {
    vCurrClipPos = uCurrViewProj * uCurrModel * vec4(aPos, 1.0);
    vPrevClipPos = uPrevViewProj * uPrevModel * vec4(aPos, 1.0);
    
    gl_Position = vCurrClipPos;
}

The shader produces two clip-space coordinates. gl_Position uses the current transform so rasterization occurs in the object's correct current screen location.

Fragment Shader Velocity Calculation

Once interpolated by the rasterizer, the fragment shader performs the perspective divide on both coordinates to bring them into Normalized Device Coordinates (NDC), where values range from \([-1, 1]\).

#version 450 core

in vec4 vCurrClipPos;
in vec4 vPrevClipPos;

layout(location = 0) out vec2 outVelocity;

void main() {
    vec2 currNDC = vCurrClipPos.xy / vCurrClipPos.w;
    vec2 prevNDC = vPrevClipPos.xy / vPrevClipPos.w;

    // Calculate screen-space delta
    vec2 velocity = currNDC - prevNDC;

    // Optional: Convert NDC delta [-2, 2] to UV space delta [-1, 1]
    velocity *= 0.5;

    outVelocity = velocity;
}

Because camera jitter is often added to the projection matrix during Temporal Anti-Aliasing, the current and previous jitter offsets must be subtracted from the respective NDC coordinates before computing the delta to ensure only real motion is recorded.

Framebuffer Setup in OpenGL

Velocity buffers require negative and positive precision without clamping:

  1. Texture Format: Use a two-channel, 16-bit floating-point texture (GL_RG16F) or 32-bit floating-point texture (GL_RG32F).
  2. MRT Integration: In deferred rendering pipelines, velocity is often written to an additional color attachment (GL_COLOR_ATTACHMENT1 or higher) within the primary G-Buffer pass using glDrawBuffers.
  3. Double Buffering Matrix State: At the end of the CPU frame render loop, current matrices are copied into the storage variables designated for the previous frame's uniforms before being updated for the next frame.
